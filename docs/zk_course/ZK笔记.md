## 第 0 章 钟表世界

### 0.1 十三格的钟

想象一个表盘只有 **0 到 12** 共 13 格。指针在 11 再走 2 格不叫 13，叫 3——绕回去了。所有加法都在钟面上进行：

```
11 + 2 = 13 → 绕回 → 3           记作  11 + 2 ≡ 3 (mod 13)
9 + 7 = 16 → 16 − 13 → 5
4 × 5 = 20 → 20 − 13 → 7
```

"≡ 5 (mod 13)"读作"除以 13 余 5"。减法往回绕：3 − 5 = −2，倒退 2 格等于前进 11 格，所以 3 − 5 ≡ 11。乘法也是绕圈：4 × 5 = 20 → 20 − 13 = 7。

### 0.2 除法：每个非零数都有"倒数"

在钟表世界里"除以 7"= 找一个数乘 7 后绕回 1。挨个试：7×2 = 14 ≡ 1，所以 7 的倒数是 2。**每个非零数都有倒数**——这样的世界叫**域**。

但这不是随便哪个钟都有的性质。看 6 格的钟里 2 的倒数：2×0=0, 2×1=2, 2×2=4, 2×3=6≡0, 2×4≡2, 2×5≡4——乘积只有 {0,2,4}，永远撞不到 1。病灶：2×3 = 6 ≡ 0，两个非零数乘出零（**零因子**）。

**为什么 13 格没有、6 格有？** 13 是素数。证明三行：取非零 a，看 a×0, …, a×12 这 13 个乘积；若有两个相同 a·i ≡ a·j，则 13 整除 a·(i−j)；13 素且不整除 a，只能整除 (i−j)，而 i、j 都在 0..12 内，只能 i = j——矛盾。**13 个乘积两两不同、塞满全钟，1 必在其中。** mod 6 复验失败点：2×0 ≡ 2×3 需要 6 | 2·3 = 6 ✓ 成立——合数允许"分期付款"整除，素数挡住的正是这个。

### 0.3 负数

钟上没有负号。"−3"= 倒退 3 格 = 前进 10 格：−3 ≡ 10。一般规则 **−x ≡ p − x**。一致性验算：整数 (−3)+10 = 7；钟表 10+10 = 20 ≡ 7 ✓。

### 0.4 真实系统的大钟

教程用 13 格学规则，真实系统用 254 位大钟。域阶取自仓库依赖库源码（`arkworks-algebra/curves/bn254/src/fields/fr.rs:4`）：

```
r = 21888242871839275222246405745257275088548364400416034343698204186575808495617
```

- 254 位：2²⁵³ ≈ 1.447×10⁷⁶ < r ≈ 2.189×10⁷⁶ < 2²⁵⁴ ≈ 2.895×10⁷⁶；
- 规则与 13 格钟完全相同，只是口诀表必须用计算机；
- **易混警告**：网上最常见的十六进制 `0x30644E72…F0000001` 是另一个域（曲线坐标用的 Fq，末尾 …08583），不是这个 r（末尾 …95617）。证明算术全部在 r 上。

为什么非要绕圈不直接用整数：①数字不膨胀（乘法封顶 254 位）；②除法人人有份（0.2 节）；③它是一个均匀的骰子（第 5 章随机挑战要用）。

### 0.5 整数搬进钟表：域化

程序数据是普通整数（含负数）。搬进钟：正数原样进，负数加一圈：−3 ≡ 10 (mod 13)。搬完之后钟表里的每次运算与整数世界一致——**前提是整数运算本身不溢出**。验算：整数 (−3)×7 = −21；钟表 10×7 = 70 ≡ 5；整数 −21 ≡ −21+26 = 5 ✓。

真实域里 i64 的 −3 映射为 r − 3。代码：`to_field`（`zkml/src/quantization/`）。

### 一句话总结

> 证明系统所有算术发生在一个素数格的绕圈钟上（本仓库：254 位的 r）；除法人人有份；整数搬进的规则是"负数加一圈"。

## 第 1 章 一维：两个数的表

### 1.1 表与函数

表 **[7, 4]**。把它看成一个只吃 0 和 1 的函数：f(0) = 7，f(1) = 4。

### 1.2 插值：两点定一条线

要在"格子之间"取值，把两点连成直线。设 f(x) = a + b·x，代入两点：a = 7，a + b = 4 ⟹ b = −3：

```
f(x) = 7 − 3x
```

**两个数唯一确定这条线**——表 [7, 5] 给出的是另一条线（7 − 2x）。"唯一确定"是后面一切安全性的根。

### 1.3 在格子之间取值

求 f(1/2)。"1/2"是 2 的倒数：2 × 7 = 14 ≡ 1，所以 1/2 = **7**。代入：

```
f(7) = 7 − 21 = −14 ≡ 12 (mod 13)
```

直觉复核：12 在 7 和 4 的正中间吗？钟表"取一半"= 乘 1/2 = 乘 7：(7+4)×7 = 11×7 = 77 ≡ 12 ✓。几何上：从 7 前进 5 格是 12，再前进 5 格回到 4——正中。**直觉活着，只是"一半"变成了"乘 7"。**

### 一句话总结

> 两个数唯一确定一条直线；直线在任意位置的值都能算；"格子的值"只是这条线在 0 和 1 两处的取样。

## 第 2 章 二维：四个格子

### 2.1 表与格子坐标

表升级到 4 个数 **[3, 1, 2, 0]**，排成 2×2 方格（行变量 x、列变量 y 各取 0/1）：

| | y=0 | y=1 |
|---|---|---|
| **x=0** | 3 | 2 |
| **x=1** | 1 | 0 |

**索引约定（全课程统一）**：格子 (x, y) 的表下标 **I = x + 2y**——x 是低位。四个格子：

| (x, y) | I = x+2y | 表值 |
|---|---|---|
| (0,0) | 0 | 3 |
| (1,0) | 1 | 1 |
| (0,1) | 2 | 2 |
| (1,1) | 3 | 0 |

> 方向约定没有对错，但必须声明。有的材料用 I = 2x + y（x 在高位）——只是表的排列顺序不同，协议数学不变。读任何代码先确认约定。

### 2.2 选择器：拼出二维函数

定义两个单变量选择器：

```
ℓ₀(t) = 1 − t      （t=0 时它 =1，"选 0"）
ℓ₁(t) = t          （t=1 时它 =1，"选 1"）
```

四个格子的值用四个"角落选择器乘积"拼装：

```
f(x, y) = 3·ℓ₀(x)ℓ₀(y) + 1·ℓ₁(x)ℓ₀(y) + 2·ℓ₀(x)ℓ₁(y) + 0·ℓ₁(x)ℓ₁(y)
```

为什么它对：代入任意格子，比如 (1, 0)——ℓ₁(1) = 1、ℓ₀(0) = 1，其余选择器全为 0，于是 f(1,0) = 1 ✓。每个格子自动取到自己的值。展开整理：

```
f(x, y) = 3(1−x)(1−y) + x(1−y) + 2(1−x)y = 3 − 2x − y
```

四角验证：3 ✓ 1 ✓ 2 ✓ 0 ✓。（xy 项消掉是这张表的运气，一般表会留下。）

### 2.3 在格子之间取值

挑一个非格子点 (x, y) = (5, 4)：

```
f(5, 4) = 3 − 2×5 − 4 = −11 ≡ 2 (mod 13)
```

这个 2 由表唯一决定——**改表中任何一个数它都会变**。当场演示：把最后一个格子 0 改成 1，新函数比原函数多了 ℓ₁(x)ℓ₁(y) = x·y 这一项，f(5,4) 变成 2 + (5×4 ≡ 7) = 9 ≠ 2。**一个格子的改动，指纹立刻不同**——第 5 章会用随机性把"改表必露指纹"变成安全保证。

### 一句话总结

> 4 个数唯一确定一个"对每个变量都是一次"的二维函数；它既能在格子上取值（还原表），也能在任意点取值（产生指纹）。

## 第 3 章 三维与 n 维：统一写法（MLE 登场）

### 3.1 三维：八个格子

再加一个变量 z，表有 8 个数，格子是 (x, y, z)。索引约定：

```
I = x + 2y + 4z        （x 最低位）
```

八个顶点全表：

| (x,y,z) | I | |
|---|---|---|
| (0,0,0) | 0 | a₀ |
| (1,0,0) | 1 | a₁ |
| (0,1,0) | 2 | a₂ |
| (1,1,0) | 3 | a₃ |
| (0,0,1) | 4 | a₄ |
| (1,0,1) | 5 | a₅ |
| (0,1,1) | 6 | a₆ |
| (1,1,1) | 7 | a₇ |

### 3.2 n 维统一公式

n 个变量的表有 2ⁿ 项，格子是布尔向量 t = (t₀,…,t_{n−1})。插值公式：

> **f(t) = Σ_{α∈{0,1}ⁿ} a[α] · ∏_k ℓ_{α_k}(t_k)**
>
> - α = 一个格子的布尔坐标（α_k ∈ {0,1}），遍历全部 2ⁿ 个格子；
> - a[α] = 表在格子 α 上的值；
> - ℓ_{α_k}(t_k) = α_k 对应的选择器（α_k = 0 用 ℓ₀，= 1 用 ℓ₁）在探针第 k 维的取值；
> - ∏_k = n 个选择器取值连乘——**这一项是"格子 α 的权重"**。

对每个变量单独看 f 都是一次的多项式——**多线性**。这行公式回答了你可能问过的问题：**(x,y,z) 是每个 bit 的取值，所以它就是二进制索引——对，方向约定要注意**（本笔记 x 在最低位）；而公式里出现的 x·y·z 这类**乘积**，是"三个选择器连乘"，它不是索引，是"索引 α = (1,1,1) 那个格子的权重"。

### 3.3 两种身份要分清

同一个 t 在公式里扮演两种角色，**这是初学最容易混的地方，值得单独说**：

- **t 取 0/1 时**：t 就是一个格子索引。此时每个选择器取值是 0 或 1，8 项里 7 项死光，只剩 a[t] 一项——f(t) 就是"取出表里那个数"。**定位**。
- **t 取连续值时**（比如 (5, 4)，甚至 (0.3, 0.7)）：t 不再对应任何格子。每一项都非零，f(t) 是**全部格子值按权重混合**的结果。权重仍然来自选择器取值，且权重之和恒为 1（第 4 章验证）——所以这是一个"加权平均"。

一句话：**顶点上是指示器（定位），一般点是权重（混合）。同一个公式，两种场合。**

### 3.4 代码：索引与 bit 互转

```python
def bits_to_index(bits):                 # bits = [t0, t1, ...]，t0 最低位
    return sum(b << k for k, b in enumerate(bits))

def index_to_bits(I, n):
    return [(I >> k) & 1 for k in range(n)]

bits_to_index([1, 0, 1])   # 1 + 0 + 4 = 5
index_to_bits(5, 3)        # [1, 0, 1]
```

### 3.5 放大到 100 万个数

规则一字不变：1,000,000 个数补零到 2²⁰，f 有 20 个变量。**命名落点**：这个 f 叫**多线性扩展**（Multilinear Extension，MLE）——"多线性"= 每变量一次；"扩展"= 从 2ⁿ 个格子扩展到整个域。名字出现在你会造它之后。

**代码对应**：`into_mle()` 把张量按行主序拍平成表——下标 I 的第 k 位 ↔ 第 k 个变量（最后一个维度占最低位，因为行主序让最后一个维度最连续）。

### 一句话总结

> 任意长的表 = 一个 n 变量多线性函数；统一公式 f(t) = Σ a[α]·∏ℓ；顶点上它就是查表，一般点上它是插值——这就是"表"获得"指纹"的方式。

**常见疑问**
- **问：约定反了（变量在高位）会怎样？** 协议自洽（双方同一约定即可），但与其他材料对拍时表顺序镜像——对不上先查约定。
- **问：为什么补 2 的幂？** 每维恰好 2 个取值，索引才能一一对应；补零不影响非零部分的语义。

## 第 4 章 eq：给每个格子配权重

### 4.1 两种算法算同一个值

第 2 章求 f(5,4) 用的是"展开后代入"：f = 3−2x−y → f(5,4) = −11 ≡ 2。另一种算法**不展开**，直接把探针代进选择器：

```
ℓ₀(5) = 1−5 = −4 ≡ 9      ℓ₁(5) = 5
ℓ₀(4) = 1−4 = −3 ≡ 10     ℓ₁(4) = 4

f(5,4) = 3×(9×10) + 1×(5×10) + 2×(9×4) + 0×(5×4)
       ≡ 3×12 + 1×11 + 2×10 + 0×7 = 36+11+20 = 67 ≡ 2 ✓
```

与展开法完全一致——必然一致，同一函数同一值。看清结构：**"在探针点求值"变成了"每个格子值乘一个权重，全加起来"**。四个权重就是四个角落选择器在探针点的取值：w(0,0) = 12，w(1,0) = 11，w(0,1) = 10，w(1,1) = 7。

### 4.2 权重的正式名字：eq

把"每维取 1−探针 或 探针、按格子坐标连乘"的函数命名为 **eq**：

> **eq(r, c) = ∏_b ( r_b·c_b + (1−r_b)(1−c_b) )**        r = 探针点，c = 格子坐标

由 3.3 节，它就是"格子 c 的选择器在探针 r 处的取值"——**eq 和第 3 章的选择器是同一个东西**，不是新概念。

### 4.3 名字的来历：equality

当探针 r 恰好取 0/1 时，eq(r, c) 在 c = r 处为 1、其余格子为 0——像一个用多项式写出的"等号"。**但注意适用范围：这只在 r 是布尔点时成立。**

### 4.4 一个真实的误解（值得单独一节）

"eq(r, r) = 1"这句话**只对布尔探针成立**。对一般探针，比如 r = (5,4)，把 c = r 代进去：

```
eq((5,4),(5,4)) = (5² + (−4)²)² = (25+16)² = 41² ≡ 2² = 4 ≠ 1
```

它不等于 1，也不该等于 1——此时 eq 不是"等号"，而是 4.1 说的**权重**（混合比例）。**恒成立的另一条性质是**：

```
Σ_{c∈{0,1}²} eq(r, c) = 1        （对任何 r 都成立）
```

数值验证：12+11+10+7 = 40 ≡ 1 ✓。一行证明：按维分组 (ℓ₀(5)+ℓ₁(5))×(ℓ₀(4)+ℓ₁(4)) = (9+5)(10+4) = 14×14，而每组内和恰为 1（ℓ₀+ℓ₁ = 1 恒成立），所以总积 = 1×1 = 1。

### 4.5 全课程的枢纽：求值 = 加权和

把 4.1 的算式写成一般形式：

> **f(r) = Σ_{c∈{0,1}ⁿ} f(c) · eq(r, c)**
>
> 在任意点求值 = 对全表做一次加权求和；**权重是验证方自己能算的**（r 是 V 选的，eq 不依赖表）。

**这解决了什么实际问题**：V 想核查"f(5,4) = 2"但没有表——点值主张原本是死局（重算 = 读全表；听 P = 没核查）。改写后，主张里只剩两类东西：**V 自己能算的权重**，和 **P 手里的表值**。而"验证一堆数的加权和"有一个专用协议——下一章的 sumcheck：它不读表，用 n 轮对话把加权和核实到逃逸概率 ≤ 2⁻¹²⁷ 级（2²⁰ 的表：20 轮 × 每轮 3 个数，对比 100 万个数）。

**这就是本章存在的理由**：eq 把 V 无法核验的"点值"，换成 V 自己出权重、sumcheck 能核验的"加权和"。后面所有章节——矩阵乘、查表、softmax——做的都是同一件事：先把主张改写成"某个求和"，再交给 sumcheck。

### 一句话总结

> eq(r,c) = 格子 c 的选择器在探针 r 处的取值；恒等式 f(r) = Σ f(c)·eq(r,c) 把"无法核查的点值"变成"可被 sumcheck 核验的加权和"——这是表与协议之间的桥。

**常见疑问**
- **问：eq(r,r) = 1 不是书上/论文里的性质吗？** 是，但前提是 r 布尔。非布尔探针时 eq 是权重不是等号——见 4.4 反例（mod 13 里等于 4）。
- **问：为什么叫"探针"？** r 由验证方随机撒下（第 5 章），像往表上随机扎一针看读数。

## 第 5 章 sumcheck：把总和压成一个点

### 5.1 问题

证明方 P 声称表 [3,1,2,0] 的总和 = 6（3+1+2+0）。验证方 V 不想读全表（真实场景是 2²⁰ 个数）。朴素的"抽查"抓不住补偿式作弊：把 1 改成 4、把 2 改成 −1，总和不变。需要新机关。

### 5.2 协议：一次削掉一个变量

总和按变量拆开：Σ = Σ_x Σ_y f(x,y)。**P 的第一条消息**：把 y 先加掉，只留 x 的函数。用第 2 章的 f(x,y) = 3−2x−y：

```
g₁(X) = f(X,0) + f(X,1) = (3−2X) + (2−2X) = 5 − 4X
```

一条直线由 2 个点确定，P 只发 **[g₁(0), g₁(1)] = [5, 1]**。

**V 的检查**：两端之和 = 声称的总和：5 + 1 = 6 ✓。这条线可能是假的——V 抽查它：掷随机挑战 **r₁ = 7**，双方算 g₁(7) = 5−28 = −23 ≡ **3**（V 用两点插值：5 + 7×(1−5) = −23 ✓）。

**主张变身**："总和 = 6"变成"**Σ_y f(7, y) = 3**"——x 被随机数钉死，问题规模减半。

**P 的第二条消息**：把 x = 7 代入后的表折叠出来——f(7,y) = (1−7)f(0,y) + 7f(1,y) = 7f(0,y) + 7f(1,y)：

```
y=0: 7×3+7×1 = 28 ≡ 2      y=1: 7×2+7×0 = 14 ≡ 1      → 折叠表 [2, 1]
```

这张折叠表**恰好就是 f(7,·) 的两个值**（直算 f(7,0) = −11 ≡ 2 ✓）——折叠是精确的变量固定。P 发 **[2, 1]**；V 查 2+1 = 3 = g₁(7) ✓；掷 **r₂ = 4**；最终主张：

```
f(7, 4) = (1−4)×2 + 4×1 = −2 ≡ 11 (mod 13)      直算：3−14−4 = −15 ≡ 11 ✓
```

**协议结束**。4 个数的表 → 凭据 = 4 个数 + 2 个挑战。2²⁰ 的表 → 20 轮、约 60 个数——**压缩比 17000:1**。

### 5.3 健全性：作弊者的三条死路

作弊者声称总和 = 5（真值 6）：

- **第一轮撒谎**：发两端点和为 5 的线，如 [3, 2]（线 3−X）。真线 5−4X。两条不同直线至多交于 1 点：3−X = 5−4X ⟹ X = 5。**V 掷的 r₁ 只要不等于 5，作弊进入死亡螺旋**——此后每个数字被真表锁定，缺口传导到终点。逃逸概率 1/13；
- **后面某轮撒谎**：逐轮独立，同样分析；
- **只改终点值**：终点主张由承诺核销（第 6 章）。

真实世界：挑战空间 2¹²⁸（16 字节哈希输出，Fiat–Shamir——把对话逐字节喂进 Blake3，输出当挑战，V 不用在线），每轮逃逸 ≤ d/2¹²⁸（d = 轮多项式次数），20 轮合计 ≈ 2⁻¹²¹。**不是 100% 抓住，是漏网概率物理上无意义。**

### 5.4 多张表的乘积

真实计算里 sumcheck 面对的是表的乘积（矩阵乘断言 Σ_k A·B 就是它）。设 h = [1,0,0,1]，乘积表 g = f⊙h = [3,0,0,0]，总和 3。第一轮消息 g₁(X) = g(X,0)+g(X,1) = (3−3X)+0 = 3−3X。**两个一次式相乘 → 轮函数 2 次 → 每轮发 3 个点**（第 3 点插值补出）。一般地 d 张表的乘积 → 每轮 d+1 个点、每轮逃逸 ≤ d/2¹²⁸。

### 5.5 工程与代码

- 挑战 = `append_and_sample(b"Internal round")`（Blake3 16 字节输出 mod r，dp-crypto `transcript/mod.rs:29`）；
- 折叠 = `fix_var`（`dense.rs:454`）——与 §5.2 手算一字不差；
- 多表表达式 = 虚拟多项式（`sumcheck/virtual_polys.rs`）；
- 两阶段并行（表按线程切片，论文 arXiv:2210.00264）= `prover.rs:23-103`；
- 成本账单（n=20、二表乘积）：全程读 ≈ 8.39M 项 ≈ 268 MB、乘 ≈ 3.15M 次——**带宽型算子**。

### 一句话总结

> sumcheck 把"2ⁿ 个数的总和 = Y"压成 n 轮对话 + 一条最终主张 f(r) = y；凭据 ~60 个数；每轮逃逸 ≤ d/2¹²⁸。

## 第 6 章 承诺：给表发指纹

### 6.1 悬空的主张

第 5 章终点"f(7,4) = 11"悬空：V 没有表，P 可以现在编一张满足等式的表。解法：证明开始前给每张表生成一个**短指纹 C**，此后一切主张用 C 核销。要求：C 短；诚实者必过；**改表必被抓**（绑定性）。

### 6.2 仪式与力量表

找一位**仪式主持人**，藏一个秘密数 τ（仪式后销毁），公开"力量表"：τ 的各次幂。mod 13 里取 τ = 6，前 4 项：

```
w = [τ⁰, τ¹, τ², τ³] = [1, 6, 36≡10, 60≡8]
```

P 承诺：**C = 表逐项乘力量表再全加** = 3×1 + 1×6 + 2×10 + 0×8 = 29 ≡ **3**。关键性质：**P 只需要力量表，不需要 τ**。

### 6.3 亲手破解这个玩具

找"改表不改指纹"的组合：δ = (6, 12, 0, 0)（即 6 和 −1）满足 Σδᵢwᵢ = 6−6 = 0，于是假表 [9,0,2,0] 的指纹 C′ = 9+20 = 29 ≡ 3 = C。**不同表、同指纹——玩具被破。** δ 的真面目：δ(X) = 6−X = −(X−τ)——知道 τ 一秒造出。不知道 τ 的攻击者在纯数字世界也容易：任何 (w₁,−w₀) 都行。**暗门遍地。**

### 6.4 修复：椭圆曲线

把力量表换成**曲线上的点** Wᵢ = τⁱ·G：点可以相加、可以乘系数（P 需要的全部能力），但从 W 反推 τ 等价于**离散对数问题**。攻击变成"找 δ₀W₀+δ₁W₁ = 0"⟹ 需要知道 τ——焊死。这套构造叫 **KZG 承诺**；点加权求和在工程里就是一次 **MSM**（多标量乘，生产规模 2²⁰ 个标量，Pippenger 算法）。

### 6.5 打开：商多项式

V 持 C，P 声称 f 在点 7 取值为 y。数学事实：**u(7) = y ⟺ u(X)−y 含因子 (X−7)**。P 交出商多项式 q(X) = (u(X)−y)/(X−7) 的承诺，V 通过配对运算核验"整除性在承诺世界成立"。y 是假的 ⟹ 不整除 ⟹ 无合法 q——必败。

**手算**（表 [3,1,2,0] 读作一元多项式 u(X) = 3+X+2X² 的系数——同一张表的另一种读法）：

```
u(7) = 3+7+2×49 = 108 ≡ 4 (mod 13)
综合除法（[2,1,12]，根 7）：2 → 1+14≡2 → 12+14≡0 ✓
商 q(X) = 2X+2；乘回：(2X+2)(X−7) ≡ 2X²+X+12 = u(X)−4 ✓
```

**负例**：谎称 u(7) = 5 → u−5 = 2X²+X+11 → 除法余 25 ≡ 12 ≠ 0——无商可除，必败。

**绑定 ≠ 隐藏**：这个承诺只做绑定（表改不了），不做隐藏。DeepProve 证完整性不需要隐藏；隐私负载必须加盲化因子。

### 一句话总结

> KZG 承诺 = "把表投进一个只有加法的魔法世界"；打开 = "除以 (X−点) 的商多项式再承诺一次"；谎报点值 = 无商可除 = 必败。

**常见疑问**
- **问：仪式主持人作恶怎么办？** 多方共同生成 τ，只要一人销毁了自己的份额即安全。
- **问：两种"表的身份"（位=变量 / 位=次数）为什么能共存？** 因为第 7 章的折叠恰好同时服务两种身份——折叠到最后一格，两种读法给出同一个数。

## 第 7 章 收口：几十条主张到一次打开

### 7.1 问题

真实证明的结尾有几十条主张：线性层吐出"权重在某点等于某值"，查表层吐出"witness 切片在某点等于某值"……每条指向不同的表、不同的点。逐条打开 = 几十次配对级代价。本章收成一次，三步全部可手算。

演员：主张① f(7,4) = 11（表 f = [3,1,2,0]，第 5 章终点）；主张② g(5,4) = 10（表 g = [3,0,0,0]，验算 3(−4)(−3) = 36 ≡ 10 ✓）。

### 7.2 第一步：batched sumcheck——把不同点搬到同一个点

抽随机系数 γ₁ = 3、γ₂ = 5，构造新主张：

```
Σ_{x,y∈{0,1}} [γ₁·eq((7,4),x,y)·f(x,y) + γ₂·eq((5,4),x,y)·g(x,y)] = 3×11 + 5×10 = 83 ≡ 5
```

右边 V 自己能算。左边为什么成立：逐项用第 4 章恒等式（Σ f·eq((7,4),·) = f(7,4) = 11 ✓）。**两把主张被随机捆成一个 sumcheck**——而 sumcheck 你已经会跑了。

四张参与表（eq 表由第 4 章倍增法生成，**V 自己算——eq 不需要承诺**）：

```
eq((7,4),·) = [5, 5, 2, 2]      eq((5,4),·) = [12, 11, 10, 7]
```

**第 1 轮**（削变量 x）。轮函数 R(X) = Σ_y [γ₁·eq₁(X,y)f(X,y) + γ₂·eq₂(X,y)g(X,y)]。乘积项使它是二次的——发 3 个点。逐点算 X=0,1，外推 X=2：

```
R(0) = 3×(5×3 + 2×2) + 5×(12×3 + 10×0) = 3×19 + 5×36 = 57+180 ≡ 5+11 = 16 ≡ 3
R(1) = 3×(5×1 + 2×0) + 5×(11×0 + 7×0) = 15 ≡ 2
X²系数 = γ₂×[(11−12)(0−3) + (7−10)(0−0)] = 5×3 = 15 ≡ 2
R(X) = 3 + 10X + 2X²        消息 [3, 2, 5]
```

V 查：3+2 = 5 ✓。掷 **r₁ = 6**：R(6) = 3+60+72 = 135 ≡ **5**（三点插值复核 3×10+2×2+5×2 = 44 ≡ 5 ✓）。

**四张表各自折叠**（权重 (1−6, 6) ≡ (8, 6)）：

```
f′ = [8×3+6×1, 8×2+6×0] = [30,16] ≡ [4, 3]     eq₁′ = [70,28] ≡ [5, 2]
g′ = [8×3+6×0, 0]       ≡ [11, 0]               eq₂′ = [162,122] ≡ [6, 5]
```

**第 2 轮**（削变量 y）：R₂(0) = 3×5×4 + 5×6×11 = 60+330 = 390 ≡ **0**；R₂(1) = 3×2×3 + 0 = 18 ≡ **5**；Y² 系数 = 3×(2−5)(3−4) + 5×(5−6)(0−11) = 9+3 = 12。消息 **[0, 5, 8]**（R₂(Y) = 6Y+12Y²）。V 查：0+5 = 5 ✓。掷 **r₂ = 2**。

**闭合**。V 自己算 eq 在最终点 (6,2) 的值（他知道两个主张点）：

```
eq((7,4),(6,2)) = eq(7,6)×eq(4,2) = [7×6+(−6)(−5)]×[8+(−3)(−1)] = 72×11 ≡ 7×11 = 77 ≡ 12
eq((5,4),(6,2)) = [50≡11]×11 = 121 ≡ 4
闭合恒等式：3×12×f(6,2) + 5×4×g(6,2) = 8        （sumcheck 终值）
```

**两张表在同一个新点 (6,2) 的取值成了两条新主张**：f(6,2) = 2（3−12−2 = −11 ≡ 2 ✓）、g(6,2) = 2（3(−5)(−1) = 15 ≡ 2 ✓）。代回 72+40 = 112 ≡ 8 ✓。

**一个必须写对的细节**：sumcheck 过程中**不要**把 eq⊙f 预先合成一张表去折叠——合成表折叠得到的是"乘积表的 MLE 在终点的值"（= 5），与"多项式乘积在终点的值"（= 8）在格子之外**不相等**。正确做法：各表独立折叠、轮函数每轮由各表现算合成。

### 7.3 第二步：RLC——两张表塌成一张

两条主张已同点不同表。再抽一对系数（3 和 5）：

```
h = 3×f + 5×g = [24, 3, 6, 0] ≡ [11, 3, 6, 0]        h(6,2) = 3×2 + 5×2 = 16 ≡ 3
```

验算（角展开）：11×96 + 3×72 + 6×16 = 1368 ≡ 3 ✓。随机性保证：伪造 h′ 同时骗过两条主张的概率 2⁻¹²⁷ 级。

### 7.4 第三步：HyperKZG——折叠 + 三点

对"h 在 (6,2) = 3"做打开是**多维点**，KZG 的商多项式只会开**一元点**。桥是**折叠**——而且就是第 5 章那个折叠（把表读作一元系数后，逐变量折叠系数表）：

```
折 x=7：p₁ = [7(1−3)+3, 7(0−2)+2] = [−11,−12] ≡ [2, 1]        ——恰为 f(7,·)
折 y=4：p₂ = 4×(p₁[1]−p₁[0]) + p₁[0] = −2 ≡ 11                ——恰为 f(7,4) = 11
```

**两个惊喜**：①折叠表 p₁ = [2,1] 就是第 5 章的折叠表——承诺世界的折叠与 sumcheck 世界的"固定变量"是**同一个操作**；②折叠终点 p₂ = 11 **正好是第 5 章的最终主张**。sumcheck 的终点、折叠链的终点、承诺打开的点，三点合一。

**三点技巧**：逐个打开折叠表要多次配对核验。HyperKZG 的办法：V 掷随机 r，只要求 P 提供每张折叠表在 **r、−r、r²** 三个点的取值，用一条恒等式串联：

```
2r·p₁(r²) = r(1−x)(p₀(r)+p₀(−r)) + x(p₀(r)−p₀(−r))
```

**手算**（r = 5, x = 7，u = 3+X+2X²）：u(5) = 58 ≡ 6；u(−5) = u(8) = 3+8+128 = 139 ≡ 9；p₁(25≡12) = 14 ≡ 1。

```
左 = 2×5×1 = 10        右 = 5×(−6)×(6+9) + 7×(6−9) = −450−21 = −471 ≡ −471+481 = 10 ✓
```

**为什么成立**：把 u 拆成偶部 A(X²) + 奇部 X·B(X²)，u(±r) 给出 A(r²)、B(r²)，而 p₁(X) = (1−x)A(X) + x·B(X)——代进去整理即得。**威力**：V 从已承诺表在 ±r 的取值**外推**出未单独承诺的折叠表在 r² 的取值 → 全部折叠表只需一次批量打开（3 点、1 次 MSM + 1 次配对）。19 张折叠表逐个打开 vs 1 次。

### 一句话总结

> 几十条主张 → batched sumcheck（不同点 → 同一点，每表一个取值）→ RLC（多表 → 一条）→ HyperKZG（折叠 + 三点 + 一次批量打开）。**几十次核验变 1 次**——真实系统"只打开一次"的全部数学。

**常见疑问**
- **问：eq 表为什么不承诺？** eq(r,·) 是 V 自己的多项式（r 是 V 选的），V 能本地算——"验证方能算的东西不承诺"。
- **问：合成表折叠为什么错？** 见 7.2 末尾的警告：乘积表的 MLE 与多项式乘积只在布尔格子上相等，折叠发生在格子之外。

## 第 8 章 查表：非线性函数的证明

### 8.1 问题

GELU、softmax、量化右移画出来是曲线。第 3 章的事实：多项式若在足够多点与曲线重合就必须是曲线——**曲线不是多项式**，sumcheck 熄火。出路：**离线把函数值打成一张表 T**，运行时"计算 = 查表"，证明任务变成：

> 证明每次查询的值 qᵢ 都在表里，且报告的输出 oᵢ 确实是 T 给的。

表的规模只由**输入位宽**决定（16 位 → 6.5 万格），与数据量无关。

### 8.2 分数与多重度

选随机数 β，把每次查询表示成分数 **1/(β+qᵢ)**，把表的每个位置 j 表示成 **mⱼ/(β+T[j])**（mⱼ = 多重度）。恒等式：

```
查询侧 Σᵢ 1/(β+qᵢ)  =  表侧 Σⱼ mⱼ/(β+T[j])     ⟺     查询全部合法
```

按值归组：查询侧 = Σ_值 cᵥ/(β+v)（cᵥ = 被查次数）；表侧 = Σ_值 tᵥ·mᵥ′/(β+v)（tᵥ = 占位次数）。相等 ⟺ 对每个值 v：**tᵥ·mᵥ′ = cᵥ**——多重度恰好记录了每个值被查的次数。所以多重度按位置记：**mⱼ = 被查次数(T[j]) ÷ 表内出现次数(T[j])**。β 随机的作用：让"表外的值"对应一个**对不上账**的分数（而不是直接溢出）。

### 8.3 亲手跑一遍（mod 13）

表 **T = [1, 2, 3, 4]**，查询 **q = [2, 1, 1]**，β = 4（检查 β+v = 5,6,7,8 全非零 ✓）。需要的逆元：1/5 = 8、1/6 = 11、1/7 = 2、1/8 = 5。

```
多重度：c(1)=2, c(2)=1, c(3)=0, c(4)=0 → 每值占 1 格 → m = [2, 1, 0, 0]
        （Σm = 3 = 查询条数 ✓）
查询侧 = 1/(4+2) + 1/(4+1) + 1/(4+1) = 11 + 8 + 8 = 27 ≡ 1 (mod 13)
表侧   = 2/(4+1) + 1/(4+2) + 0 + 0   = 16 + 11     = 27 ≡ 1 ✓   两侧相等 → 查询合法
```

**作弊测试**：查询里混入表外值 5（q = [2,1,5]）：查询侧多出 1/(4+5) = 1/9 = 3，总和 4 ≠ 1 → 抓住 ✓。

### 8.4 分数折叠：全程不做除法

逐个求逆元太贵（6.5 万格的表）。LogUp 的妙笔：**每个分数只记 (分子, 分母) 一对**，分数相加用交叉相乘：

```
n₁/d₁ + n₂/d₂ = (n₁d₂ + n₂d₁) / (d₁d₂)          （3 乘 1 加，无逆元）
```

把所有分数**两两折叠**成一棵树，每侧最后剩一个 (分子, 分母)。V 核对两侧的方式也是交叉相乘：

```
查询侧分数：(1,6), (1,5), (1,5)
  (1,6)+(1,5) = (1×5+1×6, 6×5) = (11, 30≡4)
  (11,4)+(1,5) = (11×5+1×4, 4×5) = (59≡7, 20≡7)        → 查询侧终值 (7, 7)

表侧分数：(2,5), (1,6), (0,7), (0,8)
  (2,5)+(1,6) = (2×6+1×5, 30) = (17, 4)
  (17,4)+(0,7) = (17×7, 28) = (119≡2, 28≡2)
  (2,2)+(0,8) = (16, 16)                                → 表侧终值 (3, 3)

交叉核对：查询侧.分子 × 表侧.分母 = 7×3 = 21 ≡ 8
          表侧.分子 × 查询侧.分母 = 3×7 = 21 ≡ 8     ✓ 相等 → 查表合法
```

**无一次除法、无一次求逆**。这棵"分数折叠树"逐层是一次数值计算——分层 + 每层一次 sumcheck + 挑战点逐层传递（第 5 章的形状）。层数 = log₂(表长)：4 格的表 2 层；6.5 万格 16 层——只随**位宽**涨，不随数据量涨。

### 8.5 还缺一块：把"表世界"焊回"张量世界"

第 8.2–8.4 节证明了"witness 里记录的查询/输出对与表一致"。但真正的目标是**节点的输出张量**。最后一块拼图叫 **linking sumcheck**：再用一次 sumcheck 证明"输出张量的 MLE = 查表输出按算子语义的组合"。各算子的组合方式：GELU/requant = 输出即查值（requant 的乘子与右移已折进表）；GLU = 查表半 × 直通半；softmax = 查值 − shift；RMSNorm = 输入 ⊙ 归一化因子。至此查表层闭环：**witness → 承诺（第 6 章）→ LogUp 双侧折叠（本讲）→ linking → 输入侧新主张回传上游 → 收口（第 7 章）**。

### 一句话总结

> 查表 = "多重度记账 + 分数恒等式"：查询侧 Σ 1/(β+qᵢ) 与表侧 Σ mⱼ/(β+T[j]) 相等 ⟺ 查询合法；分数折叠树（GKR 形状）让它免排序、免除法、可批量、可分层证明。

**常见疑问**
- **问：为什么表长只随位宽涨、不随数据量涨？** 表编码的是"函数"（每个可能的输入对应的输出）；涨的是查询条数——它体现在查询侧电路的叶子数与多重度之和。
- **问：log 是怎么进来的？** 非幻觉检测（论文 §4.4）用查表近似 log 函数、sumcheck 求和——同一套机器的又一次复用。

```
③ 播种：transcript 掷随机点，对最终输出与跨块边界张量立主张
   （LLM 只证最后一行 logits：206 MB 的表只证 0.4 MB——O(s²)→O(s)）
④ 逆拓扑逐算子归约：稠密层 einsum sumcheck（第 5 章乘积的放大版）；
   非线性层查表 + linking（第 8 章）；每个算子吃"输出主张"吐"输入主张"
⑤ 收口：全部主张 → batched sumcheck → RLC → 一次打开（第 7 章）
⑥ 验证：重放每轮检查 + 配对；多 chunk 用 seed 链与边界承诺相等焊死
```

**④ 的学理名：GKR 范式**（Goldwasser–Kalai–Rothblum, 2008）——"用一次 sumcheck 把『下一层输出在某随机点的取值』归约成『上一层输入在某随机点的取值』"，从输出层走到输入层。论文原话：*"Similar to the fabled GKR protocol, we compose these operator protocols in a layer-by-layer fashion."* 三处工程改造：层内协议按算子定制（比通用 GKR 快）；claim 单链（每个算子一对一归约）；权重前置承诺（setup 期一次）。

### 9.2 三个"妙手"（论文 §4 的核心技巧）

- **embedding 不承诺表**：验证方手里就有索引向量 x，把查表重写成稀疏矩阵乘 Y = H_T·X（每行恰一个 ±1）→ 证明方连 H_T 都不用承诺，V 本地 O(s·log n) 算。原则：**验证方能本地算的东西，证明方不承诺**（eq 表同此原则）；
- **RMSNorm 送答案**：证明方自己带倒数 d[i] = Quant(1/√(ΣX²/d))（把开方/逆元从电路里挪出来），证 Y = X·d，再加一条完备性检查 Σⱼ Y[i,j]² = 1 封堵假 d——"证明方送答案 + 代数恒等式验答案"；
- **requant 全查表**：乘子右移折进表（Case 1）、超范围时连"取倒数"都查表（Case 2）+ InRange/Comb 钳位表——**没有除法、没有开方、没有比较门**。它也是系统里最贵的算子（占总证明时间 27%）。

## 第 10 章 深入方向（每节都能独立展开）

### 10.1 哈希承诺与 FRI（摆脱 trusted setup）

第 6 章的仪式有个信任假设（至少一人诚实）。哈希路线完全免仪式：把"次数低"翻译成"靠近一个纠错码"，用 Merkle 树承诺 + 随机抽查验证。核心机制是**折叠**：随机 α 把次数减半，抽查保证折叠前后的"离码距离"不消失（proximity gap）。**一个值得亲手做的实验**：在 mod 13 里对表 [5,4,0,12]（f(X) = 3X+2 在四阶子群 {1,5,8,12} 上的取值）跑一轮折叠——诚实者得到常数表 [8,8]；而一张偏离 1/4 的作弊表 [5,4,0,0] 竟然能造出全程自洽的链——**这暴露了玩具域的健全性局限**（真 FRI 需要"域大小 ≫ 次数 × 安全参数"，定理叫 proximity gap）。BaseFold = FRI 折叠与第 7 章多线性折叠的合流（同一折叠的两种身份）；WHIR/Binius/Circle STARK 是这一代的延续。

### 10.2 数域的选择（为什么新一代系统都在"换钟"）

254-bit 域的一次乘法 = 十几次 64-bit 乘加；64-bit 的 Goldilocks 域 ≈ 原生整数乘（快一个量级）；31-bit 的 M31 可以 SIMD 并行。但小域**装不下**大值（mod 13 里 5×5 = 25 ≡ 12，整数语义丢失——域阶必须大于计算值域上界），解法是**扩展域**：在 F₁₃ 上取 α² = 2（X²−2 不可约，因为 2⁶ ≡ −1 是非平方），造出 169 格的大钟 F₁₆₉ = {a+bα}；Binius 的"二进制塔" F₂⊂F₄⊂F₁₆⊂… 是同一构造。DeepProve 留在 BN254 的原因：HyperKZG 绑配对曲线；而 sumcheck/查表协议**与域无关**——换域只换底盘，PIOP 原封不动。

### 10.3 折叠与递归（证明"跑了 N 步"）

把 N 步计算逐块证明、验证方读 N 个证明——违背简明性。Nova 的洞察：**不证旧证明，把旧实例折叠进新实例**。relaxed R1CS 关系 Az∘Bz = u·Cz + E（E 是"误差记账"），折叠 z* = z₁ + r·z₂、E* = E₁ + r·T（T 是交叉项）——mod 13 里一步手算即可验证对任意 r 精确成立。N 步之后：一个累积器 + 一个证明，验证方工作恒定。DeepProve 的 chunk 切分是**并行**方案，折叠是**串行累积**方案——单次推理用前者，持续服务用后者。

### 10.4 安全：攻击者视角

把所有逃逸概率记成一页**预算表**（sumcheck 每轮 ≤ d/2¹²⁸ × 实例数 + PCS + FS 熵 → DeepProve ≈ 2⁻¹¹¹）。攻击者的三板斧对应三种绑定缺失：绑挑战（Fiat–Shamir transcript 缺陷，Frozen Heart 系列 2022）、绑陈述（证明重放，Binance "Alice" 2022）、绑承诺（碰撞，Zcash BCTV14）。**可亲手复现的攻击**：如果 transcript 忘了吸收承诺 C，作弊方在 S06 玩具里事后提交 g = [10,0,0,0]（它在 (7,4) 的值 = 5×10 = 50 ≡ 11 = 声称值），重放第 5 章的证明**全部通过**——修复 = 承诺先于挑战入 transcript。审计 = 逐一检查这三种绑定。

### 10.5 一句话总结

> 哈希承诺（免仪式）、小域（快算术）、折叠（摊销）、攻击者视角（预算表+三种绑定）——四条路都从本笔记的同一套基本概念出发。走到这里，你已经具备读任何一篇 2024-2026 年 ZK 论文的语言。

## 第 11 章 讲给别人听的六步话术

> 每步 2–4 句，道具就是那张 4 格表 [3,1,2,0]。讲完这六步，听的人就拥有了理解 DeepProve 的全部骨架。

**第一步：提出问题。**
"服务器说：这张 4 个数的表加起来等于 6。你信吗？重算一遍当然能确认——但真实场景是 100 万个数，重算等于没外包。所以我们需要一种凭据：很短、核对很快、作弊必被抓。作弊漏网的概率会被压到 2⁻¹²⁷ 以下——不是零，但比宇宙年龄里连续中彩票还罕见。"

**第二步：表变成多项式。**
"先把表 [3,1,2,0] 看成一个函数的四个取样点。数学上可以证明：恰好存在一个'每个变量都是一次'的函数 f，穿过这四个点——这张表就变成了 f。关键性质：两张不同的表给出不同的 f；而且 f 在**任意位置**（不只是那四个格子）都能取值。"

**第三步：随机探针。**
"现在验证方随机扔一个点，比如 (5,4)，要求服务器报出 f(5,4)。服务器报 2。为什么这个数可信？因为两张不同的表，几乎在所有点上的取值都不同——作弊表哪怕只改一个格子，在随机点上露馅的概率也压倒性地大。这就是'随机探针审问整张表'。"

**第四步：总和变成探针。**
"但'总和 = 6'不是一个点值啊？这里有个恒等式：函数在任何点的取值 = 全表做一次加权求和，权重由验证方自己算（叫 eq）。于是'总和等于 6'这条主张，可以通过 sumcheck 协议逐变量折叠——服务器每轮只发一条直线（两三个数），验证方每轮查一次加法、掷一个随机数。20 轮之后，100 万个数的总和问题变成了一句话：'f 在这个随机点等于 11。'"

**第五步：指纹核销。**
"最后一句 'f(随机点) = 11' 怎么信？证明开始前，表已经被'承诺'了——投进一个只有加法的魔法世界，得到一枚短指纹。数学保证：如果承诺的表在随机点的取值不是 11，验证方的一次密码学检查必然失败。服务器改表、改答案、改任何环节，都会在这最后一关暴露。"

**第六步：装进真实系统。**
"DeepProve 就是这套机器加上三样工程：线性代数用矩阵乘版 sumcheck；神经网络里的 GELU、softmax 用查表论证；最后几十条主张用一次批量打开核销。它验证 GPT-2 的一次完整推理：证明约 40 分钟，验证 4 秒，比之前最快的方法快 20 到 60 倍——而且证的是全部输出，不只是最后一个 token。"
