# S09 · 查表：非线性函数的证明

> 到目前为止你能证明"线性代数"：矩阵乘（sumcheck 的天职）、加法、加权。但神经网络的灵魂是非线性的——GELU、softmax、归一化、量化右移。它们**没有**低次多项式表达式，sumcheck 无从下口。这一讲造出处理它们的机器：**查表论证**。你将全程手算一个完整例子：一张 4 格的表、3 次查询、两侧分数折叠、最终交叉核对——最后才听到 LogUp 这个名字。
> 前置：S02（逆元）、S04（恒等式的用法）、S06（sumcheck 机制——本讲只借用"逐层折叠"的形状，不重跑）。

---

## 1. 非线性为什么难，以及"表"为什么是出路

GELU 之类的函数画出来是一条曲线。S03 告诉我们：一个多项式若在"足够多点"上与曲线重合，它就必须是曲线本身——而曲线不是多项式。**所以不存在能表达 GELU 的低次多项式**，S03–S08 的机器（全部以多项式为燃料）直接熄火。

出路：**离线把函数值打成一张表**。以量化世界的 GELU 为例：输入是整数格点，把每个可能的输入对应的输出预先算好存成表 T。运行时"计算 GELU"="查表"。证明任务随之变成：

> **证明：每次查询的值 qᵢ 确实在表 T 里，且报告的输出 oᵢ 确实是 T 给的那个值。**

表的规模只由**输入位宽**决定（16 位输入 → 约 6.5 万格），与数据量无关——这就是 zkML 系统能负担的原因。

## 2. 笨办法与它的致命伤

让 P 直接把所有 qᵢ 和 oᵢ 发给 V，V 逐个查表核对。正确，但通信量 = 查询条数 × 2——**违背"短"**（S01）。需要一个把"百万次查询"压缩成"一条短主张"的办法。

## 3. 关键构造：把每次查询变成一个分数

选一个随机数 β（作用马上讲），把**每一次查询**表示成分数：

```
查询 qᵢ  →  分数 1 / (β + qᵢ)
```

把**表的每个位置** j 也表示成分数：

```
表位置 j（值 T[j]）  →  分数 m_j / (β + T[j])        m_j 叫"多重度"
```

**恒等式**（本讲的心脏）：

```
查询侧总和 = 表侧总和
Σᵢ 1/(β+qᵢ)  =  Σⱼ mⱼ/(β+T[j])
```

**为什么它等价于"查询全部合法"**：把两侧都按"值"归组。查询侧 = Σ_值v cᵥ/(β+v)（cᵥ = 值 v 被查的次数）；表侧 = Σ_值v tᵥ·mᵥ'/(β+v)（tᵥ = v 在表中占的位置数，mᵥ' = 每个位置的多重度）。两侧相等 ⟺ 对每个值 v：**tᵥ·mᵥ' = cᵥ**——即"多重度恰好记录了每个值被查的次数"。若有一次查询查了表外的值（或次数被篡改），某个值的 cᵥ 对不上，两侧总和必然不同（除非 β 恰好撞进一个坏集合——β 是 V 掷的 128-bit 随机数，撞上 = 概率可忽略；这就是 β 的作用：把"值不同"放大成"分数和不同"）。

**多重度怎么算**：mⱼ = c_{T[j]} ÷ t_{T[j]}（被查次数 ÷ 表内出现次数——除法在钟表世界里是乘逆元，S02 的老手艺）。

## 4. 亲手跑一遍（mod 13，全程数字）

**设定**：表 T = [1, 2, 3, 4]（4 个位置，每个值出现一次 → tᵥ = 1）；查询序列 q = [2, 1, 1]（值 2 查一次、值 1 查两次）。β = 4（检查 β+v = 5,6,7,8 都不为 0 ✓）。

**多重度**：c(1) = 2, c(2) = 1, c(3) = 0, c(4) = 0 → m = [2, 1, 0, 0]。自检：Σm = 3 = 查询条数 ✓。

**两侧直接对账**（用 S02 的逆元：1/5 = 8，1/6 = 11，1/7 = 2，1/8 = 5）：

```
查询侧 = 1/(4+2) + 1/(4+1) + 1/(4+1) = 11 + 8 + 8 = 27 ≡ 1 (mod 13)
表侧   = 2/(4+1) + 1/(4+2) + 0 + 0   = 2×8 + 11     = 27 ≡ 1 ✓
```

两侧相等，查询合法 ✓。（作弊测试：若 P 谎称查询了值 9——表里没有——查询侧多出 1/(4+9) = 1/13？β+9 = 13 ≡ **0**，分母为零——这正是 β 要随机的另一个原因：它让"表外的值"极大概率对应一个合法但**对不上账**的分数，而不是直接溢出。换成 β=4、谎查值 5：查询侧多 1/9 = 3（9×3 = 27 ≡ 1），总和变 4 ≠ 1 → 抓住 ✓。）

## 5. 不做除法的折叠：分数的 GKR 电路

第 4 节的对账用了**逐个求逆元**——6.5 万格的表就要 6.5 万次求逆，太贵。LogUp 的工程妙笔：**全程不做除法**。每个分数只记 (分子, 分母) 一对，分数相加用交叉相乘：

```
n₁/d₁ + n₂/d₂  =  (n₁d₂ + n₂d₁) / (d₁d₂)          （3 乘 1 加，无逆元）
```

把所有分数**两两折叠**成一棵树（形状与 S06 的表折叠一模一样），最后每侧剩一个 (分子, 分母)。V 核对两侧的方式也交叉相乘：

```
查询侧.分子 × 表侧.分母  =  表侧.分子 × 查询侧.分母
```

**亲手跑**（查询侧 3 个分数：(1,6), (1,5), (1,5)）：

```
折 (1,6)+(1,5) = (1×5+1×6, 6×5) = (11, 30≡4)
再折 (1,5)：    (11×5 + 1×4, 4×5) = (59≡7, 20≡7)
查询侧终值分数 = (7, 7)          → 值 = 7/7 = 1 ✓（与第 4 节一致）
```

**表侧**（分数：(2,5), (1,6), (0,7), (0,8)）：

```
(2,5)+(1,6) = (2×6+1×5, 30) = (17, 4)
(17,4)+(0,7) = (17×7, 28) = (119≡2, 28≡2)
(2,2)+(0,8) = (16, 16)
表侧终值分数 = (16≡3, 16≡3)      → 值 = 1 ✓
```

**交叉核对（V 的全部工作）**：

```
查询侧.分子 × 表侧.分母 = 7 × 3 = 21 ≡ 8
表侧.分子 × 查询侧.分母 = 3 × 7 = 21 ≡ 8    ✓ 相等 → 查表合法
```

无一次除法、无一次求逆。这棵"分数折叠树"逐层是一次数值计算——**又是 GKR 的分层形状**：每层一次 sumcheck（证明"下一层 = 本层折叠"），挑战点逐层传递，层数 = log₂(表长)（4 格的表 2 层；6.5 万格 16 层——只随位宽涨，不随数据量涨）。

## 6. 还缺一块：把"表世界"焊回"张量世界"

第 3–5 节证明了"witness 里记录的查询/输出对与表一致"。但真正的目标是**节点的输出张量**。最后一块拼图叫 **linking sumcheck**：再用一次 sumcheck 证明"输出张量的 MLE = 查表输出按算子语义的组合"。各算子的组合方式：

| 算子 | linking 的内容 |
| --- | --- |
| GELU / requant | 输出 = 主表查出的值（requant 的乘子与右移已折进表里） |
| GLU | 输出 = 查表半 × 直通半（两半拼接） |
| softmax | 输出 = 查值 − shift（shift 也是推理期记录的 witness） |
| RMSNorm / LN | 输出 = 输入 ⊙ 归一化因子（因子本身是 witness，逐元素乘进 sumcheck） |

至此查表层的完整证明链闭环：**witness 切片 + 多重度 → 承诺（S07）→ LogUp 双侧折叠（本讲 §5）→ linking（本讲 §6）→ 输入侧新主张回传上游（S06 的 claim 链）→ 收口（S08）**。

**名字落点**：这套"分数 + 折叠"的构造叫 **LogUp**；配 GKR 分层电路的实现叫 **LogUp-GKR**。DeepProve 论文 §4 的原话：*"lookup arguments based on LogUp for proving non-linear layers"*。
