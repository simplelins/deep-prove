# M03 · 数域的选择学：为什么新一代系统都在"换钟"

> S02 说"所有计算活在素数域上"，本仓库选了 254-bit 的 BN254 Fr。但 2023 年以来的新系统（Plonky3/Binius/Circle STARK/Jolt）几乎全在**小域**上跑。这一讲讲清这笔账：小域快多少、快在哪、**会坏在哪**（你会在 mod-13 玩具里亲眼看到"装不下"），以及两个修复方案——更大的钟与**扩展域**（你在 mod-13 里亲手造出 169 格的大钟，Binius 的塔就是这个构造的直系后代）。最后回答：DeepProve 为什么留在 BN254。
> 前置：S02（钟表）、S06（sumcheck 与域无关的原因）、M02（FRI 需要 2^m 阶子群）。

---

## 1. 域的大小直接写进乘法器的电路里

一次钟表乘法的硬件代价 ∝ 钟的位数：

| 域 | 位数 | 一次乘法的形态 | 量级感受（CPU，量级非精确 benchmark） |
| --- | --- | --- | --- |
| BN254 Fr | 254 bit（4×64 limb） | Montgomery CIOS：十几次 64×64 乘加 + 约减 | 基准（~40–60 ns 量级） |
| Goldilocks `2^64−2^32+1` | 64 bit（**单 limb**） | 一条 64×64→128 乘 + 特殊模数的一次减法约减 | 快约一个量级 |
| Mersenne31 `2^31−1` | 31 bit | 32-bit lane；AVX2/AVX-512 **一条指令并行 8~16 个乘法** | 再快数倍，GPU/SIMD 的甜点 |
| 二进制塔（Binius） | 1 bit 起步 | 加法 = XOR（免费），乘法 = 位逻辑 | 哈希类计算的天堂 |

这就是换域的动机：**同样的 sumcheck/查表机器，换到小域上整机快数倍**——新一代系统集体换钟的原因，一句话讲完。

## 2. 小域的第一个坑：装不下（mod-13 玩具实验）

在 mod 13 里算 **5 × 5**：钟表给出 5×5 = 25 ≡ **12**。但整数世界的事实是 25。如果协议需要的是"25"这个**整数语义**（比如"格子的乘积应等于 25"），mod 13 直接给错——不是算错，是**世界太小，25 这个数不存在**。

真实对应：S09 讲过 b-bit × b-bit 的积要 2b 位（requant 的位长公式 q + log n + 1 就是它）。LLM 的中间量是 i64、乘积会到 128 bit——放进 31-bit 的 M31？**溢出 = wrap-around = 正确性论证直接失效**（域里 25 和 12 无法区分，作弊与诚实不可分辨）。

> **铁律**：域阶必须大于计算链条中**最大中间值的界**（含所有乘积与累加），否则一切证明失去意义。

BN254 Fr（~2²⁵⁴）为什么安全：2¹²⁸ 级的安全参数下，i64 乘 i64 的界（2¹²⁸）< 2²⁵⁴ ✓（这正是 S01 域化一致性论证的前提）。M31（2³¹）显然装不下——**所以小域系统必须配套"表示学"**，见 §4–5。

## 3. 解法一：换一台刚好大的钟——Goldilocks

`p = 2⁶⁴ − 2³² + 1`，自证它的约减魔法（一行）：p ≡ 0 意味着 **2⁶⁴ ≡ 2³² − 1 (mod p)**——任何 128-bit 乘积的高位可以**一次减法**折回低位。

- 单 limb：乘法就是原生 `uint64` 运算；
- **2-adicity = 32**：存在 2³² 阶乘法子群 → 能做 2³² 点的 FFT/FRI（M02 折叠树的域）；
- 剩一个坑：32-bit × 32-bit 的积（≈2⁶⁴）可能**恰好超过 p**（p ≈ 1.83×10¹⁹，2⁶⁴ ≈ 1.84×10¹⁹）——所以 Goldilocks 系统对乘积要做两段拆分（这是它生态里反复出现的"lazy reduction"约定）。

## 4. 解法二：扩展域——在 mod 13 里亲手造一台 169 格的钟

小域装不下，可以**造更大的钟**。在 F_13 上找一个**不可约**二次多项式：试 X² − 2。2 是不是 mod 13 的平方？查 2⁶ = 64 ≡ 12 ≡ −1（非平方的标志）→ **X² − 2 无根、不可约** ✓。于是造出：

```
F₁₆₉ = F₁₃[α]，其中 α² = 2     （元素形如 a + bα，共 13² = 169 个）
乘法：(a+bα)(c+dα) = (ac + 2bd) + (ad + bc)α
例：(1+2α)(3+α) = (3 + 2×2×1) + (1×1 + 2×3)α = 7 + 7α     （自己展开验算：3+α+6α+2α² = 3+7α+4 ✓）
```

三个要点：

1. **装得下了**：169 > 100——如果计算需要区分"100 和 12"，F₁₃ 做不到、F₁₆₉ 做得到。真实世界：M31 装不下 64-bit 值 → 用 **M31²**（62-bit 级）；F₂ 装不下任何东西 → **塔** F₂ ⊂ F₄ ⊂ F₁₆ ⊂ … ⊂ F₂₁₂₈（Binius 的"塔"就是这个：每层都是上一层的二次扩展，嵌套算术免费）；
2. **扩展域的元素仍是多项式**——sumcheck/查表协议原封不动地在扩展域上跑（S06/S09 的机器不挑域）；
3. **安全性的角色**：FRI 的健全性需要域 ≫ 次数（M02 §5 的教训），小域系统用**低度扩展域**来满足它——扩展域是"装值"和"保安全"的双重解法。

## 5. 2-adicity：FFT/FRI 的入场券（回到你自己的玩具）

S02 说 12 = 2²×3 → **mod 13 的 2-adicity = 2**，乘法群里最大 2 幂阶子群是 4 阶——**正是你在 M02 手跑 FRI 用的 H = {1,5,8,12}**，折两层恰好用尽。2-adicity 决定 FFT/FRI 的最大规模：

| 域 | 2-adicity | 最大 FRI/FFT 规模 |
| --- | --- | --- |
| mod 13 | 2 | 4 点（你已用完） |
| Goldilocks | 32 | 2³² 点 |
| BN254 Fr | 28 | 2²⁸ 点 |
| M31 | **1**（2³¹−2 = 2×(2³⁰−1)） | 2 点！→ Circle STARK 用"圆群"绕开（一句话级） |

## 6. DeepProve 为什么留在 BN254（完整账）

1. **HyperKZG 绑定配对** → 绑定 BN254 这条配对友好曲线；BaseFold 版也在 BN254（Ceno 库实现）；
2. **换域的理论成本极低**：sumcheck/LogUp 是"域无关"的（只要求"一个域"）——换域只需换 PCS 与曲线，PIOP 原封不动。**S10 讲的 PIOP/PCS 解耦在这里第二次兑现**：论文的 BaseFold 版就是同一套算子协议换了个 PCS；
3. **不换的代价**：254-bit 算术比 Goldilocks 慢一个量级；查表/sumcheck 占 50%+ 的时间本可以再缩；
4. **不换的理由**：配对验证方极便宜（1 次配对）、生态成熟（arkworks 全家桶）、GPU MSM 已有（仓库带 cuda feature）；
5. **前沿方向**：迁 Goldilocks/31-bit + 哈希 PCS = "PIOP 不动、底盘全换"的改造——这是 M08 顶石设计的候选题之一。

## 7. 选型三问（把方法装进口袋）

1. **值域上界多大？**（含乘积与累加 → 域阶铁律；不够 → 扩展域或换大域）
2. **承诺走哪族？**（配对 → 大素数域；哈希 → 小域+2-adicity；混用 → 双域系统）
3. **硬件目标？**（CPU 大核 → 64-bit；SIMD/GPU → 31-bit；FPGA/ASIC 位运算 → 二进制塔）

三个负载练习见作业。**方法总结**：域不是信仰，是"值域 × 承诺族 × 硬件"三约束的联立解。
