## 2. 层与层的接力：GKR 范式

图中最值得命名的一环是"逆拓扑逐算子归约"。它的学理出身是 **GKR 协议**（Goldwasser–Kalai–Rothblum, 2008）：把计算按层切分，**用一次 sumcheck 把"第 i+1 层输出在某随机点的取值"归约成"第 i 层输入在某随机点的取值"**，从输出层走到输入层，验证方始终只追踪 O(1) 条主张。

DeepProve 论文对此的表述：*"Similar to the fabled GKR protocol, we compose these operator protocols in a layer-by-layer fashion."* 工程上有三处改造（对照你已有的知识就能懂）：

1. **层内协议按算子定制**：线性层直接用 einsum sumcheck（Σ_收缩维 LHS·RHS，S06 的二表乘积正是它的 2×2 缩影），非线性层用查表+linking（S09）——比通用 GKR 的"加法门/乘法门"表述快得多；
2. **claim 是单链**：每个算子被设计成"输出主张 ⇒ 输入主张"的一对一归约（einsum 的 sumcheck 终点就是输入点），避免了经典 GKR 每层两条主张的合并开销；
3. **静态部分前置**：权重/查表在 setup 期就承诺好（S07 的仪式做一次、全体层共用），证明期只对动态 witness 承诺。

**为什么这叫"范式"**：S09 的分数折叠树、卷积的 FFT 矩阵委托（zkCNN 式蝶形分层），都是同一句话的不同应用——**"分层 + 每层一次 sumcheck + 挑战点逐层传递"**。学会识别这个形状，你就获得了读任何新协议的模板。

## 3. DeepProve 全景：一次真实的 LLM 推理证明

把机器开起来。以 GPT-2 的一次推理（序列长 s=512）为例，端到端数据流：

```
① 前向推理（i64 定点算术）：
   Transformer 逐层算，每个节点的输入/输出/辅助量（LN 均值方差、softmax 位移）
   记入 Trace —— 一张 HashMap<节点, 快照>。这是证明的唯一数据来源。

② 域化与承诺（S02/S03/S07）：
   每个 i64 → Fr（负数加一圈）；表补 2 的幂 → MLE；
   全部 witness 表批量 MSM 承诺（2²⁰ 一块，块数 ≈ 元素总量/2²⁰）；
   权重/查表的承诺 setup 期已做好。

③ 播种（S04/S05）：
   V（transcript）掷随机点，对"最终输出"（只有最后一行 logits！）
   与"跨块边界张量"求值立主张。

④ 逆拓扑逐算子归约（S06/S09 + 本讲 §2）：
   稠密层：einsum sumcheck（收缩维 768 → 10 轮；建表扫全张量）；
   GELU/softmax/RMSNorm：查表 witness + LogUp 双侧折叠 + linking；
   每个算子吐出输入侧新主张 → 上游继续。

⑤ 收口（S08）：
   上百条主张 → batched sumcheck → RLC → HyperKZG 折叠 + 三点 → 1 次打开。

⑥ 打包与验证：
   ChunkProof（本 chunk 的全部 sumcheck 消息 + 打开证明 + 结构与边界承诺）
   → 多 chunk 按 seed 链串联（每个 chunk 的随机性依赖前面所有 chunk 的承诺
     ——验证方逐字节重放，chunk 无法被重排/替换）
   → V 核对：每轮 sumcheck（便宜）、边界承诺相等（相邻 chunk 对同一张
     边界张量的两次独立承诺必须相同）、配对核验（1 次 MSM + 1 次配对）。
```

**两条成本规律**（现在你可以自己推出来，不许背）：

- **MSM 的量 ∝ 数据总量**：witness 域化元素有多少，就要做多少 MSM 标量乘（每 2²⁰ 一块，一块 ≈ 2.7×10⁷ 次点加，Pippenger w=10）。注意力 score 张量是 s×s 的 → 数据量随序列长度平方涨；
- **sumcheck 的实例数 ∝ 算子节点数**，单实例的轮数 ∝ log(收缩维)，但**建表段扫全张量** → 总时间仍随数据量涨，只是涨的方式不同（带宽型 vs 实例数）。

**final-token 优化的定量含义**：GPT-2 的 logits 是 512×50257 的表（i64 下 206 MB），但用户只关心**最后一个 token** 的输出——只对最后一行（0.4 MB）立主张、进证明。证明量从 O(s²) 降为 O(s)。

**chunk 与流式**：一张 2²⁰ 的表 = 32 MB（Fr），GPT-2 一层几十张——内存装不下整份 trace 时，把模型图切成 chunk：每个 chunk 证明完立即释放其张量（流式模式，本仓库当前分支的主题）；chunk 间靠 §3-⑥ 的两个机制焊死。**你在 S08 学的收口在每个 chunk 内部各跑一次**。
