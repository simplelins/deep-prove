## 1. 有限域：证明系统的宇宙

**定义**。素数域 `F_p`（p 为素数）：元素 {0, 1, …, p−1}，加/乘按 mod p，非零元可逆（费马小定理：a^(p−2) = a⁻¹）。

**为什么是素数域而不是整数/浮点**：

1. **无舍入**：整数运算是精确的，证明才有意义；
2. **有逆元**：除法、插值、随机线性组合都需要逆；
3. **`Z/pZ` 是域 ⟺ p 素数**——合数模下会出现零因子（a·b ≡ 0 而 a,b ≠ 0），多项式根的个数不再受次数控制，一切健全性论证崩塌。

**本项目的域**：`ark_bn254::Fr`，域阶（源码 `arkworks-algebra/curves/bn254/src/fields/fr.rs:4`）：
`r = 21888242871839275222246405745257275088548364400416034343698204186575808495617`
（254 bit：2^253 ≈ 1.447×10⁷⁶ < r ≈ 2.189×10⁷⁶ < 2^254 ≈ 2.895×10⁷⁶；MontBackend 4×64-bit limb，生成元 5）。
**易混警告**：常被引用的十六进制 `0x30644E72…F0000001` 是**基域 Fq**（G1 坐标域，fq.rs:4，十进制末尾 …08583），不是 Fr（末尾 …95617）——证明算术全部在 Fr 上。
工程表示：4×64-bit limb 的 **Montgomery 形式**（R = 2^256；乘法走 CIOS，进出做 Montgomery 变换）——这是所有硬件/高性能实现的公共起点（见 `prove_pipeline_FPGA算子开发指导.md` §2.1）。

**i64 → Fr 的映射**（trace 域化的规则）：x ≥ 0 → x；x < 0 → p − |x|。由于 |x| < 2^63 < p，这是一次条件加法即可完成的归约。代码：`to_field`（quantization 模块）。

**自测 1**：p = 13。求 7⁻¹、计算 (−5)·(−9) mod 13。答案：7⁻¹ = 2（7·2=14≡1）；(−5)(−9)=45≡45−39=6；域中即 (p−5)(p−9) ≡ 6，符号行为与整数一致。

## 2. 多项式与 MLE：把数据变成代数对象

**单变量多项式**：p(X) = Σ aᵢXⁱ，次数 deg p。两个基本事实（后面反复使用）：

- **根的个数 ≤ 次数**（域上成立，这是素数性的直接红利）；
- 由此得 **Schwartz–Zippel 引理**：deg d 的非零多项式在均匀随机点取零的概率 ≤ d/|F|。**把这句记死：证明系统的健全性 = "作弊者无法让一个高次多项式在随机点上恰巧为零"。**
  **本系统的精确口径（易错点）**：随机挑战**不是**全域均匀的——`challenge_scalar` 取 16 字节 XOF 输出再 `from_le_bytes_mod_order`（transcript/mod.rs:29-34，注释原文 *"for challenge we dont need 256 bits we only need 128 bits"*），即每个挑战坐标均匀落在 [0, 2¹²⁸)（且 2¹²⁸ < r，无模回绕偏差）。因此命中误差按 **d/2¹²⁸** 计，不是 d/2²⁵⁴：d=6 时单点误差 ≈ 2⁻¹²⁵·1.5，仍远超 128-bit 安全线，但数量级必须写对。

**多线性扩展（MLE）**：n 变量多线性多项式 f 在布尔超立方 {0,1}ⁿ 上有 2ⁿ 个值，这 2ⁿ 个值**唯一确定** f（变量次数 ≤ 1）。证明系统把一张 2ⁿ 的数据表直接当作 f 的求值表：

- 索引约定：表中第 i 项 = f(bit(i))，bit(i) 为 i 的二进制展开；
- 本仓库约定（**全系统统一，必须记牢**）：**索引第 b 位 ↔ 求值点第 b 个坐标**（第一个坐标是最低位）；张量按行主序展平时最后一个维度占最低位；
- f 在任意点 r ∈ Fⁿ 的取值：`f(r) = Σ_{x∈{0,1}ⁿ} f(x)·eq(r,x)`，其中 `eq(r,x) = ∏_b ( r_b·x_b + (1−r_b)(1−x_b) )`。

**EQ 多项式的三个事实**（贯穿全课程）：

1. eq(r, x) 在 x = r 处为 1，在其余布尔点为 0——它是"求值"的代数化身；
2. EQ 表可用**倍增法**生成（首元 1，每轮把旧表上移一位、新坐标放位 0），2ⁿ−1 次乘法（代码 `poly/eq.rs`）；
3. EQ 表元素和恒为 1（把 r 代入第 2 条恒等式即得）。

**例 1（必须手算）**：f 的表 [3,1,2,0]（2 变量，索引位 0↔第一坐标）。求 f(5,4)：
eq(5,·) = [−4, 5]，eq(4,·) = [−3, 4]，两维张量积得 EQ 表 [12, −15, −16, 20]；
f(5,4) = 3·12 + 1·(−15) + 2·(−16) + 0·20 = **−11**。
（校验 EQ 元素和 = 1 ✓。此例在 L02 的 sumcheck 与仓库文档 §2 中反复出现。）

**MLE 的两个关键性质**：

- **乘积保持多线性语义**：两个 MLE 的逐点乘 g = f·h 的表 = 两表逐点相乘，g 仍是 MLE（次数 2，但只在"乘积多项式"意义上使用——sumcheck 对此有精确处理）；
- **随机点求值 = 承诺内容的指纹**：f(r) 对随机 r 的取值在计算上"锁死"了整张表（改表中任何一项都会改变 f(r)，除非伪造整个多项式——而这需要与承诺绑定，见 L04）。

**代码落点**：`DensePolynomial`（dp-crypto `poly/dense.rs`）就是求值表；`evals`（`poly/eq.rs`）；`evaluate` 的两半法优化（dense.rs:584）。仓库约定速查见 `prove_pipeline_FPGA算子开发指导.md` §2.1/§2.4。

## 3. 交互式证明 → IOP → Fiat–Shamir

**问题**：证明方 P 拥有超大计算（比如一次 LLM 推理），验证方 V 只有毫秒级算力。V 如何在**不看数据**的前提下相信结论？

**交互式证明（IP）**：P 与 V 多轮通信；要求**完备性**（诚实的 P 总能说服 V）与**健全性**（作弊的 P 说服 V 的概率 ≤ ε，ε 叫健全性误差）。若 ε 只依赖安全参数而不依赖问题规模，协议才可用。

**IOP（交互式预言机证明）**：把"P 发送长消息"改为"P 对一条长多项式/表做**承诺**，V 只能查询其在指定点的取值"。这是现代 SNARK 的标准形态：

```
PIOP（概率可检查证明：sumcheck、GKR、查表等） + PCS（多项式承诺方案：KZG、FRI…）
    = 可执行的证明系统
```

**Fiat–Shamir 变换**：交互式协议里的 V 每轮发随机挑战；把"V 的挑战"替换为"对到目前为止全部通信内容的密码学哈希"，协议即非交互化：

- 挑战 = H(transcript 状态) 的输出截断；
- P 无法"回滚"哈希重选有利挑战——**吸收顺序就是协议本身**；
- 工程生死线：P 与 V 必须逐字节一致地吸收同样的消息（本项目用 Blake3，全部吸收点/标签见 `prove_pipeline_FPGA算子开发指导.md` 附录 A）。

**例 2（健全性直觉，必须想通）**：协议要求 P 证 Σ_x g(x) = Y。P 若在第一轮发了一个假的轮多项式 g̃，只要 g̃(0)+g̃(1) = Y 就能过第一道检查。但随机挑战 r 落在 g̃ 与真 g 的差异点上（g̃−g 是次数 ≤ d 的非零多项式，至多 d 个根）概率 ≤ d/2¹²⁸（挑战熵口径，见 §2）。一旦未命中，P 从此在为一条假多项式维持自洽，最终必在某个可查等式上暴露。**整门课的所有健全性论证都是这个模板的变体。**

**例 3（零知识是什么）**：完备性/健全性之外还可要求"V 学不到除结论外的任何信息"（模拟器存在性）。DeepProve 的证明目标是**模型推理结果可信**（integrity），不是隐藏输入的隐私证明，所以其协议不以 ZK 为目标——理解"zkML ≠ 一定 zero-knowledge"是你建立正确术语观的第一课。

**代码落点**：transcript trait 与 Blake3（dp-crypto `arkyper/transcript/`）；挑战派生 `challenge_scalar`（16 字节 XOF mod p）；`read_challenges` 连续采样的实现现状（同值）已记录在 FPGA 指导 §2.3。
