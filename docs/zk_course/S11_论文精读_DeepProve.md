## 1. Abstract & §1 Introduction（p.1–3）：论文在争什么

**原文主张**：DeepProve 是**第一个**对"完整 LLM 推理"做端到端验证的系统——验证**所有生成 token**。此前的工作只覆盖一部分：zkGPT 只证**单个 token**，zkLLM 只证 **Softmax** 这一个算子，zkML 只证特定模型的特定矩阵乘。

**通俗解释**：想象你怀疑云服务商"说用大模型、实际用小模型糊弄你"（论文给了三个场景：企业降级模型省成本、编程助手执行恶意代码、政府采购防腐败）。SNARK 能解决——但此前没有任何系统能把"一整段生成文本确实由该模型算出"完整证下来。DeepProve 的核心断言：**证"输出序列正确"，而不是把推理电路化**。

**关键数字（摘要原话，记这几个就够）**：
- 吞吐 **174 TPM**（GPT-2）/ **86 TPM**（Gemma 3），单机；
- 比当时最优系统 [zkGPT] 快 **20–60×**；
- 验证 **1–3 秒**；证明 7–27 MB（GPT-2）、16–54 MB（Gemma 3）；
- 分布式 17 台机器 **1655 TPM**。

**§1.1 五大挑战**（论文诚实列出的"为什么以前没人做成"）——每条都对应你课程里的一个知识点：

| 挑战（原文） | 人话 | 课程对应 |
| --- | --- | --- |
| **Quadratic blowup**（p.2） | attention 让单 token 电路已是平方级；逐 token 建电路的证明时间是 O(\|C\|³)——"prohibitively impossible"。推理界用 KV-cache 逃掉了，但证明世界里 P 要证的是"算过"，cache 反而是要被证明的数据 | S10 §3 的 final-token 优化就是答案 |
| **Pure-integer inference**（p.2） | SNARK 活在素数域，LLM 活在浮点；浮点上域有精度/效率损失；量化格点又必须够细——**格太粗，小值装不下，离群值撑爆格** | S02 域化；S09 requant 表 |
| **Outlier activations**（p.2） | 激活里混着 [9,1,33,11,3,**1000.0**] 这种离群值：8-bit 量化会把它们压成 0 或 1，精度归零 | S09 §1"非线性为什么难"的量化侧面 |
| **Requantization strategy**（p.2-3） | 新式 SNARK 用 64-bit 小域（快），但量化乘几次就位长爆炸，必须"每几步 requant 一次"，而 requant 本身有损 | S09 requant 表（乘子+右移折进查表） |
| **Batch proving**（p.3） | 非线性层是"SNARK-unfriendly"且**反复出现**；整个 trace 有"多条多项式、多个求值点、多趟前向"——不批量就死 | **S08 整讲**就是答案 |

**§1.2 六条贡献**（p.3）——注意每条背后是一个课程概念：
1. 专用 PIOP：requant、**用"非确定性值"证归一化层（证明方不现场算平方根和逆）**、多头 attention、旋转位置编码；轮到轮健全性 + Fiat–Shamir（= S05+S06）；
2. **认证算法**：证"整段输出"的窍门（见 §3.1 伴读）+ PCS 组装；
3. 工程优化：延迟 requant、离群钳位；
4. Rust 开源实现 + 全部数字；
5. 精度可比（12-bit 量化与浮点基线差 0.34% 以内）；
6. **proof-of-non-hallucination**：把"没幻觉"也证明出来（§4.4）。

**容易读错的地方**：摘要的"174 和 86 TPM"——174 是 GPT-2 且来自**次机**（表 2），86 是 Gemma 3（表 2）；主机的数字看表 1（GPT-2 135 TPM@512）。不同表不能混着比。

## 2. §2 Preliminaries（p.4）：量化公式——S09 那张表的出生证明

**原文**：仿射量化 x̂ = s×(x − z)（s 尺度、z 零点）；线性层 Z = X×Y + W 的量化关系 [x̂]×[ŷ] = M×[ẑ]，其中 M = (s_X·s_Y)/s_W；再把 M 写成 M = 2^(−2n)·M′（M′ 整数），M ∈ (0,1) 取 M = 2^(−k)（最接近的 2 的幂）。

**通俗解释**：定点乘法后，结果带着"多乘了一次的尺度"，要把它除回去。除以任意数在钟表世界里要逆元（贵），所以选 **M 是 2 的负幂 → 除法变右移**。而"右移 + 钳位"没有多项式表达 → **查表**（S09）。所以这个 §2 的三行公式，就是 S09 requant 表的出生证明。

**§2.2**：LLM = embedding 层 + N 个 transformer block + unembedding 层；自回归生成。图 1 是 GPT-2 结构（论文后文所有协议对着这张图讲）。

## 3. §3 Technical Overview（p.4–5）：全文纲领，三步走

### 3.1 认证算法——论文最聪明的一步（p.4）

**原文**：认证算法把**整段输入 token + 整段输出 token 拼接**后喂进模型，做**一次**前向推理；用 Attention Mask 保证位置 t 的预测只看得到前 t−1 个 token；逐位置核对"模型预测 == 声称的下一 token"；最后一个位置才真正做一次推理步。

**通俗解释**（用论文自己的例子，p.4）：prompt 是 "The cat"，声称输出 "sat"。拼成 [The, cat, sat] 喂进模型一次，模型在每个位置给出预测 [cat, sat, on, …]。核对：位置 0 预测 "cat" ✓、位置 1 预测 "sat" ✓（**位置 1 只能看到 "The cat"——Attention Mask 保证它没用过 "sat" 这个答案**）。

**为什么这一步是革命性的**：它把"逐 token 证 s 次"（平方级）换成"一次前向 + 逐位置核对"（线性）——这正是 §1.1 第一条挑战的解。依赖的前提：**argmax 的确定性**（论文：GPT-2 图 1 与 Gemma 3 图 4 的最后一步 argmax 提供确定性）与 Attention Mask 的可证明性（PIOP split 里它占 3.96%，表 7）。

### 3.2 纯整数推理的两个武器（p.4–5）

- **混合精度（mixed-precision）**：残差层把"归一化后的输入"和"尺度千差万别的块输出"相加——两者必须同一尺度 → 中间用**更大的位宽**，让量化格细到能同时罩住大小两端的值。代价（精度损失）用更大的格换回来。
- **离群平滑（outlier smoothing）**：用正交矩阵 M（M·Mᵀ = I）：X·W = (X·M)·(Mᵀ·W)。妙处：**X·M 和 Mᵀ·W 都比原 X、W 好量化**（离群值被正交旋转摊匀）；且 X 永远不需要真正物化——右乘 M 直接**吸收进 W**（W′ ← W′·M）。论文引用 [CCKDS23]。

**与课程对应**：这两条是**推理算法设计为可证明性服务**的例子——量化的每个选择（位宽、平滑、钳位）都在为"查表/sumcheck 能处理"让路。课程 S09 §1 讲的"非线性难"，论文在这里给了系统级答案。

### 3.3 高效证明（p.5）

四个决定，全部是课程已学概念的组合拳：
1. 认证算法让**一次前向产出多个预测** → 用 **batched variants** 一次证多个（S08）；
2. 工具 = **sumcheck（线性层）+ LogUp（非线性层）**，按 GKR 式逐层组装（S06/S09/S10 §2）；
3. **不承诺中间值**——只承诺模型参数和查表需要的 witness（"cannot be virtualized"，§4.2；virtual claims 概念：验证方能自己推的值不承诺，见 [Tha25]）；
4. **延迟 requant**：requant 与它后面的非线性操作**合并成一次查表**一起证——两次查表变一次。

## 4. §4 DeepProve 设计（p.5–10）

### 4.1 预处理（p.5–6）与 4.2 证明阶段（p.6）

- **预处理（一次性）**：①解析 safetensors/GGUF/ONNX 成算子图；②量化：**校准集**跑一遍收集每层统计 → 定每层的 s、z 与钳位范围 [−a,a]（离群值截断）；③承诺权重与量化参数（batch commit，S07）。
- **证明（每个输入一次）**：①量化推理（逐算子：钳位 → 平滑 → 混合精度 → requant），**同时记录执行 trace（= witness）**；②witness 承诺：只承诺"**不能被 virtualize**"的值——例如 softmax 前加的那些数（LogUp 要求承诺表和 witness，S09）；③算子证明。

**算子证明循环（p.6，§4.3 开头）**——这就是你 S10 §2 画的 claim 链，论文原文的表述：从最后一层 L 开始，P 对 L 的输出立 claim；Fiat–Shamir 吸收全部承诺；跑 PIOP；V 得到 ①L 正确的证明 ②模型参数的 claims ③witness 的 claims ④**L−1 输入的 claims（virtual claims）**；如此逆推到输入层；PCS 收口时用 batching opening 把所有模型/witness 的求值合并成**一次**打开（S08 整讲）。

### 4.3.1 Embedding（p.7）——第一个"妙手"

笨办法：查表论证表 T（词表 5 万 × 维度 768 的表！）——承诺量爆炸。论文的观察：**验证方手里就有索引向量 x**（输入是公开的），于是把 Embed 重写成矩阵乘 Y = H_T·X，其中 H_T 是每行恰有一个 ±1 的**稀疏矩阵**。妙处：H_T 非零元是 ±1 → **证明方根本不用承诺它的 MLE**，验证方本地 O(s·log n) 就能算它的值。**教学点：证明方不承诺验证方能自己算的东西——S10 §3-⑥ 的 verifier 重放、S08 里 eq 表不用承诺，全是同一个原则。**

### 4.3.2 Requantization（p.7–8）——第二个妙手（对应 S09 §4.3.2 的完整版）

两种情况：**Case 1**（x 在正确范围内）：y = ⌊c′·x/2^(δ+f)⌋ − 2^(g−1)——除法是 2 的幂 → 右移 → 用**可分解表**（把 x 切成 k-bit 块，逐块范围检查，只保留最高 g/q 块）。**Case 2**（x 超范围）：先算 x′ = Quant(2^k/x + 2^(g′−δ−1))——**用查表实现"取倒数"**！然后查三张表：T_a（范围检查）、T_b（符号判别：负 → −1、正 → 1）、InRange（高位块是否全零），组合出钳位后的输出。全部是查表——**没有除法、没有开方、没有比较门**。

**课程对应**：S09 §4.3.2 的"requant 的乘子与右移已折进表里"就是这里的完整版。这是全文**最贵的一个算子**——§5 表 7 显示 requant 占总证明时间 **27%**。

### 4.3.3 RMSNorm（p.8）——第三个妙手（"证明方送答案"模式）

标准做法要证明"除以 sqrt(ΣX²)"——开方+逆元都是 SNARK-unfriendly，且每步引入舍入误差。论文的做法：

1. 证明方**自己带一个非确定性 witness**：d[i] = Quant(1/√(1/d·ΣX[i,d]²))——即"把倒数直接算好送给验证方"；
2. 证 Y[i,j] = X[i,j]·d[i]（一个普通乘法 sumcheck）；
3. 但验证方不知道 d 是不是真的——所以**再加一条完备性检查**：Σⱼ Y[i,j]² = n·(ΣX²)/(ΣX²) = **1**。

**教学点**：这是"证明方送答案 + 检查答案"模式——把贵计算（开方/逆）从电路里挪到证词里，再用一条**便宜的代数恒等式**验证答案的自洽。注意恒等式的形状：分子分母同项相消（论文原式 = n·(ΣX[i,j]²)/(ΣX[i,j]²) = 1），你还能看出它为什么防得住"随便编一个 d"：d 错了则 Y = X·d 错，ΣY² ≠ 1。Protocol 10（附录 B）含 requant 变体。**RMSNorm 占 witness commit 的 10.59%、PIOP 的 6.02%（表 7）**。

### 4.3.4 LayerNorm（p.8）

LayerNorm(X) = RMSNorm(X − μ)，所以拆成两步：①对 X′ = X − μ·I 跑 RMSNorm 协议；②μ 本身也是非确定性的，其良构性用**一次查表**验证：Quant(1/d·ΣX[i,j]) ≡ μᵢ。又是一个"均值倒数查表"。

### 4.3.5 MHA（p.8–9）——第四个妙手

单头 attention（Protocol 14, B.8）：P 先算 T_K = Q·Kᵀ 与 T_V = Softmax(T_K/√(d/h))，发 Y 的承诺；V 得到 Y 在随机点 r 的求值主张后，**逐步反推**：先从 f_V 拿到 V 的主张（y_i = Σₓ eq(x,r_y)·vₓ），对 T_K 跑 softmax 的查表协议（Protocol 13, B.7），再对 T_K = Q·Kᵀ 跑**批量矩阵乘 sumcheck**（Protocol 4），最后用矩阵乘 PIOP 证 Q = X·W_Q（K、V 同理）[Tha13]。**三个矩阵乘 + 一个查表，串成一条链**——你的 claim 链直觉直接适用。

**d/h 不是 2 的幂怎么办**：pad 到 Q̂,K̂,V̂ ∈ R^(s×d̂ₕ)，pad 矩阵 P_I ∈ {0,1}^(d×d̂ₕ) 每列恰一个非零元 → **V 用 O(d) 就能本地评估它**——又是"稀疏=不承诺"原则。

### 4.3.6 非确定性（p.9）

LLM 推理可能是**随机的**（从 top-k 采样）。解法：把"纯随机种子"当附加输入——种子正确性的证明用可验证随机数或与 V 的交互协议（§4.3 [CCH+19]）；论文强调这是**先前所有可验证 LLM 推理都没处理**的问题。

### 4.4 非幻觉证明（p.9–10）——额外的赠品

**LLM-Check** [SBS*24] 的检测信号：Attention Score′ = Σᵢ log Ker_i，其中 Ker(Q,K) 经因果掩码后是**下三角矩阵 → 行列式 = 对角元之积** → log-det = 对角线 log 之和。DeepProve 用**查表近似 log** + **sumcheck 求和**把它并入电路（Protocol, B.9）。结果（表 5，512 长度）：GPT-2 AUROC 68.69 / 准确率 67.90 / **只花 98.1 ms**；Gemma 3：65.94 / 64.16 / 21.1 ms——与原方法（非量化、非证明版）的 AUROC 接近（原 LLM-Check：GPT-2 68.29%）。**"证明没幻觉"只占证明总时间的千分之一量级**——因为它的查表/求和形状和主体协议完全同构。

### 4.5 分布式证明（p.10）

chunk 切分 DAG；每个 chunk 是独立子 DAG；**三步（witness 承诺/证明主张/承诺打开）都能在子图上做且不重做密码学**；每个 worker 把 chunk 的**输入和输出都承诺**（V 核对：①切分与原图一致、没丢节点；②本 chunk 输入承诺 = 下一 chunk 输出承诺——**你 S10 §3 的"边界承诺相等"正是论文原话的机制**）；coordinator 把 trace 子集异步分发（某个 chunk 的 trace 一就绪就发）——除了最后一个 chunk，通信延迟被流水线藏掉。数字：9 台 1079 TPM（6.19×）、17 台 1655 TPM（10.64×）；通信总量 43–54 MB；100 Mb/s 广域网下只慢 2%。

## 5. §5 Evaluation（p.10–13）：教你读表 1–8

**机器与实现**：主机 EPYC 9534（24 核 2.9 GHz，500 GB）；次机 Ryzen 7950X3D（16 核 4.2 GHz，128 GB）。实现：Rust + Scroll 的 **Ceno** 库；PCS 两套——**BaseFold**（透明、抗量子、证明大）与 **HyperKZG**（小证明、需 setup）——**PIOP 与 PCS 解耦，两套共用同一套算子协议**（你在 S07/S08 学的机制）。

**表 1/2（性能主表）怎么读**（GPT-2, 512 长度为例）：

| PCS | 证明 | 验证 | 证明大小 | TPM |
| --- | --- | --- | --- | --- |
| BaseFold（主机） | 41.98 min | 4.44 s | 24.33 MB | 135.26 |
| HyperKZG（主机） | 76.7 min | 4.02 s | **11.4 MB** | 122.25 |

- **证明时间随序列长度近似线性**（长序列摊薄更好 → TPM 上升）；
- HyperKZG 证明**小一半**但证明**更慢**（对 witness 的承诺效率随长度此消彼长——论文原话："HyperKZG being more efficient to commit to witness polynomials, which become more relevant at longer sequence lengths"）；
- Gemma 3 比 GPT-2 慢：模型大 2 倍余；Gemma 3 在次机 512 长度 HyperKZG **OOM**（表 2 里标 OOM）；
- **吞吐的 CPU 时钟故事**：次机核少但时钟快（4.2 vs 2.9 GHz）→ 次机反而 175 TPM——**吞吐瓶颈在单线程延迟而非核数**。

**表 3（与先前系统对比）**：zkGPT 275 TPM 但**只证单 token** 且用 200 GB；zkTorch 4 TB RAM；Ours 127 TPM 证**全部输出**——"数字不能裸比，证的东西不同"（论文自己先说了这一点，并注明 zkLLM 因 GPU 不可复现被排除）。

**表 7（逐层瓶颈，p.13）——全文最有行动价值的一张表**：
- 证明时间构成：witness 生成 ~57% / PIOP ~35% / 打开 ~1%；
- **>50% 花在激活函数、Softmax、requant 上；requant 单项最贵 = 27%**——查表论证是整个系统的主战场（S09 的地位由此而来）；
- witness commit 侧：softmax 29.68%、requant 27.49%、activation 22.96%（GPT-2）；Gemma 3 里 requant 41.60% 更重。

**验证与证明大小**：验证 <3.2 s（GPT-2）/<3.5 s（Gemma 3）随长度略涨；证明 9–43 MB，HyperKZG 系统性小于 BaseFold。

**内存**：GPT-2 9 GB / Gemma 3 176 GB（后者在 128 GB 次机 512 长度 OOM）——>3B 参数模型需要 TB 级内存，空间高效 PCS [FP24,FP25] 或磁盘化是未来方向。

**精度（表 4）**：cosine 相似度——GPT-2：8-bit 0.9967、10-bit 0.9993、12-bit 0.9996；**Gemma 3 必须用 12-bit**（8-bit 只有 0.2935、10-bit 0.4998——它有极端离群值 + 额外 RMSNorm 层，传统平滑技术不适用）。量化从 8→12 bit 只增加 **0.8% 证明开销**（因为 requant 的查表协议不敏感于位宽——延迟 requant + 分解表的设计红利）。

**非幻觉（表 5）**：AUROC GPT-2 68.69（原 LLM-Check 68.29）、Gemma 3 65.94；prover 时间 98.1/21.1 ms——"证明中的千分之一"。

**分布式（表 6）**：9 台 6.19×、17 台 10.64×（512 长度 1655 TPM）；通信总量仅 43–54 MB（一轮交互）；广域网 100 Mb/s 下只慢 2%。

## 6. §6 Related Work + 附录地图（p.13–16）

**定位一句话**：经典 ML 可验证（决策树/小网络）→ 常规可验证推理（CNN，zkCNN 一脉 [LXZ*21] 精神最接近）→ 通用 ML 框架（性能换通用性）→ LLM 专用（zkML/zkTorch/zkGPT）。对三个直接竞品的判词（论文原话的转述）：
- **zkML**：把 GPT-2 编进 Halo2 电路——"generic"的代价是效率塌方 + 巨型架构要求；
- **zkTorch**：中间路线（按算子分解），但只证**一个输出 token**，实验用 64 核 4 TB RAM，且 sealing factor 限 2 的幂（精度损失）；
- **zkGPT**（SOTA）：单 token，且改掉了 GPT-2 的残差连接/attention mask/输出投影层；定点乘 + 固定 scale 查表 requant **无钳位** → 表更大。**DeepProve 是唯一在"证明的同一代码库"上给出精度测量的工作**（附录 C 列了量化/查表选表/钳位的各种坑）。

**附录地图（配合课程）**：
- **A.1 Protocol 1（sumcheck）**：就是 S06，论文给了轮到轮健全性（κ_rbr = min_j d_j/|F|）的正式定义与"domed state"证明——S06 §5 的"死亡螺旋"就是论文里 leave-the-dome 的过程；
- **A.2 Protocol 2（batched sumcheck）**：注意——论文版是"多个 sumcheck 实例用随机权重 r^j **线性组合**、最终在**公共点 r** 求值"；代码里跨不同点用的是 **eq 表进 sumcheck**（S08 §2）。两种批量视角互补，读的时候别把它们当成同一个协议；

- **C**：量化的工程坑（钳位、选表、位宽）——§1.1 离群值挑战的工程落地。

## 9. 关键数字速查（复习用）
