## 2. 调试与对拍工具箱（P9 的素材）

1. **transcript 吸收字节 dump**：在 `Transcript::append_bytes`（trait 默认实现处）加条件日志/写文件——这是端到端失败时的终极二分工具（FPGA 指导 §5.1）；
2. **claim 流 dump**：在 `Claim` 的构造点与 `add_witness_claim`/`add_common_claims` 打点，序列化 (poly_id, point, eval)；
3. **中间表 dump**：`generate_lookup_witness_for_chunk` 末尾、`fix_axes` 输出、sumcheck 每轮消息（`prove_round_and_update_state_parallel` 的返回值）；
4. **golden 对拍**：同一输入跑两份实现，逐字节比对上述 dump——硬件/优化改动的标准验收（S06 的 P2/P3 与 L08 的项目都依赖它）；
5. **小模型复现**：`Model::random_with_rng`（iop/mod.rs 测试）可用任意小模型跑全协议，是快速迭代的首选。

## 3. 关键约定速查（读代码时手边常备）

- 位序：表索引位 b ↔ 点坐标 r[b]；`fix_low` 相邻对；`evals` 倍增移位（FPGA 指导 §2.1/OP-04 有推导）；
- claimed sum 两种约定（einsum 重算 vs LogUp 先吸收）；
- transcript 标签总表（FPGA 指导附录 A）——任何新代码路径先登记；
- `read_challenges(n)` 连续同值的实现现状（blake3 XOF 位置语义）；
- chunk 内两份 transcript：块级（`b"model_chunk_proving"` + seed）与全局（seed 链）。

## 4. 常见卡点与解法（历届踩坑地图）

| 症状 | 根因 | 排查 |
| --- | --- | --- |
| verify 失败但各 sumcheck 单测通过 | transcript 吸收顺序/字节不一致 | dump 吸收流二分 |
| 手改位序后小例子"碰巧"通过 | 例子太对称（全 0/1 系数） | 用非对称随机小例子 + 与 CPU 对拍 |
| 多 claim 合并后值对不上 | eq_point_per_chunk 的块选择位没截 | 检查点长度 vs num_chunks |
| 证明耗时暴涨 | 请求了过大 witness 尺寸的 SRS/表未切块 | 看 batch_commit 的块数日志 |
| streaming 模式 seed 错位 | chunk 完成顺序与吸收顺序不一致 | 对照 `verify_streaming` 的循环顺序 |
