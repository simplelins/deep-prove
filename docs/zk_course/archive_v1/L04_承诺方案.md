## 1. 承诺要解决什么

sumcheck 结束时 V 手里只有一条求值主张 `f(r) = y`。若 f 没有被事先"锁死"，作弊的 P 可以现编一张恰好满足该等式的表。**多项式承诺方案（PCS）**在证明开始前给每张表生成一个短指纹 C，之后任何 claim 都用 C 兑现。一个 PCS 提供三个算法：

```
Commit(f) → C          短、绑定（改 f 必改 C）、可隐藏（可选）
Open(f, r) → (y, π)    证明对象 π 短
Verify(C, r, y, π) → bool   验证方不接触 f 本体
```

**DeepProve 的 PCS = HyperKZG**（BN254 上）：`type Pcs = HyperKZG<Bn254>`（testing.rs:9）。setup 期权重/查表承诺一次，witness 每 chunk 承诺一次。

## 2. 群与 MSM：承诺的算术基座

**椭圆曲线群**：BN254 G1/G2。标量乘 [a]₁ = a·G 形成一个"单向"代数结构：知道 G 与 [a]₁ 反推 a 是离散对数问题。**配对** e: G1×G2 → GT 满足 e(aP, bQ) = e(P,Q)^{ab}，使得"乘法关系"可以跨群验证。

**MSM（多标量乘）**：C = Σᵢ sᵢ·Gᵢ，254-bit 标量。朴素 O(N·254) 次点加；**Pippenger 桶法**：切 w 位窗口，每窗建 2^w 个桶，每个 (标量,窗口) 对做一次桶加（窗口值为 0 时跳过，概率 2⁻ʷ），窗口间位权合并。**精确计数（w=10、N=2²⁰）**：窗口数 ⌈254/10⌉=26；点加 ≈ 2²⁰×26×(1−2⁻¹⁰) ≈ **2.72×10⁷**，对比朴素的 2²⁰×254 ≈ 2.66×10⁸——**10 倍**。工程参数：N = 2²⁰ 标量（32 MiB）、基点表（SRS）64 MiB 常驻 HBM、桶阵列 2¹⁰×26×32B×双缓冲 ≈ 3.4 MiB 片上（FPGA 指导 OP-10）。**共享基点批量**（batch_poly_msm：多张表、同一套基点，基点读一遍 HBM）是 GPU/FPGA 的主要优化面。

## 3. KZG 承诺（单变量）

trusted setup 产生 τ（毒物，用后销毁）与 SRS：`[τⁱ·G₁]`、`[τⁱ·G₂]`、H、τ·H。

- **Commit**：p(X) = ΣaᵢXⁱ，C = [p(τ)]₁ = Σ aᵢ·[τⁱG₁]——**一次 MSM**；
- **Open(u)**：y = p(u)；商多项式 w(X) = (p(X)−y)/(X−u)（整除，综合除法 O(d)）；W = [w(τ)]₁；
- **Verify**：配对等式 `e(C − [y·G₁] , H) == e(W, [τ·H] − u·H)`。

**健全性直觉**：等式成立 ⟺ (p(τ)−y) = w(τ)·(τ−u) 在 τ 处成立 ⟺ (p(X)−y) 在 X=u 为零 **或** P 找到了 τ 的非零消去多项式——后者等价于离散对数攻击。y 错 ⇒ p(X)−y 在 u 处非零 ⇒ (X−u) 整除它才可能凑出 w ⇒ p(u) = y。一次配对核对，证明对象 O(1)。

**无余式批量打开**（本项目用法，`kzg_batch_open_no_rem`，arkyper/mod.rs:157-183）：对点 u_i，商多项式系数用综合除法递推 `h[i−1] = b[i] + h[i]·u_i`，每个 (d−1) 乘加；三个点共 3 张商表，一次 batch MSM 出 (w₀,w₁,w₂)。

## 4. 从单变量到多线性：把表当系数

MLE 的表 z₀…z_{N−1} 直接解释为一元多项式系数：`u(X) = Σ zᵢ·Xⁱ`，承诺 C = u(τ) = MSM（标量就是表本身，`msm.rs:47`）。**从此承诺锁的是"这张表"**——但打开目标是"MLE 在多维点 x 的取值 f(x)"，不是某个一元点。桥就是下面的 Gemini 变换。

## 5. Gemini 变换与 HyperKZG 三点打开（本讲核心推导，逐行对上代码）

**折叠**：p₀ = z（长 2^m），点 x = (x₀,…,x_{m−1})。逐变量折叠：

```
p_{i+1}[j] = (1−x_i)·p_i[2j] + x_i·p_i[2j+1]        （arkyper/mod.rs:351，注意代码写法 = x_i·(p[2j+1]−p[2j]) + p[2j]）
```

m−1 轮后剩长 2 的表，其再折叠即常数 = f(x)。**只有折叠中间表 p₁…p_{m−1} 需要承诺**（末值 V 可自算方向核对）。

**关键引理（本推导自己走一遍）**：把 p_i 分解为偶/奇两半 A_i(X²) + X·B_i(X²)（A_i、B_i 系数分别是偶/奇下标项）。则 u(X) = A₀(X²) + X·B₀(X²)，且 u(r) = A₀(r²) + r·B₀(r²)，u(−r) = A₀(r²) − r·B₀(r²)。于是

```
A_i(r²) = (p_i(r) + p_i(−r)) / 2
B_i(r²) = (p_i(r) − p_i(−r)) / (2r)
p_{i+1}(r²) = (1−x_i)·A_i(r²) + x_i·B_i(r²)
⇒ 2r·p_{i+1}(r²) = r(1−x_i)·(p_i(r)+p_i(−r)) + x_i·(p_i(r)−p_i(−r))
```

**这正是 HyperKZG 验证方的一致性检查**（arkyper/mod.rs:420-428，变量名 ypos/yneg/Y 一一对应）。三点 `u = [r, −r, r²]` 的作用就此揭晓：**用原始承诺在 ±r 的求值"外推"出所有折叠表在 r² 的求值**，再用一次无余式批量打开（第 3 节）把全部 3m 个求值对承诺的绑定一次配对核验（t=3 特化：1 次 MSM + 1 次配对，mod.rs:237-320）。
**随机性口径**：打开点 x 的每个坐标都是 Fiat–Shamir 挑战，落在 [0,2¹²⁸)（128-bit 熵，L01 §2）——绑定论证按 d/2¹²⁸ 计；推导本身与坐标取值范围无关。

**数值例子（N=4，手算）**：表 [3,1,2,0]，x=(5,4)：

```
折叠1（x₀=5）：p₁ = [3+5(1−3), 2+5(0−2)] = [−7, −8]
折叠2（x₁=4）：p₂ = [−7 + 4(−8−(−7))] = [−11]   →  f(5,4) = −11（与 L01/L02 一致 ✓）
验证链：取随机 r；V 用 p₀(±r) 外推 p₁(r²)，用 p₁(±r) 外推 p₂(r²)=y，与 P 送来的 v 全等才通过。
```

**完整流程串线（DeepProve 步骤 7）**：全部 claim → batched sumcheck 归单点 r\*（L02 §6）→ RLC 成一条 rlc = ΣcᵢPᵢ → HyperKZG::open(rlc, r\*)（折叠 → 批量 MSM 承诺折叠表 → 三点批量打开）。**几十上百条 claim 的兑现 = 1 条 sumcheck + 2 次 MSM + 1 次配对**（`poly_commit/prover.rs:97-138` → arkyper `mod.rs:329`）。

## 6. PCS 路线图与选型视角

| 路线 | 代表 | 多线性支持 | 验证方 | 本项目用法 |
| --- | --- | --- | --- | --- |
| 配对型 | KZG → Gemini → HyperKZG | Gemini 变换 | O(1) 配对 | **主路线**（SRS 需 trusted setup） |
| 哈希/FRI 型 | BaseFold、FRI 变体 | 折叠至一元 | 哈希重算，无可信 setup | 论文评测的另一变体；量子抗性 |
| 点积/内积型 | Hyrax 类 | 原生 | O(√N) | 未采用 |

**为什么 DeepProve 证据链选 HyperKZG**：验证方 O(1)、证明侧与 MSM 硬件同构（与 sumcheck 共享"表扫描"形态）。两处必读源码：`arkyper/mod.rs:329-436`（open/verify）、`poly_commit/prover.rs:97-255`（claim 批处理 + RLC）。
