# L05 · 查表论证：从对数导数到 LogUp-GKR

> 学习目标：理解非线性函数为什么必须查表；掌握对数导数恒等式与 LogUp；理解 LogUp-GKR 的分层电路；能推导 DeepProve 查表层（GELU/requant/softmax/RMSNorm）的完整证明链。
> 前置：L02、L03。预计 1 周。

---

## 1. 为什么非线性层是 zkML 的真正难点

线性层（矩阵乘）有多项式表达：Y = X·W 的每个输出是输入的次数-2 多项式，sumcheck 直接处理（L03）。但 ReLU/GELU/softmax/RMSNorm/量化右移是**分段或超越函数**——不存在低次多项式表达。两条出路：

1. **位分解 + 布尔电路**：把函数拆成位级门，规模爆炸（softmax 的 exp/除法尤其灾难）；
2. **查表论证（lookup argument）**：把函数离线量化成一张表 T，证明"输出 = 表在输入处的取值"。表大小只由**量化位宽**决定（如 GELU 输入 16 位 → 表 ~2¹⁶），与序列长度无关——这就是 DeepProve 论文选择的路：*"lookup arguments based on LogUp for proving non-linear layers"*。

## 2. 问题形式化

表 T = (T[0..N))，P 拥有查询序列 q = (q₀..q_{M−1}) 与对应的表输出 oᵢ = T[查(qᵢ)]。要证：**每个 qᵢ 都在表里，且 oᵢ 是它查出的值**。朴素做法（P 交出全部 q 与 o 让 V 重查）通信 = M×2，违背简明性目标。查表论证的目标：O(N + M) 级承诺 + O(log) 级交互完成上述证明。

## 3. 对数导数恒等式（LogUp 的数学核心）

把每个"查表事件"表示为**分数**：查询 i 贡献 `1/(β + qᵢ)`；表位置 j 贡献 `m_j/(β + T[j])`，m_j 叫**多重度**。则：

```
查询侧和 = Σᵢ 1/(β + qᵢ) = Σ_v c_v/(β + v)         （c_v = 查询值 v 的出现次数）
表侧和   = Σⱼ m_j/(β + T[j]) = Σ_v (t_v·m_v')/(β + v) （t_v = v 在表中的位置数）
恒等式成立 ⟺ t_v·m_v' = c_v 对每个值 v
```

于是令 `m_j = c_{T[j]} / t_{T[j]}`（每位置分摊），恒等式 ⟺ 查询集合与多重度完全一致。**除法在域中很贵**，LogUp 的技巧是：两边各用一个 GKR 电路计算"分数和"的 (分子, 分母) 对，验证方只需核对 `查询侧.num·表侧.den = 表侧.num·查询侧.den`（交叉相乘），全程无除法。β 的随机性保证 β + v ≠ 0（v 是已知小整数集合，随机 β 命中 −v 概率可忽略）。

**数值例子（必须手算）**：表 [10,20,10,30]（10 占两位置），查询 [20,10,10]：

```
c：10→2, 20→1；t：10→2, 20→1, 30→1
mult = [2/2, 1/1, 2/2, 0/1] = [1,1,1,0]     Σ mult = 3 = M ✓
两侧行动：Σ 1/(β+qᵢ) = 1/(β+20)+1/(β+10)+1/(β+10)
        表侧 = 1/(β+10)+1/(β+20)+1/(β+10)+0    相等 ✓
```

**DeepProve 的 witness 生成**：位切片列 MLE（如 GELU 高/低位）+ 值计数 + 上述 multiplicity 公式（lookup/context.rs:317-362；数值例子见 FPGA 指导 OP-12）。辅助表（zero_check / signed_zero_check / shift_check）用于消除补码位切片的符号歧义——这是量化系统特有的细节。

## 4. LogUp-GKR：把分数和变成可证电路

"分数和"本身要可证。观察：分数加法是**逐对运算**，天然构成一棵折叠树——每层把相邻分数对相加：

```
层 l+1 位置 y = ( 层 l 位置 2y 与 2y+1 的分数和 )：
  num' = n₀·d₁ + n₁·d₀      den' = d₀·d₁        （3 乘 1 加）
```

这正是 GKR 的分层形状：**每层一次 sumcheck**，证明"下一层 = 本层的分数折叠"。三种层的 sumcheck 表达式、claim 表达式、`α^k` 批量、终值合并——全部已推导并列在 FPGA 指导 OP-13 §13.1-13.2（必读，含可验算数值例子）。本讲补充三个理解要点：

1. **分母列合并发生在最底层**：多个表列（如 GELU 的高/低位列）在进电路前用 `β + Σ α_col^c·D_c[p]` 合并成一个分母——α_col 是列分离挑战，保证不同列线性组合后不碰撞；
2. **分子分母合并成单个域元素**：每层的 claim 是 `N + λ·D`（λ = lambda 挑战）——把两个多项式的 claim 压成一个，是"随机线性组合换通信"的又一例；
3. **落地闭环**：查询侧电路的终值 claim 落在 **witness 切片列**（步骤 7 打开 witness 承诺）；表侧落在 **multiplicity**（witness 承诺）与**承诺过的表输出列**（setup 承诺）；两侧最终由验证方交叉相乘核对（verifier.rs:587）。

## 5. 查表层在 DeepProve 中的完整证明链（以 GELU 为例，串起全课程）

```
推理期：input(i64) → 位切片 → 查表得输出（witness 列 MLE + counts）
证明期：
 ① witness 切片列/输出列/multiplicity → MLE → batch_commit（OP-10，承诺入 transcript）
 ② LogUp-GKR 查询侧：切.columns 为分母 → 逐层 sumcheck → 切片列 claim（在 logup 点）
 ③ linking sumcheck：把"表世界"（logup 点）焊到"张量世界"（输出 claim 点）——
    证 输出张量 = 查表结果按算子语义组合（GLU 拼半、softmax 减 shift、RMSNorm 乘归一化因子）
    一次 sumcheck（inputs/proving.rs:26），变体相关挑战数
 ④ 输入 claim 回传上游；witness claims 进步骤 7
```

**linking sumcheck 是查表层证明的关键粘合**：LogUp 只证"witness 里记录的查表输入/输出对与表一致"，③证"witness 里的输出 = 节点真正的输出张量"。两截合起来，"输出 claim ⇒ 输入 claim"的归约才闭合——这是读懂 `prove_lookup_op`（generic_prove.rs:66-343）的地图。

**各算子差异速查**（细节在 FPGA 指导 OP-12/13 与 `prove_chunk 详解` §5.5.4）：

| 算子 | 列数 | 额外表 | linking 内容 |
| --- | --- | --- | --- |
| GELU/SiLU | 2 切片列 + 输出列 | shift/zero/signed_zero | 输出 = 主表查值 |
| GLU | 2 切片 + 1 直通 | 同上 | 输出 = 查值 ⊙ 直通半 |
| requant | 1 列 + 输出 | — | 输出 = 表查值（乘子+右移已折进表） |
| softmax | 2 列 | — | 输出 = 查值 − shift（shift 也在 witness 中） |
| RMSNorm/LN | 多列 | 归一化 witness | 输出 = 输入 ⊙ 归一化因子 |
