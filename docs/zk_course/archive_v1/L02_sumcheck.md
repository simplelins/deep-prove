## 1. 问题设定

P 持有一张 2ⁿ 的表（即 MLE f），声称 `Σ_{x∈{0,1}ⁿ} f(x) = Y`。V 没时间读全表。目标：V 在 O(n) 通信 + O(n) 时间内核验。

这个抽象为什么够用？因为**一切计算都可写成超立方求和**：电路求值、矩阵乘（Σ_k A(r1,k)B(k,r2)）、查表分数和、多 claim 归并——后面每一讲都是把"我想证的东西"化成某个 g 的求和。sumcheck 是整个 PIOP 世界的发动机。

## 2. 协议（Lund–Fortnow–Karloff–Nisan, 1992）

n 轮。记 g 当前已被固定到 (r₁,…,r_{i−1})。

- **第 i 轮**：P 发送单变量多项式
  `g_i(X) = Σ_{x_{i+1}…x_n∈{0,1}} g(r₁,…,r_{i−1}, X, x_{i+1},…,x_n)`
  在 X = 0, 1, …, d+1 处的取值（d = g 对单变量的最高次数；发 d+1 个值即完整确定它）；
- **V 检查**：`g_{i−1}(r_{i−1}) = g_i(0) + g_i(1)`（首轮 `g_0(0)+g_0(1) = Y`，其中 g_0(X) ≡ Y 视为常数）；
- V 发随机挑战 r_i（Fiat–Shamir 下从 transcript 抽取）；双方把 f 沿变量 x_i 折叠：`f'(x_{i+1}…) = (1−r_i)f(0,…) + r_i f(1,…)`，表长减半。

n 轮后：V 手里剩 `f(r₁,…,rₙ) = y` 一条**求值主张**——交给多项式承诺方案（L04）核销。

**为什么轮多项式只发 d+1 个点就够**：g_i 是次数 ≤ d 的单变量多项式，d+1 个点唯一确定它；V 抽 r_i 后用插值求 g_i(r_i) 与上轮衔接。

**例 1（手算全流程）**：f 表 [3,1,2,0]（位 0↔第一坐标），证 Σ = 6，取 max_degree = 2（发 3 个点）：

```
轮1：g₁(X) = f(X,0)+f(X,1) = (3−2X)+(2−2X) = 5−4X → 发 [5, 1, −3]
     V：5+1 = 6 ✓；采 r₁ = 5；折叠 → [−7, −8]
轮2：g₂(X) = −7 − X → 发 [−7, −8, −9]
     V：−7+(−8) = −15 = g₁(5) ✓；采 r₂ = 4
终值：f(5,4) = −7 − 4 = −11     （与 L01 例 1 的直接求值一致 ✓）
```

## 3. 完备性与健全性（要求能白板复述）

**完备性**：诚实的 P 每轮发送的正是真多项式，检查恒过；终值即 f(r)。

**健全性**（轮轮归约）：若某轮 P 发送假多项式 g̃ᵢ ≠ gᵢ（但过检查），则 g̃ᵢ−gᵢ 是次数 ≤ d 的非零多项式，在 ≤ d 个点为零；随机 rᵢ 命中零点的概率 ≤ d/2¹²⁸（挑战 = 16 字节 XOF mod r，落在 [0,2¹²⁸)，见 L01 §2 的精确口径；源码注释 transcript/mod.rs:29-34）。若未命中，V 从此相信的是"假多项式在 rᵢ 的值"，P 必须为一条**与自己数据无关的多项式**继续维持一致性，最终在最后一条（与承诺绑定的）求值上必败。

- 轮轮健全性误差 ≤ d/2¹²⁸；n 轮合计 ≤ n·d/2¹²⁸；
- **工程读法（数字代进去）**：d = 6（引擎支持的单项式最大表数）、n = 20 → 合计 ≤ 120/2¹²⁸ ≈ 2⁻¹²¹·1.8，远超 128-bit 安全目标——因此这些协议不需要"重复挑战"，一次通过；
- 注意此口径是**挑战熵**决定的（2¹²⁸），不是域大小（2²⁵⁴）——两类数字在文献里都出现，必须区分：域大小决定"值域"，挑战熵决定"作弊者能重试的随机空间"。

**V 复杂度**：O(n·d) 域运算（插值/检查）+ 读 1 条最终求值（由 PCS 兑现）。
**P 复杂度（精确核算；设定：n=20 个变量、单项式 = 二表乘积 f₁·f₂、max_degree = 2）**。
记号：轮 i（0 起）时当前立方有 2^{20−i} 个点 = 2^{19−i} 个相邻对。

| 轮 i | 当前点数 | 对数 | 读取（建多项式 + 折叠，各扫一遍，两表合计 = 2×2×2^{20−i}） | 写出（折叠后，两表合计） | 乘法 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1,048,576 | 524,288 | 2²² = 4,194,304 | 2²⁰ = 1,048,576 | 3·2¹⁹ = 1,572,864 |
| i | 2^{20−i} | 2^{19−i} | 2^{22−i} | 2^{20−i} | 3·2^{19−i} |
| **合计** | — | — | 2²³−8 ≈ **8.39 M 项** | 2²¹−2 ≈ **2.10 M 项** | 3·(2²⁰−1) ≈ **3.15 M** |

- 合计的推导：读取 Σ_{i=0..19} 2^{22−i} = 2²³−8（建一遍 2^{21−i}、折一遍 2^{21−i}）；写出 Σ 2^{20−i} = 2²¹−2；乘法 Σ 3·2^{19−i} = 3·(2²⁰−1)；
- "每对 3 次乘"的出处：三个幂基系数 c₀ = a₁a₂（1 乘）、c₂ = b₁b₂（1 乘）、c₁ = (a₁+b₁)(a₂+b₂) − c₀ − c₂（1 乘）——宏用预计算差值还能再省，但数量级不变；
- **换算成带宽**：(8.39M 读 + 2.10M 写)×32B ≈ **336 MB 内存流量/实例**；HBM 3 TB/s 下纯访存下限 ≈ 0.11 ms——"sumcheck 是带宽型算子"的定量依据；
- **einsum 的现实规模（重要区分，防口径混淆）**：sumcheck 只在**收缩维**上跑——GPT-2 d_model=768 → n = 10 轮，代入上表（n=10）：读 2·(2¹²−4) ≈ 8,188 项 ≈ 262 KB、乘 3·(2¹¹−1) ≈ 6,141 次——**很小**；该算子的大头在建表段（fix_axes 读全张量 512×768 = 393,216 项 ≈ 12.6 MB，见 L06 §4）。所以准确表述是：**单实例 sumcheck 的规模 ∝ 收缩维；op.prove 的总成本 ∝ 全张量（建表段主导）**。

## 4. 多乘积与虚拟多项式

真实系统里 g 不是一个 f，而是**多张表的乘加组合**，如 `g(x) = f₁(x)·f₂(x) + 3·f₃(x)`。两种等价组织方式：

- **表级预组合**：先把 f₁·f₂ 算成一张新表再进 sumcheck——多一次 2ⁿ 乘 + 2ⁿ 存储，不划算；
- **虚拟多项式（本项目做法）**：sumcheck 引擎接受"多项式清单 + 单项式表达式"，每轮对每个单项式在 (偶, 奇) 邻接对上展开 ∏((1−X)aⱼ + X·bⱼ) 的幂基系数并累加。表不合并，只在每轮扫描时做逐点乘。

**例 2**：g = f·h，轮多项式系数 c₀ = Σa₁a₂, c₁ = Σ(a₁b₂+a₂b₁−2a₁a₂), c₂ = Σ(a₁a₂−a₁b₂−b₁a₂+b₁b₂)（a=偶项，b=奇项）。用 f=[3,1,2,0]、h=[1,1,1,1] 手算 c₀ = 6 验证（h≡1 ⇒ g=f ⇒ c₀ = Σf = 6 ✓）。

**代码落点**：`VirtualPolynomialsBuilder`（dp-crypto `sumcheck/virtual_polys.rs`）按指针注册表并分配 witness 编号；单项式展开由过程宏 `sumcheck_code_gen!` 生成（度 ≤ 6），用预计算差值减少乘法；度数不足 max_degree 时用**重心外推表**补点（`sumcheck/extrapolate.rs`，系数可预计算常量化）。

## 5. 表折叠的实现（fix_low）

每轮的折叠：`z'[i] = z[2i] + r·(z[2i+1] − z[2i])`——**相邻对**合并，位 0 是当前轮变量。CPU 两个实现（`fix_low_mut` / `bound_poly_var_bot_01_optimized`）语义一致，后者带 0/1 系数快路径。每轮"读全表 + 写半表"，n 轮总计 ≈ 2·2ⁿ 读。

**全仓库位序约定（再次强调）**：表索引位 b ↔ 点坐标 r[b]；`evals(r)` 的倍增法最终布局恰好如此。任何自定义实现若"想当然"改成跨半区折叠，与 CPU 的对拍会立即失败——这是新工程师最常见的翻车点。

## 6. 批处理：一次 sumcheck 服务多条主张

**Batched sumcheck**（论文 Appendix A.2 同款）：k 条不同表、不同点的求值主张 {(Pⱼ, rⱼ, yⱼ)}，抽随机系数 γⱼ，证

```
Σ_{x∈{0,1}ⁿ}  Σⱼ γⱼ·eq(rⱼ, x)·Pⱼ(x)  =  Σⱼ γⱼ·yⱼ
```

一次 sumcheck 后所有 Pⱼ 都在**同一个新点 r\*** 上被求值。健全性：任一 Pⱼ 作弊 ⇒ 左侧作为 γ 的多项式非零 ⇒ 随机 γ 命中零概率可忽略。

**同表多 claim（same_poly）**：k 条 claim 落在同一张表 f 上：`Σ_x f(x)·Σᵢ aᵢ·eq(rᵢ,x) = Σᵢ aᵢ·yᵢ`，k 条压成 1 条（代码 `iop/same_poly.rs`）。

**DeepProve 的用法**：一个 chunk 证明结束时的几十上百条 claim（权重/偏置/查表 witness/边界），全部由一次 batched sumcheck 归到单点 r\*，再经 RLC（随机线性组合 ΣcᵢPᵢ）塌成**一条多项式做一次 KZG 打开**——"只打开一次"由此而来。完整走线见 `prove_chunk 详解` §5.8。

## 7. 工程优化清单（第二遍学习的重点）

| 优化 | 原理 | 代码 |
| --- | --- | --- |
| 两阶段并行（distributed sumcheck） | 把超立方按线程切片，各线程独立跑 n 轮、每轮加法归约轮多项式；剩 log₂P 个线程选择变量在 Phase 2 补普通轮次 | dp-crypto `sumcheck/prover.rs:23-103/196-208`；论文 arXiv:2210.00264 |
| 差值预计算 | 单项式展开用 c = v[b+1]−v[b] 的二进制组合减少乘法 | `sumcheck_macro` 过程宏 |
| 外推表 | 度数 < max_degree 的单项式补点用预计算重心系数 | `sumcheck/extrapolate.rs` |
| 0/1 系数快路径 | 系数为 0/1 的项跳过乘法 | `dense.rs` 的 mul_01 系列 |
| mixed-size 表 | 参与表尺寸不一（EQ 表较小）时按 PolyMeta 跳过已到底的表 | prover.rs:640-642 |

**claimed sum 的两种约定（读验证代码前必知）**：引擎不吸收初始和——einsum 等由 V 从已持有 claim 重算；LogUp 由 P 先吸收实例输出。清单见 FPGA 指导附录 A。
