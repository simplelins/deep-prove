> 前置：S06（sumcheck）、S07/S08（承诺）、S09（查表）、S10（系统）。所有"点"的一句话定位都可在 L09 资料清单找到论文出处。

## 0. 地图怎么用（一个真实场景）

面试题："我们要证明一个 70B 模型的每次推理输出，验证方是手机。" 顶尖的答案是先问四个问题——**每个问题对应地图上一根轴**：

1. 计算长什么样、什么算子占大头？（→ 轴一 算术化）
2. 验证方要多便宜、要不要 trusted setup、抗量子吗？（→ 轴二 PCS）
3. 非线性占比多少、表多大？（→ 轴三 查表）
4. 要不要流式/递归/聚合？（→ 轴四 折叠）

学完本讲，这四个问题对你不再是名词，而是带定量判断的决策。

## 1. 轴一：算术化——把计算变成代数的四种方言

所有证明系统的第一步都是同一件事：把"计算做对了"翻译成"某些多项式/约束满足"。翻译方式决定一切 downstream 成本。

| 方言 | 表示 | 单位代价 | 强项 | 弱项 |
| --- | --- | --- | --- | --- |
| **R1CS** | 每门 `a·z ∘ b·z = c·z`（三个线性组合一个乘） | 1 乘/门，但门数多（位运算爆炸） | 通用、最成熟（Groth16/PLONK 生态）、**Nova 折叠天然适配**（M05） | 无查表原生支持；张量计算约束数爆炸 |
| **Plonkish** | 自定义门 + 查表门 + 拷贝约束 | 一个门可做任意 k 元一次组合 | 表达力最强（哈希一门化）、查表门原生 | 依赖多项式承诺的整表性质；设计门是手工活 |
| **AIR** | 执行 trace 的行间转移约束 `w(t+1) = F(w(t))` | 每行一次转移 | VM/递归类循环计算天然贴合（STARK 系） | 非循环、数据依赖分支的计算表达别扭 |
| **sumcheck-native（GKR 式）** | 计算 = 分层/求和的多项式恒等式，claim 链归约 | 每层一次 sumcheck，**无电路编码** | 张量线性代数（本系统 LLM 的形状）、无需承诺中间层 | 每算子要定制协议；分支/控制流弱 |

**DeepProve 的坐标**：sumcheck-native。**为什么对 LLM 是最优**：LLM 的 95% 计算是大张量矩阵乘——einsum sumcheck 直接证 `Σ_k A·B`，约束数量与张量元素同阶而非同阶×常数倍电路膨胀；非线性用查表旁路（轴三）。**若把 GPT-2 写成 R1CS**（zkML 的做法），一个 32-bit 乘法要拆几十个门——论文 §6 判 zkML "reduced efficiency and massive architecture requirements" 的机制就在这。

**专家级追问**（作业会考）：sumcheck-native 对**分支/循环**弱——如果负载是"证一个 RISC-V 程序跑了 N 步"呢？答案指向 AIR（zkVM 路线）——这就是轴一上"负载决定方言"的第一个实例。

## 2. 轴二：多项式承诺——三大族

承诺方案回答"表没被调包"（S07）。工程上只有三大族，各有死穴：

| 族 | 代表 | 证明大小 | 验证 | setup | 抗量子 | 一句话定位 |
| --- | --- | --- | --- | --- | --- | --- |
| **配对族** | KZG → Gemini → **HyperKZG** | O(1)，最小 | O(1) 次配对（贵但常数） | **要**（毒物仪式） | ✗ | 验证方最小的选择；聚合证明的主力 |
| **哈希族** | **FRI/STARK → BaseFold → WHIR → Binius** | 对数级，较大 | 哈希重算（快，可并行） | **透明** | ✓ | 无仪式 + 小域高速算术 + 硬件友好；新一代系统的主流 |
| **内积族** | Bulletproofs / IPA | 对数级 | O(n) 线性（或 log 变体牺牲证明） | 透明 | ✓ | 验证方算力极弱、证明可接受偏大时 |

多线性专属变体（DeepProve 需要 MLE 承诺）：**HyperKZG**（Gemini 变换把多线性点折叠成一元打开——S08 §4 你手验过）、**BaseFold**（FRI 折叠与多线性折叠合流——M02 手算）、**Zeromorph**（把 MLE 映成单变量 KZG）、**Binius**（二进制域塔上的哈希承诺）、**Dory**（内积型配对）。

**DeepProve 的坐标**：双 PCS 并存（论文 §5）——BaseFold（透明版）与 HyperKZG（小证明版），**PIOP 完全共享**。实验结论（表 1/2，你已经会读）：HyperKZG 证明小一半（11.4 vs 24.3 MB）但长序列证明更慢；BaseFold 透明但大。**这正是轴二的取舍在真实系统里的样子：没有全面赢家，只有工作负载匹配。**

## 3. 轴三：查表论证的谱系

| 方案 | 核心想法 | 代价特征 | 一句话 |
| --- | --- | --- | --- |
| **Plookup** (2020) | 查询与表**排序后逐位对齐**，商式证明相邻差为零 | 首个高效方案；排序代价大；单表 | 开山；被 LogUp 的多重度法取代为主流 |
| **Caulk / cq / Baloo** (2022-23) | 预先**承诺表本身**，查询=子向量证明 | 表承诺一次性、查询便宜 | 表巨大且固定时好；子表技术后来喂给了折叠 |
| **LogUp / LogUp-GKR** (2023) | 对数导数分数和 + 多重度 + GKR 折叠 | 无除法、多列天然、多实例批量 | **DeepProve 的选择**（S09 你手跑过） |
| **Lasso + Jolt** (2023-24) | "现成查表"：不承诺大表，用小承诺组合出任意大表 | 小域（如 Goldilocks）+ R1CSVM 上极快 | zkVM 时代的主角；与 LogUp 是互补不是替代 |

**选型直觉**：表是"每层动态小表"→ LogUp-GKR（DeepProve：GELU/requant 表随层变化）；表是"巨大静态统一表"（如 CPU 指令语义）→ Lasso 系；需要最小证明且表可排序 → Plookup 一脉。

## 4. 轴四：折叠与递归

- **递归（recursion）**：把"验证一个证明"做成另一个证明系统的算术化——昂贵（要内嵌验证器）；
- **折叠（folding）**：**Nova**（2021）的洞察——不证"验证器"，只把两次执行的 R1CS 项**累积**成一个 relaxed 实例，用一次小 MSM/哈希折叠；IVC（增量可验证计算）由此实用化（SuperNova 多电路、ProtoStar/HyperNova 扩展到高次/多折叠）；
- **与 sumcheck 的合流**：折叠思想已渗入 PCS（BaseFold 的折叠=FRI 的折叠=你 S08 手算的多线性折叠——**三个"折叠"是同一操作在不同身份下的样子**，这是 M02 的主题）；
- **DeepProve 的坐标**：没用折叠——chunk 切分+seed 链是**并行**方案而非累积方案；对"单次推理证明"这是对的；若要证"流式持续服务 10⁶ 次推理"，Nova 一族立刻变成候选（M05 的作业）。

## 5. DeepProve 在地图上的完整坐标（及边界）

```
算术化: sumcheck-native（einsum + 查表旁路）      ← 对 LLM 最优
PCS:    HyperKZG + BaseFold 双支持                ← 取舍留给了部署方
查表:   LogUp-GKR（多列、多实例批量）              ← 对"每层动态小表"最优
折叠:   无（chunk 并行 + seed 链）                ← 单次推理够用
域:     BN254 Fr（254-bit，配对友好）              ← 为 HyperKZG 服务
```

**它会在哪输**（地图边界的自觉）：
1. **要求免 setup** → BaseFold 版可用但证明大 2 倍；更彻底的答案是 M02 的 WHIR/Binius 一代；
2. **证 VM 程序**（循环/分支/内存）→ AIR + Lasso 系（zkVM 路线）的天下，sumcheck-native 的算子定制优势消失；
3. **验证方在浏览器/合约里且带宽金贵** → KZG 的 O(1) 证明无可替代（但 setup 意识形态冲突）；
4. **量子敌手** → 配对族出局；
5. **模型 >3B** → 内存天花板（论文自认，S11 §5）——需要空间高效 PCS 或折叠流式化。

## 6. 决策树（把地图变成肌肉记忆）

```
负载是什么？
├─ 大张量线性代数 + 少量非线性（LLM/推荐/风控模型）
│    → sumcheck-native + LogUp-GKR + 多线性 PCS（本系统）
├─ VM/指令序列（zkVM、證明程序执行）
│    → AIR/Plonkish + Lasso 系查表 + 小域哈希 PCS
├─ 聚合大量既有证明 / 持续流式计算
│    → 折叠（Nova 族）或递归聚合
└─ 验证方极弱（浏览器/链上）
     → 配对族 PCS 优先，接受 setup
约束覆盖检查：免 setup？抗量子？内存上限？→ 逐条过滤上面的选择
```
