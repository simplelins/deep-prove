# L09 · 进阶专题、研究前沿与资料清单

> 学习目标：建立"协议设计空间"的全景视角；知道本系统之外的路线上发生了什么；掌握读协议论文的方法。W12 + 毕业后持续使用。

## 1. 进阶专题（每个 1~2 小时的拓展阅读量）

### 1.1 折叠型方案与递归

sumcheck 的折叠思想被推广成一类"折叠型证明系统"：Nova/SuperNova（折叠式 IVC，多次证明累加成一次）、ProtoStar 等。与本系统的关系：HyperKZG 本身就是 Nova 生态的产物（仓库代码头注释：port 自 Nova provider）；若未来要做"证明的证明"（如把 chunk 证明递归聚合），折叠方案是首选方向。读法：先懂 Nova 的 relaxed R1CS 折叠直觉即可，不必先啃完整论文。

### 1.2 FRI 与 BaseFold（无 trusted setup 路线）

FRI 用哈希+ Merkle 树做多线性承诺（无配对、无 setup、抗量子），代价是证明更大、验证方做哈希重算。BaseFold 把 FRI 折叠与多线性 sumcheck 结合。DeepProve 论文 §5 的评测表同时含 KZG 与 BaseFold 变体——两条路线在本代码库中**PIOP 完全共享**（PCS 解耦）。思考题：若目标平台无 trusted setup 基础设施，迁移成本在哪？

### 1.3 分布式与流式证明

- **分布式**：ProverGraph 执行图（prover.rs:927 起）把 chunk 分派到多 worker；论文 §4.5 的多机方案；
- **流式**：本分支的核心——trace 逐步产生、chunk 证完即释放（`StreamingProver`）；seed 链替代公共挑战是协议级改动（对比 `Verifier::verify` vs `verify_streaming` 的 transcript 差异，这是你已精读的内容在真实演进中的活例子）。

### 1.4 硬件加速

 prove 管线的计算收敛为三类核：MSM（Pippenger/GPU）、sumcheck 轮引擎（带宽型）、表级数据算子（EQ/折叠/RLC）。FPGA 指导文档给出了完整算子规格与集成设计——把它当作"协议的硬件投影"来读，你会对协议的算子结构有更深一层理解。

### 1.5 安全视角

- transcript 等价性的工程攻击面（吸收顺序、序列化格式、XOF 语义）——本项目附录 A 的存在本身就是安全工程；
- trusted setup 仪式（powers-of-tau）；
- 量化边界与溢出：证明系统证明的是"i64 计算的域像一致"，i64 溢出本身不在证明范围内——位宽预算是模型/编译期的责任（conv 的 output_bitsize 即此逻辑）。

## 2. 研究开放问题（可作长期课题）

1. **查表层 overhead 的压缩**：GELU 级查表 witness 占 witness 承诺量的大头，能否用更少的列/更小的表？
2. **注意力二次项**：score 张量使数据量随 s² 涨——流式已解决内存，证明时间呢？（可结合 sparse attention 的证明友好结构。）
3. **PCS 混合**：witness 用 BaseFold（免 setup）、权重用 KZG（setup 一次）的混合承诺是否值得？
4. **验证方的进一步降载**：当前 V 需重放全部 sumcheck；对超深模型能否引入证明聚合？

## 3. 读协议论文的方法（导师方法论）

1. 先读 §问题定义与 Theorem 陈述（10 分钟），自问"这个定理正是我想要的吗"；
2. 跳到 Protocol 框图，手推一个 n=2 的例子（论文例题通常有）；
3. 回读健全性证明，找出"随机挑战在哪个等式上发力"；
4. 列出"工程落点清单"：承诺几次、sumcheck 几轮、挑战几个、验证方重算什么；
5. 用本仓库做对照：哪些已有、哪些是新原语。

## 4. 资料清单

**论文（按标题/出处检索）**
1. Lund–Fortnow–Karloff–Nisan, *Algebraic Methods for Interactive Proof Systems*（JACM 1992）—— sumcheck 起点；
2. Goldwasser–Kalai–Rothblum, *Delegating Computation: Interactive Proofs for Muggles*（STOC'08 / JACM'15）—— GKR；
