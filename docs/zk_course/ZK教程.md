# 第 0 章 钟表世界：为什么在 mod 13 里算

## 0.1 十三格的钟

想象一个表盘只有 **0 到 12** 共 13 格。指针在 11 再走 2 格不是 13，是 3——绕回去了。所有加法都在钟面上进行：

```
11 + 2 = 13 → 绕回 → 3           记作  11 + 2 ≡ 3 (mod 13)
9 + 7 = 16 → 16 − 13 → 5         记作  9 + 7 ≡ 5 (mod 13)
```

"≡ 5 (mod 13)"读作"除以 13 余 5"。减法同理往回绕：3 − 5 = −2，倒退 2 格 = 前进 11 格，所以 3 − 5 ≡ 11。乘法也是绕圈：4 × 5 = 20 → 20 − 13 = 7。

## 0.2 除法：每个非零数都有"倒数"

在钟表世界里"除以 7"= 找一个数乘 7 后绕回 1。挨个试（0 到 12 共 13 个候选）：

```
7×1=7,  7×2=14≡1   ← 就是它
```

所以 7 的倒数是 2。**每个非零数都有倒数**——这个性质叫"非零元素都有逆元"，这样的世界叫**域**（field）。

但不是随便几个格子都有这性质。看 6 格的钟（mod 6）里 2 的倒数：把 2 乘遍 0..5：

```
2×0=0, 2×1=2, 2×2=4, 2×3=6≡0, 2×4=8≡2, 2×5=10≡4
```

乘积只有 {0, 2, 4}，永远撞不到 1。病灶：2×3 = 6 ≡ 0——两个非零数乘出零（**零因子**）。

**为什么 13 格没有、6 格有？** 13 是素数。证明只需三行：取非零 a，看 a×0, a×1, …, a×12 这 13 个乘积。若有两个相同：a·i ≡ a·j，则 13 整除 a·(i−j)；13 是素数且不整除 a，只能整除 (i−j)，而 i、j 都在 0..12 内，只能 i = j。**13 个乘积两两不同，塞满整个钟，1 必然在其中。** 用 mod 6 复验：2×0 ≡ 2×3 需 6 | 2·3 = 6 ✓——6 是合数，可以"分期付款"地整除，素数挡住的正是这个。

## 0.3 负数与一致性

钟上没有负号。"−3"= 从 0 倒退 3 格 = 前进 10 格：−3 ≡ 10 (mod 13)。一致性验算：整数世界 (−3) + 10 = 7；钟表世界 10 + 10 = 20 ≡ 7 ✓。一般规则：**−x ≡ p − x**。

## 0.4 真实系统的大钟

教程用 13 格学规则，真实系统用 254 位的大钟。域阶取自本仓库依赖库源码（`arkworks-algebra/curves/bn254/src/fields/fr.rs:4`）：

```
r = 21888242871839275222246405745257275088548364400416034343698204186575808495617
```

- 254 位（2²⁵³ ≈ 1.447×10⁷⁶ < r ≈ 2.189×10⁷⁶ < 2²⁵⁴ ≈ 2.895×10⁷⁶）；
- 所有规则与 13 格钟完全相同，只是口诀表大到必须用计算机；
- **易混警告**：网上最常见的十六进制 `0x30644E72…F0000001` 是另一个域（曲线坐标用的 Fq，末尾 …08583），不是这个 r（末尾 …95617）。证明算术全部在 r 上。

**为什么非要绕圈**：①数字不膨胀（254 位封顶，计算机存得下）；②除法人人有份（0.2 节）；③它是均匀的骰子（第 5 章的随机挑战需要）。

## 0.5 整数搬进钟表：域化

程序里的数据是普通整数（含负数）。搬进钟表：正数原样进，负数加一圈：−3 ≡ 13 − 3 = 10 (mod 13)。搬完之后钟表里的每次加、乘与整数世界一致——**只要整数运算本身不溢出**。验算：整数 (−3)×7 = −21；钟表 10×7 = 70 ≡ 70 − 65 = 5；整数 −21 ≡ −21 + 26 = 5 ✓。

真实域里 i64 的 −3 映射为 r − 3（因为 |x| < 2⁶³ < r，一次条件加法完成）。代码位置：`to_field`（`zkml/src/quantization/`）。

## 0.6 一句话总结

> 证明系统的所有算术都发生在一个"绕圈的钟"上；钟的格子数必须是素数（人人可除）；本仓库的钟有 2²⁵⁴ 格；整数数据搬进钟的规则是"负数加一圈"。

# 第 1 章 一维：两个数的表

## 1.1 表与函数

取表 **[7, 4]**。把它看成一个只吃 0 和 1 的函数：

```
f(0) = 7        f(1) = 4
```

## 1.2 插值：两点定一条线

要在"格子之间"取值，最自然的做法是把两点连成直线。设 f(x) = a + b·x，代入两点：a = 7，a + b = 4 ⟹ b = −3：

```
f(x) = 7 − 3x
```

**两个数唯一确定这条线**——不同的表（如 [7, 5]）给出不同的线（7 − 2x）。这条"唯一性"是后面一切安全性的根。

## 1.3 在格子之间取值

求 f(1/2)。"1/2"是 2 的倒数：2 × 7 = 14 ≡ 1，所以 1/2 = **7**（在钟上，乘 7 就是"乘一半"）。代入：

```
f(7) = 7 − 21 = −14 ≡ 12 (mod 13)
```

**直觉复核**：12 真的在 7 和 4 的"正中间"吗？钟表算法：先加后乘一半 = (7 + 4) × 7 = 11 × 7 = 77 ≡ 77 − 65 = 12 ✓。几何直观：从 7 前进 5 格是 12，再前进 5 格回到 4——12 恰好在正中。**直觉活着，只是"一半"变成了"乘 7"。**

## 1.4 一句话总结

> 两个数唯一确定一条直线；直线在任意位置的值都可以算；"格子的值"只是这条线在 0 和 1 两处的取样。

# 第 2 章 二维：四个格子

## 2.1 表与格子坐标

表升级到 4 个数 **[3, 1, 2, 0]**，排成 2×2 方格（行变量 x、列变量 y 各取 0/1）：

| | y=0 | y=1 |
|---|---|---|
| **x=0** | 3 | 2 |
| **x=1** | 1 | 0 |

**索引约定（全课程统一）**：格子 (x, y) 对应表下标 **I = x + 2y**（第 0 位 = 第一个变量 = 最低二进制位）。四个格子：

| (x, y) | 二进制 I | 表值 |
|---|---|---|
| (0, 0) | 00 | 3 |
| (1, 0) | 01 | 1 |
| (0, 1) | 10 | 2 |
| (1, 1) | 11 | 0 |

> **方向约定没有对错，但必须声明**。有的材料用 I = 2x + y（第一个变量在高位）——只是表的排列顺序不同，协议数学不变。读任何代码/论文先确认它的约定。

## 2.2 选择器：拼出二维函数

定义两个单变量选择器：

```
ℓ₀(t) = 1 − t      （t = 0 时 = 1，t = 1 时 = 0 —— "选 0"）
ℓ₁(t) = t          （t = 1 时 = 1 —— "选 1"）
```

四个格子的值用四个"角落选择器乘积"拼装：

```
f(x, y) = 3·ℓ₀(x)ℓ₀(y) + 1·ℓ₁(x)ℓ₀(y) + 2·ℓ₀(x)ℓ₁(y) + 0·ℓ₁(x)ℓ₁(y)
```

**为什么它对**：代入任意格子，比如 (1, 0)：ℓ₁(1) = 1、ℓ₀(0) = 1，其余选择器全为 0，于是 f(1, 0) = 1 ✓——每个格子自动取到自己的值。

## 2.3 展开与验证

展开整理（自己算一遍）：

```
f(x, y) = 3(1−x)(1−y) + x(1−y) + 2(1−x)y
        = 3 − 3x − 3y + 3xy + x − xy + 2y − 2xy
        = 3 − 2x − y          （xy 项恰好消掉——这张表的运气，一般表会留下）
```

四角验证：f(0,0) = 3 ✓　f(1,0) = 1 ✓　f(0,1) = 2 ✓　f(1,1) = 0 ✓。

## 2.4 一般点求值

挑一个非格子点 (x, y) = (5, 4)：

```
f(5, 4) = 3 − 2×5 − 4 = −11 ≡ 2 (mod 13)
```

这个 2 由表唯一决定——改表中任何一个数它都会变。当场演示：把最后一个格子 0 改成 1，表变成 [3,1,2,1]，新增的差是 ℓ₁(5)ℓ₁(4) = 5×4 = 20 ≡ 7，指纹变成 2+7 = 9 ≠ 2。**一个格子的改动，指纹立刻不同**——第 5 章会用随机探针把"改表必露指纹"变成安全保证。

## 2.5 一句话总结

> 4 个数唯一确定一个"对每个变量都是一次"的二维函数；它既能在格子上取值（还原表），也能在格子之间的任意点取值（产生指纹）。

# 第 3 章 n 维：统一写法（MLE 登场）

## 3.1 从 2 到 n：索引就是二进制数

n 个变量的表有 2ⁿ 项，格子是 n 位布尔向量 t = (t₀, …, t_{n−1})，索引约定：

```
I = t₀ + 2·t₁ + 4·t₂ + … + 2^{n−1}·t_{n−1}        （第 0 位 = 第一个变量 = 最低位）
```

互转代码（Python，10 行）：

```python
def bits_to_index(bits):          # bits = [t0, t1, ...]，t0 是最低位
    return sum(b << k for k, b in enumerate(bits))

def index_to_bits(I, n):
    return [(I >> k) & 1 for k in range(n)]

bits_to_index([1, 0, 1])   # 1 + 4 = 5
index_to_bits(5, 3)        # [1, 0, 1]
```

## 3.2 统一公式

n 维插值公式（后面所有层的协议用的都是这一条形式）：

> **f(t) = Σ_{α∈{0,1}ⁿ} a[α] · ∏_{k} ℓ_{α_k}(t_k)**
>
> 其中 a[α] 是表在第 α 个格子的值，ℓ₀(t) = 1−t、ℓ₁(t) = t。

对每个变量单独看，f 都是一次的多项式——这就是**多线性**（Multilinear）的含义。

## 3.3 一个常见困惑：三种"x"要分清

初学时最容易把三种角色混成一个（这是真实踩过的坑，值得单开一节）：

| 角色 | 取值范围 | 含义 |
|---|---|---|
| **格子坐标** c = (c₀, c₁, …) | 只能 0/1 | 表的下标（二进制索引）——"数据住在哪" |
| **探针坐标** t = (t₀, t₁, …) | 任意域元素 | 插值函数的输入——"在哪里取值" |
| **选择器取值** ℓ_{c_k}(t_k) | 任意域元素 | 第 k 维的权重——"这个格子贡献多少" |

- 当探针 t 恰好取 0/1（t = 某个格子 c）：每个选择器取值是 0 或 1，**8 项（n=3 时）里 7 项死光，只剩 a[c] 一项**——效果是"定位取出"；
- 当探针是连续值（如 (5, 4)）：所有项都非零，**结果是全部格子值的加权混合**，权重就是选择器取值。

一句话：**顶点上是指示器，一般点是权重**。两种场合共用同一个公式，不需要两套理论。

## 3.4 放大到 100 万个数

规则一字不变：1,000,000 个数补零到 2²⁰，f 有 20 个变量；展开式有 2²⁰ 项——人算不动，计算机刚好。

**命名落点**：这个 f 叫**多线性扩展**（Multilinear Extension，MLE）。"扩展"= 从 2ⁿ 个格子扩展到整个域上的函数。名字出现在你已经会造它之后。

**代码对应**：`into_mle()`（`tensor/` 模块）把张量按行主序拍平成表——**下标的第 k 位 ↔ 第 k 个变量**。表 [3,1,2,0] 的下标 2 = 二进制 10 → (x=0, y=1) → 值 2 ✓ 与 2.1 的表一致。

## 3.5 一句话总结

> 任意长的表 = 一个 n 变量多线性函数；"位 = 变量"的索引约定统一一切；顶点上它是查表，一般点上它是插值。

**常见疑问**
- **问：约定反了（第一个变量在高位）会怎样？** 协议本身仍自洽（只要双方用同一约定），但与其他材料对拍时表顺序会镜像——对不上号先查约定。
- **问：为什么要补 2 的幂？** 索引需要每维恰好 2 个取值（0/1）；补零不影响"非零部分的插值语义"。

# 第 4 章 eq：探针的权重

## 4.1 先看一个事实：不展开也能求值

第 2 章求 f(5,4) 用的是"展开后代入"。另一种算法——**直接把探针代进选择器**：

```
ℓ₀(5) = 1−5 = −4 ≡ 9      ℓ₁(5) = 5
ℓ₀(4) = 1−4 = −3 ≡ 10     ℓ₁(4) = 4

f(5,4) = 3×(9×10) + 1×(5×10) + 2×(9×4) + 0×(5×4)
       = 3×12  + 1×11  + 2×10  + 0×7
       = 36 + 11 + 20 = 67 ≡ 2 (mod 13)     ✓ 与展开法完全一致
```

四个数 12, 11, 10, 7 就是四个格子在探针点 (5,4) 处的**权重**：每个格子的值乘上自己的权重，全加起来 = f 在探针点的值。

## 4.2 权重的正式名字：eq

把"每个变量取 1−探针值 或 探针值、按格子坐标连乘"的函数命名为 **eq**：

> **eq(r, c) = ∏_b ( r_b·c_b + (1−r_b)·(1−c_b) )**
>
> r = 探针点（任意域元素），c = 格子坐标（布尔 0/1），b 遍历每个维度。

**eq 与选择器是同一个东西**。单变量时按 c_b 分情况：

```
r_b·c_b + (1−r_b)(1−c_b) = 1−r_b = ℓ₀(r_b)     （c_b = 0）
                         = r_b   = ℓ₁(r_b)     （c_b = 1）
```

所以 **eq(r, c) = ∏_b ℓ_{c_b}(r_b)**——它就是"格子 c 的角落选择器在探针 r 处的取值"。不是新概念，是 S03 选择器的换装登场。

## 4.3 名字的来历与适用范围（一个真实的误解）

名字 eq 来自 **equality**：当探针 r 恰好是布尔点（每个 r_b ∈ {0,1}）时，对格子 c：

```
eq(r, c) = 1   若 c = r
eq(r, c) = 0   若 c ≠ r        （至少一个坐标错开 → 该维因子为 0）
```

它是一个用多项式写出的"等号"——只在布尔探针时成立。**常见误解（真实踩过的坑）**：把"eq(r, r) = 1"用到非布尔探针上。反例（mod 13，r = (5,4)）：

```
eq((5,4), (5,4)) = (5² + (−4)²)² = (25+16)² = 41² ≡ 2×2 = 4 ≠ 1
```

（每维因子 5·5 + (−4)(−4) = 41 ≡ 2。）**对任意探针恒真的是另一条**：

```
Σ_{c∈{0,1}ⁿ} eq(r, c) = 1        （对所有 r 成立）
```

证明一行：Σ_{x,y} ℓ₀(x)ℓ₀(y) + ℓ₁(x)ℓ₀(y) + … = (ℓ₀(5)+ℓ₁(5))(ℓ₀(4)+ℓ₁(4)) = (9+5)(10+4) = 14×14 ≡ 1×1 = 1 ✓——分组后每组内和为 1。数值：12+11+10+7 = 40 ≡ 1 ✓。

## 4.4 全课程最重要的一个等式（它把"无法核查"变成"可核查"）

把 4.1 的算式写成一般形式：

> **f(r) = Σ_{c∈{0,1}ⁿ} f(c) · eq(r, c)**
>
> 在任意点求值 = 对全表做一次加权求和。

**这个等式解决了什么实际问题（用数字说）**。

先看没有它时的困境。V 想核查"f(5,4) = 2"这条主张。V 手里没有表，他能做什么？只有两条路：重算（把 4 个格子全读一遍——表是 2²⁰ 个格子时等于重跑一遍推理），或者听 P 的（等于没核查）。**点值主张在 V 手里是死局。**

再看有它之后。恒等式把死局主张改写成：

```
f(5,4) = 3×12 + 1×11 + 2×10 + 0×7 = 2
```

注意两件事。第一：权重 [12, 11, 10, 7] **是 V 自己算的**——r = (5,4) 是 V 选的点，eq(r,c) 只依赖 r 和格子坐标，不依赖表。第二：改写之后，整条主张里只含两类东西——V 自己能算的权重，和 P 手里的表值。未知量从"整张表的语义"缩小成"4 个孤立的数"。

**缩小了为什么就好**：因为"核验一堆未知数的加权和"有一个专用协议——下一章的 sumcheck。它不读表、不要求 V 重算，用 n 轮对话把"Σ f(c)·w(c) = 2"核实到逃逸概率 ≤ d/2¹²⁸。表长 2²⁰ 时：20 轮 × 每轮 3 个数，对比读全表的 1,048,576 个数。

这就是本章存在的全部理由：**eq 把 V 无法核验的"点值"，换成 V 自己出权重、sumcheck 能核验的"加权和"**。第 9 章里 DeepProve 证矩阵乘、查表、softmax，做的都是同一件事——先把每种计算的主张改写成"某个求和"，再交给 sumcheck。

**代码对应**：eq 表的倍增法生成 = `evals()`（dp-crypto `poly/eq.rs`）；加权求和 = `evaluate_at_chi`（`dense.rs`）。

## 4.5 一句话总结

> eq(r, c) = 格子 c 的选择器在探针 r 处的取值；恒等式 f(r) = Σ f(c)·eq(r,c) 把"求值"变成"加权求和"——sumcheck 由此获得审问任何表的能力。

**常见疑问**
- **问：eq(r,r) = 1 到底哪里错了？** r 必须是布尔点才成立；对一般探针 eq(r,r) = ∏(r_b²+(1−r_b)²) ≠ 1。恒真的是"权重和为 1"（对布尔格子求和）。
- **问：为什么叫"探针"？** 因为它由验证方随机撒下（第 5 章）——像往表上随机扎一针，看读数对不对。

# 第 5 章 sumcheck：把总和压成一个点

## 5.1 主张

证明方 P 持有表 f = [3, 1, 2, 0]（第 2 章的表），声称：**Σ f = 6**（3+1+2+0）。验证方 V 不想读全表。目标：V 花小代价核实。

朴素的"抽查"抓不住补偿式作弊（把 1 改成 4、把 2 改成 −1，总和不变）。需要新机关。

## 5.2 协议：一次削掉一个变量

总和按变量拆开：Σ = Σ_x Σ_y f(x, y)。**证明方的第一条消息**：先把 y 加掉，只留 x 的函数。用 f(x,y) = 3−2x−y：

```
g₁(X) = f(X,0) + f(X,1) = (3−2X) + (2−2X) = 5 − 4X
```

一条直线由 2 个点确定，P 只需发 **[g₁(0), g₁(1)] = [5, 1]**。

**V 的检查**：直线两端之和 = 声称的总和：5 + 1 = **6** ✓。

**随机挑战**（V 掷，mod 13 掷出 r₁ = 7）：双方计算 g₁(7) = 5 − 28 = −23 ≡ **3**。V 用两点插值复核：g₁(7) = 5 + 7×(1−5) = −23 ≡ 3 ✓。

**主张变身**：原来的"总和 = 6"变成"**Σ_y f(7, y) = 3**"——x 被随机数钉死，表小了一半。

**第 2 轮**：双方把表沿 x=7 折叠（用 (1−7)·f(0,y) + 7·f(1,y)，mod 13 里 1−7 ≡ 7）：

```
折叠表：y=0: 7×3+7×1 = 28 ≡ 2      y=1: 7×2+7×0 = 14 ≡ 1     → [2, 1]
```

这张折叠表**恰好就是** f(7, y) 的两个值（直算：f(7,0) = −11 ≡ 2 ✓）——折叠是精确的变量固定，不是近似。P 发 [2, 1]；V 查 2+1 = 3 = g₁(7) ✓；掷 r₂ = 4；最终主张：

```
f(7, 4) = 2 − 4 = −2 ≡ 11 (mod 13)      直算：3−14−4 = −15 ≡ 11 ✓
```

**协议结束**。4 个数的表 → 凭据 = 4 个数 + 2 个挑战。2²⁰ 个数的表 → 20 轮、约 60 个数——**这就是"压缩"**。

## 5.3 健全性：作弊者的三条死路

作弊者声称总和 = 5（真值 6）：

- **第一轮撒谎**：发一条两端点和为 5 的线，如 [3, 2]（线 3−X）。真线是 5−4X。两条不同的线**至多在 1 个点相等**：3−X = 5−4X ⟹ X = 5。**V 掷的 r₁ 只要不等于 5，作弊立即进入死亡螺旋**——此后每个数字都被真表锁定，缺口一路传导到终点。逃逸概率 1/13；
- **后面某轮撒谎**：同样的分析逐轮独立成立；
- **全程诚实、只改终点**：终点主张会被承诺核销（第 6 章）。

**真实世界的数字**：挑战空间 2¹²⁸（16 字节哈希输出，见 5.5）；每轮逃生 ≤ d/2¹²⁸（d = 轮多项式次数）；20 轮合计 ≈ 2⁻¹²¹·1.9——**不是 100% 抓住，是漏网概率物理上无意义**。

## 5.4 多张表的乘积：协议一字不改

真实计算里 sumcheck 面对的是**表的乘积**（矩阵乘的断言 Σ_k A·B 就是它）。设 h = [1, 0, 0, 1]，乘积表 g = f⊙h = [3, 0, 0, 0]，总和 3。第一轮消息：

```
g₁(X) = g(X,0) + g(X,1) = (3−3X) + 0 = 3 − 3X
```

乘积的轮函数是 X 的 **2 次**多项式（两个一次相乘）→ 每轮发 **3 个点**（补第 3 点用插值：g₁(2) = 2·g₁(1) − g₁(0) = −3）。**d 张表的乘积 → 每轮 d+1 个点、每轮逃逸 ≤ d/2¹²⁸**——这就是"次数 d"进入健全性公式的路径。

## 5.5 工程与代码

- **挑战从哪来**：交互式协议里 V 现场掷；真实系统把 V 换成**哈希**——把对话逐字节喂进 Blake3，输出当挑战（Fiat–Shamir）。P 无法重掷（重试一次逃逸 2⁻¹²⁷，试到宇宙热寂也不够）。代码：`dp-crypto/arkyper/transcript/`；挑战 = 16 字节输出 mod r → 挑战空间 2¹²⁸；
- **多张表的表达式**：虚拟多项式机制把多张表按单项式组合、一次 sumcheck 处理（`sumcheck/virtual_polys.rs`）；
- **两阶段并行**：表按线程切片并行折叠（论文 arXiv:2210.00264）；
- **成本账单**（n=20、二表乘积）：全程读 ≈ 8.39M 项（268 MB）、乘 ≈ 3.15M 次——sumcheck 是**带宽型**算子。

**代码对应**：轮循环 = `IOPProverState::prove`（dp-crypto `sumcheck/prover.rs:116`）；折叠 = `fix_var`（`dense.rs:454`，相邻对 z[2i]+r(z[2i+1]−z[2i])——与 §5.2 手算一字不差）；挑战 = `append_and_sample(b"Internal round")`。

## 5.6 一句话总结

> sumcheck 把"2ⁿ 个数的总和 = Y"压成 n 轮对话 + 一条最终主张 f(r) = y；每轮逃逸 ≤ d/2¹²⁸；它只会证"求和"，而第 4 章的恒等式保证一切"求值"都能翻译成求和——两者合体，任何表都能被审问。

**常见疑问**
- **问：最终主张 f(7,4) = 11 悬在空中，谁担保？** sumcheck 只负责归约；"表没被调包"由第 6 章的承诺兜底。两者合起来才完整。
- **问：claimed sum（6）为什么不进哈希？** 验证方从它已持有的主张重算；少数协议由证明方先吸收进哈希——读代码时两种都要认。

# 第 6 章 承诺：给表发指纹

## 6.1 悬空的主张

第 5 章结束时，验证方手里有一条主张"f(7,4) = 11"。但他没有表——凭什么信？如果表没有被事先锁死，作弊方可以现在编一张恰好满足等式的表。**承诺方案**在证明开始前给每张表生成一个短的"指纹"C，此后一切主张都用 C 核销。三个要求照旧：C 短；诚实者必过；**改表必被抓**（绑定性）。

## 6.2 仪式与力量表

思路：找一位**仪式主持人**，心里藏一个秘密数 τ（仪式后销毁），公开一张"力量表"——τ 的各次幂。在 mod 13 里取 τ = 6，前 4 项（表长 4）：

```
w = [τ⁰, τ¹, τ², τ³] = [1, 6, 36≡10, 60≡8]
```

证明方承诺：**C = 表逐项乘力量表再全加**：

```
C = 3×1 + 1×6 + 2×10 + 0×8 = 29 ≡ 3 (mod 13)
```

关键性质：证明方**只需要力量表，不需要 τ**——他做的只是加权求和。

## 6.3 亲手破解这个玩具

找"改表不改指纹"的组合。试系数 δ = (6, 12, 0, 0)（即 6 和 −1）：

```
Σ δᵢ·wᵢ = 6×1 + (−1)×6 = 0
```

假表 f′ = f + δ = [9, 0, 2, 0] 的指纹：C′ = 9 + 0 + 20 + 0 = 29 ≡ **3 = C** ✓。**不同的表、同一枚指纹——玩具被破解。** 看 δ 的真面目：δ 对应多项式 δ(X) = 6 − X = −(X − 6) = −(X − τ)——它在 τ 处恰好为零。**知道 τ 的人造这种多项式只要一秒。**

不知道 τ 的攻击者呢？他从公开的 w 里找"加权为零的非零组合"——纯数字世界里太容易了：**任何**两个位置都行（δ = (w₁, −w₀) 永远成立）。暗门遍地。

## 6.4 修复：搬进"能加不能开锁"的世界

把力量表从裸数字换成**椭圆曲线上的点**：仪式公开 Wᵢ = τⁱ·G（G 是公开生成点）。点可以相加、可以乘系数（证明方算 C 需要的全部能力），但从 W 反推 τ 等价于**离散对数问题**——几十年攻不动的硬骨头。第 6.3 节的攻击在点世界里变成"找 δ₀·W₀ + δ₁·W₁ = 0"，展开需要 δ₀ + δ₁τ = 0——**必须知道 τ**。暗门焊死。

这套构造叫 **KZG 多项式承诺**。承诺 C = Σ fᵢ·Wᵢ 这次"点加权求和"，工程里就是一次 **MSM**（多标量乘）——真实系统里是 2²⁰ 个标量乘 2²⁰ 个曲线点再求和，用 Pippenger 分桶算法加速约 10 倍。

## 6.5 打开：用商多项式证明一个点的取值

V 持有 C，P 声称"f 在点 7 取值为 y"。数学事实：

```
u(X) − y 能被 (X − 7) 整除  ⟺  u(7) = y
```

所以诚实的 P 拿出**商多项式** q(X) = (u(X) − y)/(X − 7)，对 q 再做一次承诺发给 V。V 通过**配对**（pairing，一种让"点世界的乘法关系可以被检验"的运算）核验这条恒等式在承诺世界成立。**y 是假的 ⟹ (u−y) 在 7 处不为零 ⟹ 不存在能通过核验的 q**——绑定性在此兑现。

**这一整段可以亲手算**（多项式代数不需要魔法世界）。先把表换成"承诺身份"：表 [3,1,2,0] 读作一元多项式 **u(X) = 3 + X + 2X²** 的系数（"位 = 次数"，与第 3 章"位 = 变量"是同一张表的两种读法）。

```
u(7) = 3 + 7 + 2×49 = 108 ≡ 4 (mod 13)
```

综合除法（系数 [2, 1, 12]，逐位乘 7 再加）：

```
2  →  1+14 ≡ 2  →  12+14 ≡ 0 ✓ 余数 0（确认 u(7)=4）
商 q(X) = 2X + 2
```

**乘回验证**：(2X+2)(X−7) = 2X² − 12X − 14 ≡ 2X² + X + 12 = u(X) − 4 ✓。

**负例（亲手做）**：若谎称 u(7) = 5，则 u−5 = 2X²+X+11，综合除法：2 → 1+14≡2 → 11+14≡25≡**12 ≠ 0**——余数非零，不存在合法的 q。**谎报一个点值 = 无商可除 = 必败。**

**边界注记（绑定 ≠ 隐藏）**：这个承诺做到了绑定（表改不了），**不做隐藏**（不掩盖表的信息）。DeepProve 证明的是完整性（结果没被篡改），不需要隐藏；隐私负载必须给承诺加盲化因子并重新审视零知识性——选型时最易混的两个性质。

## 6.6 一句话总结

> KZG 承诺 = "把表投进一个只有加法的魔法世界"（MSM）；打开 = "除以 (X−点) 的商多项式再做一次承诺"；谎报点值 = 商不存在 = 配对核验必败。

# 第 7 章 收口：几十条主张到一次打开

## 7.1 问题

真实证明的结尾有**几十条**主张：线性层吐出"权重在某点等于某值"，查表层吐出"witness 切片在某点等于某值"……每条指向不同的表、不同的点。逐条打开承诺？每次打开都是配对级代价——几十次就把验证方拖垮。本章把一整把主张收口成**一次**打开，三步全部可手算。

演员表：

```
表 f = [3,1,2,0]（已承诺），主张 ①：f(7,4) = 11        （第 5 章的终点）
表 g = [3,0,0,0]（已承诺），主张 ②：g(5,4) = 10        （验算：3(1−5)(1−4) = 3×12 ≡ 10 ✓）
```

## 7.2 第一步：把不同点的主张搬到同一个点（batched sumcheck）

抽随机系数 γ₁ = 3、γ₂ = 5，构造新主张：

```
Σ_{x,y∈{0,1}} [ γ₁·eq((7,4),x,y)·f(x,y) + γ₂·eq((5,4),x,y)·g(x,y) ] = 3×11 + 5×10 = 83 ≡ 5
```

右边 V 自己能算（主张值是公开的）。左边为什么成立：逐项用第 4 章恒等式（f(7,4) = Σ f·eq((7,4),·) = 11 ✓）。**两把主张被随机捆成一个 sumcheck**。

四张参与表（eq 表用第 4 章的倍增法生成）：

```
eq((7,4),·) = [5, 5, 2, 2]      eq((5,4),·) = [12, 11, 10, 7]
```

**第 1 轮**（削变量 x）。轮函数 R(X) = Σ_y [γ₁·eq₁(X,y)f(X,y) + γ₂·eq₂(X,y)g(X,y)]。乘积项使它是 **X 的二次多项式**——发 3 个点：

```
R(0) = 3×(5×3 + 2×2) + 5×(12×3 + 10×0) = 3×19 + 5×36 = 57+180 ≡ 5+11 = 16 ≡ 3
R(1) = 3×(5×1 + 2×0) + 5×(11×0 + 7×0) = 15 ≡ 2
X²系数 = γ₂×[(11−12)(0−3) + (7−10)(0−0)] = 5×3 = 15 ≡ 2
     （乘积的 X² 系数 = ΔA×ΔB；γ₁ 部分的 Δeq₁ = 0，无二次项）
R(X) = 3 + 10X + 2X²        消息 [R(0), R(1), R(2)] = [3, 2, 5]
```

V 查：R(0)+R(1) = 3+2 = 5 ✓。掷 **r₁ = 6**：R(6) = 3+60+72 = 135 ≡ **5**（三点插值复核：3×10 + 2×2 + 5×2 = 44 ≡ 5 ✓）。

**四张表各自折叠**（权重 (1−6, 6) ≡ (8, 6)）：

```
f′ = [8×3+6×1, 8×2+6×0] = [30,16] ≡ [4, 3]     eq₁′ = [70,28] ≡ [5, 2]
g′ = [8×3+6×0, 0]       ≡ [11, 0]               eq₂′ = [162,122] ≡ [6, 5]
```

**第 2 轮**（削变量 y）：R₂(0) = 3×5×4 + 5×6×11 = 60+330 = 390 ≡ **0**；R₂(1) = 3×2×3 + 0 = 18 ≡ **5**；Y² 系数 = 3×(2−5)(3−4) + 5×(5−6)(0−11) = 9+3 = 12。消息 **[R₂(0), R₂(1), R₂(2)] = [0, 5, 8]**（R₂(Y) = 6Y+12Y²，R₂(2) = 12+48 = 60 ≡ 8）。V 查：0+5 = 5 = R(6) ✓。掷 **r₂ = 2**。

**收口**。V 自己算 eq 在最终点 (6,2) 的值（他知道两个主张点，eq 是他的多项式，**eq 表不需要承诺**）：

```
eq((7,4),(6,2)) = eq(7,6)×eq(4,2) = [42+(−6)(−5)]×[8+(−3)(−1)] = 72×11 ≡ 7×11 = 77 ≡ 12
eq((5,4),(6,2)) = [50≡11]×11 = 121 ≡ 4
闭合恒等式：3×12×f(6,2) + 5×4×g(6,2) = 8        （sumcheck 终值）
```

**两张表在同一个新点 (6,2) 的取值成了两条新主张**：f(6,2) = 2（3−12−2 = −11 ≡ 2 ✓）、g(6,2) = 2（3(−5)(−1) = 15 ≡ 2 ✓）。代回：3×12×2 + 5×4×2 = 72+40 = 112 ≡ **8** ✓ 闭合。

**一个必须写对的细节**：sumcheck 过程中**不要**把 eq⊙f 预先合成一张表去折叠——合成表折叠得到"乘积表的 MLE 在终点的值"，与"多项式乘积在终点的值"在格子之外**不相等**（前者给 5，正确协议给 8）。各表独立折叠、轮函数每轮由各表现算——这也是实现里"虚拟多项式"把表分开登记的原因。

## 7.3 第二步：两张表塌成一张（RLC）

两条主张已同点不同表。再抽一对系数（3 和 5）：

```
h = 3×f + 5×g = [24, 3, 6, 0] ≡ [11, 3, 6, 0]        h(6,2) = 3×2 + 5×2 = 16 ≡ 3
```

验算（角展开）：11×96 + 3×72 + 6×16 = 1368 ≡ 1368 − 1365 = **3** ✓。**"两把主张"变"一把"**：随机性保证伪造一张 h′ 同时骗过两条主张的概率是 2⁻¹²⁷ 级。

## 7.4 第三步：一次打开（折叠 + 三点）

对"h 在 (6,2) = 3"做 KZG 打开，用的是**多维点**——桥是折叠。把表 [3,1,2,0] 读作一元系数（S07 的第二种身份），逐变量折叠系数表：

```
折 x=7：p₁[j] = 7×(p[2j+1]−p[2j]) + p[2j] → p₁ = [7(1−3)+3, 7(0−2)+2] = [−11,−12] ≡ [2, 1]
折 y=4：p₂ = 4×(p₁[1]−p₁[0]) + p₁[0] = 4×(1−2)+2 = −2 ≡ 11
```

**两个惊喜**：①p₁ = [2,1] 正是第 5 章折叠出的表 f(7,·)——承诺世界的折叠与 sumcheck 世界的"固定变量"是**同一个操作**；②p₂ = 11 **正好是第 5 章的最终主张 f(7,4) = 11**。sumcheck 的终点、折叠链的终点、承诺打开的点，三点合一。

**三点技巧**。逐个打开折叠表要多次配对核验；HyperKZG 的办法：V 掷随机 r，只要求 P 提供每张折叠表在 **r、−r、r²** 三个点的取值，用一条恒等式串联：

```
2r·p₁(r²) = r×(1−x)×(p₀(r)+p₀(−r)) + x×(p₀(r)−p₀(−r))       （x = 7 是第一个折叠变量）
```

**亲手验证**（r = 5）：u(5) = 3+5+2×25 = 58 ≡ 6；u(−5) = u(8) = 3+8+128 = 139 ≡ 9；p₁(25≡12) = 2+12 = 14 ≡ 1。

```
左边 = 2×5×1 = 10
右边 = 5×(−6)×(6+9) + 7×(6−9) = −450 − 21 = −471 ≡ −471 + 481 = 10 ✓      （13×37 = 481）
```

**为什么成立**：把 u 拆成偶部 A(X²) + 奇部 X·B(X²)，u(±r) 给出 A(r²) 和 B(r²)，而 p₁(X) = (1−x)A(X) + x·B(X)——代进去整理即得。**威力**：V 从"已承诺的 u 在 ±r 的取值"外推出"未单独承诺的 p₁ 在 r² 的取值"，所有折叠表只需**一次**批量打开（3 个点、1 次 MSM + 1 次配对）。20 个变量的表：19 张折叠表逐个打开要 19 次核验，三点法只要 1 次。

## 7.5 一句话总结

> 几十条主张 → batched sumcheck（同一点上的每表取值）→ RLC（一条多项式）→ HyperKZG（折叠 + 三点 + 一次批量打开）。**几十次核验变 1 次**——这就是真实系统"只打开一次"的全部数学。

**代码对应**：batched sumcheck = `claims_batching_sumcheck`（`poly_commit/prover.rs:140`，表达式构造 `poly_commit/mod.rs:83`）；RLC = `linear_combination`（prover.rs:115）；三点打开 = `HyperKZG::open`（dp-crypto `arkyper/mod.rs:329`：折叠 ：343、三点 ：373、批量打开 ：186）。

# 第 8 章 查表：非线性函数的证明

## 8.1 非线性为什么难

GELU、softmax、量化右移画出来是曲线。第 3 章的事实：多项式若在足够多点与曲线重合就必须是曲线——**曲线不是多项式**，sumcheck 熄火。出路：**离线把函数值打成一张表 T**，运行时"计算 = 查表"，证明任务变成：

> 证明每次查询的值 qᵢ 都在表里，且报告的输出 oᵢ 确实是 T 给的。

表的规模只由**输入位宽**决定（16 位 → 6.5 万格），与数据量无关。

## 8.2 分数与多重度

选随机数 β，把每次查询表示成分数 **1/(β+qᵢ)**，把表的每个位置 j 表示成 **mⱼ/(β+T[j])**（mⱼ = 多重度）。恒等式：

```
查询侧 Σᵢ 1/(β+qᵢ)  =  表侧 Σⱼ mⱼ/(β+T[j])     ⟺     查询全部合法
```

按值归组：查询侧 = Σ_值 cᵥ/(β+v)（cᵥ = 被查次数）；表侧 = Σ_值 tᵥ·mᵥ′/(β+v)（tᵥ = 占位次数）。相等 ⟺ **tᵥ·mᵥ′ = cᵥ 对每个值成立**。所以多重度按位置记：**mⱼ = 被查次数(T[j]) ÷ 表内出现次数(T[j])**。β 随机的作用：让"表外的值"对应一个**对不上账**的分数（而不是直接溢出）。

## 8.3 亲手跑一遍（mod 13）

表 **T = [1, 2, 3, 4]**，查询 **q = [2, 1, 1]**，β = 4（检查 β+v = 5,6,7,8 全非零 ✓）。需要的逆元：1/5 = 8、1/6 = 11、1/7 = 2、1/8 = 5。

```
多重度：c(1)=2, c(2)=1, c(3)=0, c(4)=0；每个值占 1 格 → m = [2, 1, 0, 0]     （Σm = 3 = 查询数 ✓）
查询侧 = 1/(4+2) + 1/(4+1) + 1/(4+1) = 11 + 8 + 8 = 27 ≡ 1 (mod 13)
表侧   = 2/(4+1) + 1/(4+2) + 0 + 0   = 16 + 11     = 27 ≡ 1 ✓    两侧相等 → 查询合法
```

**作弊测试**：查询里混入表外值 5（q = [2,1,5]）：查询侧多出 1/(4+5) = 1/9 = 3，总和 4 ≠ 1 → 抓住 ✓。

## 8.4 分数折叠：全程不做除法

逐个求逆元太贵（6.5 万格的表）。LogUp 的妙笔：每个分数只记 (分子, 分母) 一对，相加用交叉相乘：

```
n₁/d₁ + n₂/d₂ = (n₁d₂ + n₂d₁) / (d₁d₂)          （3 乘 1 加，无逆元）
```

把所有分数**两两折叠**成一棵树，每侧最后剩一个 (分子, 分母)。V 核对两侧的方式也是交叉相乘：

```
查询侧分数：(1,6), (1,5), (1,5)
  (1,6)+(1,5) = (1×5+1×6, 6×5) = (11, 30≡4)
  (11,4)+(1,5) = (11×5+1×4, 4×5) = (59≡7, 20≡7)        → 查询侧终值 (7, 7)

表侧分数：(2,5), (1,6), (0,7), (0,8)
  (2,5)+(1,6) = (2×6+1×5, 30) = (17≡4, 4)
  (17,4)+(0,7) = (17×7, 28) = (119≡2, 28≡2)
  (2,2)+(0,8) = (16, 16)                                → 表侧终值 (3, 3)

交叉核对：查询侧.分子 × 表侧.分母 = 7×3 = 21 ≡ 8
          表侧.分子 × 查询侧.分母 = 3×7 = 21 ≡ 8     ✓ 相等 → 查表合法
```

**无一次除法、无一次求逆**。这棵折叠树逐层是一次数值计算——分层 + 每层一次 sumcheck + 挑战点逐层传递（第 5 章的形状）。层数 = log₂(表长)（4 格 2 层；6.5 万格 16 层——只随**位宽**涨，不随数据量涨）。

## 8.5 还缺一块：把"表世界"焊回"张量世界"

LogUp 只证了"witness 里记录的查询/输出对与表一致"。最后一环是 **linking sumcheck**：再证"节点真正的输出张量 = 查表结果按算子语义的组合"。各算子的组合：GELU/requant = 输出即查值（requant 的乘子与右移已折进表）；GLU = 查表半 × 直通半；softmax = 查值 − shift；RMSNorm = 输入 ⊙ 归一化因子。至此查表层闭环：witness → 承诺（第 6 章）→ LogUp 双侧折叠（本讲）→ linking → 输入侧新主张回传上游 → 收口（第 7 章）。

## 8.6 一句话总结

> 查表 = "多重度记账 + 分数恒等式"：查询侧 Σ 1/(β+qᵢ) 与表侧 Σ mⱼ/(β+T[j]) 相等 ⟺ 查询合法；分数折叠树（GKR 形状）让它免排序、免除法、可批量、可分层证明。

**代码对应**：witness 与多重度 = `generate_lookup_witness_for_chunk`（`lookup/context.rs:233`，mⱼ 公式 :317 起）；双侧折叠 = `new_batch_multiple_sizes_prove`（`lookup/logup_gkr/prover.rs:91`）；linking = `prove_linking_sumcheck`（`lookup/operation/inputs/proving.rs:26`）；交叉核对 = `verifier.rs:587`。

# 第 9 章 组装：DeepProve 完整系统

## 9.1 六步端到端

```
① 前向推理（i64 定点算术）：逐层计算，每个节点的输入/输出/辅助量记入 Trace
② 域化与承诺：i64 → Fr（负数加一圈）→ 补 2 的幂 → MLE → 批量 MSM 承诺
   （权重/查表的承诺 setup 期已做好——第 6 章仪式做一次全体共用）
③ 播种：transcript 掷随机点，对最终输出与跨块边界张量立主张
   （LLM 只证最后一行 logits——前 s−1 行不进证明，O(s²)→O(s)）
④ 逆拓扑逐算子归约：稠密层用 einsum sumcheck（第 5 章乘积的放大版）；
   非线性层用查表 + linking（第 8 章）；每个算子吃"输出主张"吐"输入主张"
⑤ 收口：全部主张 → batched sumcheck → RLC → 一次打开（第 7 章）
⑥ 验证：重放每轮检查 + 配对核验；多 chunk 用 seed 链与边界承诺相等焊死
```

**逐算子归约为什么成立**：这就是 **GKR 范式**（Goldwasser–Kalai–Rothblum, 2008）——"用一次 sumcheck 把『下一层输出在某随机点的取值』归约成『上一层输入在某随机点的取值』"，从输出层走到输入层。DeepProve 论文原话：*"Similar to the fabled GKR protocol, we compose these operator protocols in a layer-by-layer fashion."* 三个工程改造：层内协议按算子定制（比通用 GKR 快）、claim 单链（无双主张合并）、静态部分（权重）前置承诺。

## 9.2 三个"妙手"（论文 §4 的核心技巧）

- **embedding 不承诺表**：验证方手里就有索引向量 x，把查表重写成稀疏矩阵乘 Y = H_T·X（每行恰一个 ±1）→ 证明方连 H_T 都不用承诺，V 本地 O(s·log n) 算。原则：**验证方能本地算的东西，证明方不承诺**；
- **RMSNorm 送答案**：证明方自己带倒数 d[i] = Quant(1/√(ΣX²/d))（把开方/逆元从电路里挪出来），证 Y = X·d，再加一条完备性检查 Σⱼ Y[i,j]² = 1 封堵假 d；
- **requant 全查表**：乘子右移折进表（Case 1）、超范围时连"取倒数"都查表（Case 2）+ InRange/Comb 钳位表——**没有除法、没有开方、没有比较门**。它也是系统里最贵的算子（占总证明时间 27%）。

# 第 10 章 深入方向（每节都能独立展开）

## 10.1 哈希承诺与 FRI（摆脱 trusted setup）

第 6 章的仪式有个信任假设（至少一人诚实）。哈希路线完全免仪式：把"次数低"翻译成"靠近一个纠错码"，用 Merkle 树承诺 + 随机抽查验证。核心机制是**折叠**：随机 α 把次数减半，抽查保证折叠前后的"离码距离"不消失（proximity gap）。**一个值得亲手做的实验**：在 mod 13 里对表 [5,4,0,12]（f(X) = 3X+2 在四阶子群 {1,5,8,12} 上的取值）跑一轮折叠——诚实者得到常数表 [8,8]；而一张偏离 1/4 的作弊表 [5,4,0,0] 竟然能造出全程自洽的链——**这暴露了玩具域的健全性局限**（真 FRI 需要"域大小 ≫ 次数 × 安全参数"，定理叫 proximity gap）。BaseFold = FRI 折叠与第 7 章多线性折叠的合流；WHIR/Binius/Circle STARK 是这一代的延续。

## 10.2 数域的选择（为什么新一代系统都在"换钟"）

254-bit 域的一次乘法 = 十几次 64-bit 乘加；64-bit 的 Goldilocks 域 ≈ 原生整数乘（快一个量级）；31-bit 的 M31 可以 SIMD 并行。但小域**装不下**大值（mod 13 里 5×5 = 25 ≡ 12，整数语义丢失——域阶必须大于计算值域上界），解法是**扩展域**：在 F₁₃ 上取 α² = 2（X²−2 不可约，因为 2⁶ ≡ −1 是非平方），造出 169 格的大钟 F₁₆₉ = {a+bα}；Binius 的"二进制塔" F₂⊂F₄⊂F₁₆⊂… 是同一构造。DeepProve 留在 BN254 的原因：HyperKZG 绑配对曲线；而 sumcheck/查表协议**与域无关**——换域只换底盘，PIOP 原封不动。

## 10.3 折叠与递归（证明"跑了 N 步"）

把 N 步计算逐块证明、验证方读 N 个证明——违背简明性。Nova 的洞察：**不证旧证明，把旧实例折叠进新实例**。relaxed R1CS 关系 Az∘Bz = u·Cz + E（E 是"误差记账"），折叠 z* = z₁ + r·z₂、E* = E₁ + r·T（T 是交叉项）——mod 13 里一步手算即可验证对任意 r 精确成立。N 步之后：一个累积器 + 一个证明，验证方工作恒定。DeepProve 的 chunk 切分是**并行**方案，折叠是**串行累积**方案——单次推理用前者，持续服务用后者。

## 10.4 安全：攻击者视角

把所有逃逸概率记成一页**预算表**（sumcheck 每轮 ≤ d/2¹²⁸ × 实例数 + PCS + FS 熵 → DeepProve ≈ 2⁻¹¹¹）。攻击者的三板斧对应三种绑定缺失：绑挑战（Fiat–Shamir transcript 缺陷，Frozen Heart 系列 2022）、绑陈述（证明重放，Binance "Alice" 2022）、绑承诺（碰撞，Zcash BCTV14）。**可亲手复现的攻击**：如果 transcript 忘了吸收承诺 C，作弊方在 S06 玩具里事后提交 g = [10,0,0,0]（它在 (7,4) 的值 = 5×10 = 50 ≡ 11 = 声称值），重放第 5 章的证明**全部通过**——修复 = 承诺先于挑战入 transcript。审计 = 逐一检查这三种绑定。

## 10.5 一句话总结

> 哈希承诺（免仪式）、小域（快算术）、折叠（摊销）、攻击者视角（预算表+三种绑定）——四条路都从本教程的同一套基本概念出发。走到这里，你已经具备读任何一篇 2024-2026 年 ZK 论文的语言。
