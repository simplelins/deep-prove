## 2. 三个候选题目（也可自提，需导师认可负载的代表性）

**T-A · 70B 模型推理的手机验证**：模型在服务器、验证方是手机。关键张力：内存（M03 的域选择 × 内存预算表）、证明大小（手机带宽）、验证时间（<1 s？）——HyperKZG vs WHIR 的选型是本题的核心考点；70B 的 witness 量级要用 M00 的公式外推并给出内存方案（空间高效 PCS？折叠流式？）。

**T-B · EVM 区块执行证明**：负载 = 交易签名验证 + 状态读写 + EVM 字节码。关键张力：VM 负载指向 AIR + Lasso 系查表（M01/M04），与 LLM 路线完全不同；签名验证（ECDSA/Ed25519）是查表/MSM 的复合考点；聚合多区块时的折叠（M05）。

**T-C · 隐私交易（隐藏金额的转账正确性）**：与 DeepProve 相反的威胁模型——**要零知识**（隐藏输入）+ 范围证明（金额非负 → 查表/位分解）。考点：ZK 变体的代价、 Pedersen 承诺与 MLE 承诺的混合、以及"证明范围之外"的语义（M06 §4）。

## 3. 三位模拟评审（导师扮演，各具人格）

| 人格 | 攻击风格 | 典型问题 |
| --- | --- | --- |
| **理论洁癖** | 只攻健全性与假设 | "这个恒等式在扩展域上还成立吗？""你的 RBR 预算把 grinding 算进去了吗？""第 7 页的 eq 表维度和第 9 页对不上。" |
| **工程现实** | 只攻成本与落地 | "这个数字的硬件依据？""瓶颈预判的依据是测量还是想象？""这套协议需要新算子——团队三个月能写完吗？" |
| **安全偏执** | 只攻边界与信任 | "statement binding 在哪？""随机种子谁提供？""这个'证明范围之外'的假设被谁兜底？" |

**应对纪律**：每条质疑要么当场推导回答，要么登记为文档修订——**含糊其辞 = 该关不通过**（M00 出师标准的评审关）。

## 4. 答辩流程

1. 提前 48 小时交文档（评审预读）；
2. 30 分钟：20 分钟主讲（负载 → 选型 → 协议 → 预算 → 实验计划）+ 10 分钟三评审轮番质询；
3. 评分：选型定量性 / 协议完整性 / 预算表可信度 / 质询应对 四项各 25%；
4. 未过：按评审意见修订，两周后重答辩——**这是 M00 承诺的"真实战场"形态**。

## 5. 出师之后

- 与导师转为同行关系：互评设计、共读 ePrint、合写短文；
