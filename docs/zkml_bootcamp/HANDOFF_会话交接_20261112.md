## 三、关键新知识（架构）

- **logUp GKR claim 布局**：lookup 侧输出 claims = `[v0..v_{dk-1}, index]`；table 侧 = `[multiplicity, v0..v_{dk-1}, index]`（`circuit.rs::combine_final_evals`）。claim 点 = 完整 log2(len) 坐标（`num_vars+1` 约定，prover.rs `sumcheck_point[point_length-num_vars..]`）。
- **claims batching**（poly_commit/prover.rs）：eq 修正的多点批处理（每 claim 的 point 生成 eq poly）——任意点的多 claims 可安全注册进同一承诺。
- **同一张量被承诺两次的结构**：producer 的输出列 ∈ producer witness；consumer 的输入列 ∈ consumer witness——两者靠 consumer 的 linking sumcheck（从 claim 出发）交叉校验。**任何"绕过 linking 的算子"（如 gather）必须把 consumer claims 注册进自己的承诺**，否则是 soundness 缺口。
- **lookUp claim 直评陷阱**：lookup 路径 claim 带非零 padding 修正（`compute_lookup_padding_evaluation`）+ 列组织（chunked to_evals）——`to_field_mle` 直评在通过运行也 DIFF。
- **witness 列布局因模型而异**：gpt2 12-bit requant = 24 列位切片（numel/24），gemma = 2 个全尺寸列——不要跨模型假设布局。
- token 数 = prompt 分词结果（`--sequence` 是上限）：gemma long_prompt → 1023，gpt2 → 127。
- verify_chunk 顺序 = proof.chunk_proofs 存储序 = prove 完成序 = Chunk(15)→Chunk(0)（chunk id 与图序相反）。
