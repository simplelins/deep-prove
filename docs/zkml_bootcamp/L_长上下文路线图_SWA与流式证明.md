## 1 目标场景与结论速览

目标（项目需求）：CPU 推理 + CPU trace 生成，FPGA/ASIC 承担核心证明；Llama-13B/32k（理想）或 Llama-7B/16k（底线）。

| 结论 | 内容 |
| --- | --- |
| C1 | **全注意力下 16k/32k 不可行**：Llama-2-7b 满注意力 T_pad s=4k 已 486GB、s=8k 1.8TB（F 文档 §7.4，`‡` 越界档）；且 Llama-2 架构 `max_position_embeddings=4096`，16k/32k 原生不支持——需要选原生长上下文模型或 RoPE scaling |
| C2 | **滑窗注意力（SWA）+ 流式证明是唯一可行组合**：SWA(w=512) 把 score 张量从 `[Hq,s,s]` 降到 `[Hq,s,w]`（s² → s·w，/32），流式证明把"全量 trace 驻留"降为"窗口内段驻留"——两者缺一不可 |
| C3 | SWA + 流式下 Llama-7B/16k 全模型 trace ≈ **1.2–1.4 TB Fr**，但**峰值内存仍由段预算决定**（512MB 级）——流式使 TB 级总量的证明在普通服务器内存上可行 |
| C4 | 段数量级 ~1500（512MB 段预算）→ **表证明全局化（J 文档 L-4）从"优化项"升级为"长上下文必需项"** |
| C5 | CPU 标定外推：Llama-7B/16k SWA 证明 ≈ **5–7 小时/次（单机 CPU）**；FPGA（D 文档 M0-M2 阶段化）目标 10–100× → 数分钟–数十分钟。标定含不确定性（§5） |
| C6 | 前置工作：**阶段 5 水平切分流式**（单 score 张量 8.6GB Fr 远超任何段预算，必须行切）、RoPE/长上下文模型选型 |

## 2 体积推导（SWA 下）

公式（沿用 F 文档口径，i64 域，pad≈pow2）：

```text
SWA score 张量:  [Hq, s, w]  = Hq·s·w 元素     （全注意力 [Hq,s,s] = Hq·s²）
每层 s² 家族:    3 × score（score/softmax/mask）
线性张量:        [·, s] 级（QKV/fc/proj），每层 ~6–9 张
num_vars(score) = ⌈log₂(Hq·s·w)⌉
```

**Llama-7B（L=32, Hq=32, d=4096）@ s=16k, w=512**：

| 张量 | 形状 | 元素 | i64 | Fr(pad, ×4B) |
| --- | --- | ---: | ---: | ---: |
| 单个 score | [32, 16384, 512] = 2²⁸ | 268M | 2.1 GB | 8.6 GB |
| 每层 s² 家族 | 3 × score | 805M | 6.4 GB | 25.8 GB |
| 单个线性张量 | [16384, 4096] ≈ 2²⁶ | 67M | 0.54 GB | 2.1 GB |
| 每层线性家族 | ~8 × | 537M | 4.3 GB | 17.2 GB |
| **每层合计** | | | **10.7 GB** | **43 GB** |
| **全模型（×32 层）** | | | **342 GB** | **1.37 TB** |

对照：满注意力 s=16k 的 score = [32,16384,16384] = 2³³ 元素/张（34GB i64 / 137GB Fr），全模型 ≈ 21TB——不可行。**SWA 的 /32 压缩 + 流式的"段后即释放"共同把问题拉回可行域**：峰值内存 ≈ 段预算（512MB–数GB）+ 单段证明工作集 + 推理活跃集，与总 trace 体量解耦。

s=32k（Llama-13B, Hq=40, d=5120, w=512）：score [40, 32768, 512] ≈ 2²⁹·1.25 → 单张 4.3GB i64 / 17GB Fr，全模型 Fr ≈ 3TB 量级——流式同样适用，sumcheck 成本见 §5。

## 3 段切分与段数估算

以段预算 B=512MB（Fr 口径）计 Llama-7B/16k SWA：

- 单个 score 张量 8.6GB Fr → **水平切分（阶段 5）按 query 行切成 ~17 段**（[32, 2¹⁰, 512]/段量级）；
- 全模型 s² 家族 96 张 × 17 段 ≈ **1600 段**，加线性/查表段 → **~2000 段量级**；
- 每段固定开销：transcript 初始化、边界承诺 ×2、opening、**表证明 ×1**（J 文档 L-4）；
- → **表证明全局化是长上下文必需项**：每段省一次表证明，2000 段 × 表证明成本（GPT-2 实测单段表证明 ~0.7s 量级起，随表尺寸涨）= 小时级浪费。
- 段预算也可放大（B=4GB → ~250 段），用内存换段数——预算参数本就是流式的旋钮，需实测扫描找峰值点。

## 4 证明成本标定（CPU 基准外推）

标定点（GPT-2 s=1024 实测，F 文档 §7.2）：C 段（节点 sumcheck，占 84.6%）681.5s；
C 段总求值量 ≈ 平均轮数 20.8 × T_pad 元素数 2.01G ≈ **41.7G 次域求值** → 标定吞吐 ≈ **61M 求值/s**（128 核机单标定点，含实际实现的多线程与访存）。

Llama-7B/16k SWA 外推：

| 实例族 | 数量 | 单实例求值量（轮数×张量） | 小计 |
| --- | ---: | ---: | ---: |
| score（3/层 × 32 层） | 96 | 28 × 268M ≈ 7.5G | 720G |
| 线性（~8/层 × 32 层） | 256 | 22 × 67M ≈ 1.5G | 377G |
| 查表/其余 | — | 未精确标定（F 文档诚实边界） | +30–100% |
| **合计** | | | **≈ 1.4–2.0T 求值** |

→ **5.5–9 小时（61M/s 标定吞吐）**；D 文档 C 段占比 84.6% → 端到端 ≈ **6.5–10.5 小时**。
不确定性：①吞吐标定只有 GPT-2 单点（张量形状/访存模式不同）；②查表族未标定；③轮数均值近似。
**FPGA 对照**（D 文档附录 C：M0 MSM 引擎 → M1 +sumcheck 引擎 → M2 数据通路/双缓冲）：sumcheck 引擎 10–100× → **6–60 分钟**量级；MSM 侧总量 = ceil(T_pad/2²⁰)（F 文档 §4.3.3），SWA 16k 下 T_pad≈1.37TB → ~1.8M chunks（2²⁰ 元素/chunk）——**MSM 总量与满注意力同量级按 T_pad 线性走**，是 FPGA 吞吐规划的主输入。

## 5 模型选型注意

| 模型 | 原生上下文 | 注意力 | 备注 |
| --- | --- | --- | --- |
| Llama-2-7B/13B | 4096 | 全注意力 | 16k/32k 需 RoPE scaling（改变位置编码 → RoPE PIOP 的形状与上下文绑定，需协议侧复核） |
| Llama-3.2-1B | 128k | 全注意力（部分层 SWA?） | 原生支持；Hq=32 |
| Gemma-3-1B | 32k | **sliding_window=512（局部注意力）** | **唯一原生 SWA 且 32k 的候选**；Hq=4，trace 最小（F 文档已给全注意力曲线） |
| Qwen2-1.5B | 32k | 全注意力（GQA） | 需自行加 SWA |

**建议**：首个长上下文验证目标选 **Gemma-3-1B@32k（原生 SWA）**，把"SWA + 流式 + 水平切分"全链路在最小模型上打通，再迁 Llama 系（避免同时引入 RoPE scaling 变量）。
