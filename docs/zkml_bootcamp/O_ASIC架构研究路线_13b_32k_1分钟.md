## 0 目标的可行性数学（先算清，再定义 ASIC）

### 0.1 Llama-13B @ 32k 的工作负载（满注意力，当前协议）

| 量 | 数值 | 说明 |
| --- | ---: | --- |
| 前向计算 | **0.86 P MAC**（int 域） | 线性层 0.42P + 注意力 0.44P——32k 下两者相当 |
| T_pad（域化 trace） | **≈58 TB Fr ≈ 1.8T 元素** | **注意力图占 95%**（40 层×40 头×32k² = 1.72T 元素） |
| 证明数据搬运（5 遍） | ≈288 TB | fieldize/承诺 1 遍 + sumcheck 折叠 ~2 遍 + LogUp/链接 ~1.5 遍 + opening |
| 域乘总量 | ≈13.5 T 次 | BN254 Montgomery |

### 0.2 一分钟预算下的三条铁律

1. **带宽**：288TB / 60s → **聚合 ≥5TB/s** ——单卡 HBM（~1.5-2TB/s 有效）不够，≥3-4 卡起步；
2. **算力**：13.5T 次域乘 → 5G/s=45min ✗、50G/s=4.5min ✗、**300G/s=42s ✓** ——需 10-20 张
   旗舰级域乘引擎（或多 die ASIC）——面积/功耗被 95% 的注意力图绑架；
3. **主机内存**：58TB Fr 不可能落地 host RAM——**零物化流式（A3）从优化项升级为协议前置**。

### 0.3 结论：先改约，再画版图

**W1（注意力图不物化）必须先于 ASIC 规格定义**。改约后：

| 量 | 满注意力 | W1 改约后 | 降幅 |
| --- | ---: | ---: | ---: |
| T_pad | 58 TB | **≈2.6 TB** | **22×** |
| 搬运（5 遍） | 288 TB | ≈13 TB | 单卡 HBM 7-9s 即可搬完 |
| 域乘 | 13.5 T | **≈0.6 T** | 单卡 64 lane @ 300MHz ≈ 20-30s ✓ |
| 聚合带宽需求 | ≥5 TB/s | ≈0.22 TB/s | **单卡达标** |

**一分钟目标在 W1 之后与"一颗多 die ASIC 或 2-4 张 FPGA 级联"的系统规模闭合**；
在 W1 之前需要 10-20 倍的硬件规模且仍受 host RAM 不可行约束。这是本研究的第一个
（也是成本最大的）架构决策点。

## 2 维度 0：协议改约（决定 ASIC 规格的三项工作）

### W1 · 注意力图不物化（22× 的来源，最高优先级）

现状：softmax 以 [Hq,s,s] 表查证 → 注意力图占 T_pad 95%。两条候选路线：

- **R1 · Flash 式在线 softmax + sumcheck 折叠**：QK^T 按 row 块流式计算，在线
  softmax 产出 O(s) 的 (row_max, row_sum, 归一化分母) 向量；exp 用低阶多项式
  逼近在 sumcheck 内证明（放弃查表）或对小域查表。**协议研究重点**：exp 的
  sumcheck-friendly 表示与精度论证（量化域下 exp 近似误差必须与 requant 语义一致）。
- **R2 · SWA 化**：若产品可接受滑动窗口注意力（L 文档路线），s² 项直接坍缩为
  s×w。**工程量小但改变模型语义**——需与模型所有者确认可否微调适配。

R1 是纯证明侧改约（模型不变），是首选研究方向；R2 是保底。

### W2 · 零物化管线（A3 升级为前置）

i64 激活流 → Fr 域化 → MLE → MSM/折叠 全部按流消费，任何 >单段容量的张量不落地
（现状 13b@512 靠 A4 已解 context；32k 的 58TB/2.6TB 都是主机 RAM 装不下的）。
与 W1 天然契合：注意力按 row 块流出即证即弃。

### W3 · 查表族增量化（C1/A1 的协议化）

实测查表族占证明算力 82%（N 文档 §1.3）。32k 时 requant 实例 ~1100 个、每实例
linking sumcheck 轮数 = log₂(段元素)。改约：**稀疏 multiplicity + 跨实例批处理**
（A1），把查表族成本从 O(实例×表长) 降到 O(命中数)。

**维度 0 的产出 = 新的成本模型（T_pad/搬运/域乘三元组）→ 这是 ASIC 规格书的输入。**

## 3 维度 1：工作负载画像与 ASIC 规格定义

从 M 文档的实测锚点（每 512MB 段：查表族 82%、einsum 8%、MSM 6%；段体积与
证明时间线性）外推到 W1 改约后的 32k 负载，产出规格三表：

| 规格 | 依据 | 目标值（初版，W1 后） |
| --- | --- | ---: |
| 域乘吞吐 | 0.6T 域乘 / 60s ÷ (安全余量 2) | **≥20-40 G mul/s**（64-128 lane @ 300-400MHz） |
| 有效带宽 | 13TB / 60s × 遍数余量 | **≥0.5-1 TB/s**（HBM2e/3e 单栈 ×4） |
| 片上 SRAM | sumcheck 折叠双缓冲 2^22 窗口 | 256-512 MB |
| MAC 阵列（前向） | 0.86P int8 MAC / 60s 内并行于证明 | ≥300 TOPS int8 |
| MSM | 0.6T 标量位贡献（fixed-base） | 与域乘阵列共享周期或独立 1-2G scalar/s |
| Blake3 | 每轮挑战 <1μs 延迟 | 常驻独立核（FPGA 文档 §2.3 已定） |

每项都要有"从实测锚点外推"的推导链，禁止拍数字。

## 4 维度 2：ASIC 微架构

1. **BN254 域乘阵列**：Montgomery 4-limb 深流水（17 级 × 64-bit 乘法器树），
   每 lane 目标 300-400MHz 下 0.6-1 mul/cycle 有效吞吐；lane 间独立指令流
   （sumcheck 折叠是数据并行、无依赖）。7nm 下单 lane 面积 ~0.03-0.06mm² 量级
   ——128 lane 是完全可流片的规模（这是选择 BN254 + HyperKZG 而非大域的架构红利）。
2. **sumcheck/LogUp 折叠引擎**（OP-07/13，实测 82% 的主算子）：fix_low 相邻对
   合并 = 纯流式；片上双缓冲 2^22 窗口，HBM 直接供数；轮间挑战由 Blake3 核
   <1μs 回注（流水线不停摆）。
3. **MSM 单元（OP-10/11）**：fixed-base（g1_powers 常驻 HBM）+ 桶累加；
   与域乘阵列的张力（面积分配）由维度 1 的占比表决定——实测 MSM 仅 6%，
   **初始配比 1:15（MSM:域乘）**，不要被"MSM 是 ZK 硬件标配"的直觉绑架。
4. **前向 MAC 阵列**：int8/bf16 混合（量化推理 + requant），与证明引擎共享
   HBM 控制器——**trace 生成与证明同卡流水**是本架构最大的系统红利（见维度 3）。
5. **互联**：单 die（chiplet 可选）；多卡场景 C2C/PCIe Gen5×16 ≈ 64GB/s 只传
   控制面与挑战流，数据面各自本地（见维度 4 的多卡划分）。

## 5 维度 3：CPU+ASIC 系统划分与接口契约

| 阶段 | CPU | ASIC |
| --- | --- | --- |
| 图调度/chunk 划分/claim 簿记 | ✓（控制流，K 文档安全边界） | — |
| 前向推理 | 协调 | **int8 MAC 阵列**（trace 直出证明管线） |
| fieldize/折叠/LogUp | — | **域乘阵列 + 折叠引擎** |
| MSM/打开 | — | MSM 单元 |
| transcript | 主导（吸收顺序的协议安全性） | Blake3 常驻、挑战回注 <1μs |
| 合并/verify | ✓（秒级，无需加速） | — |

接口沿用 FPGA 文档 §2.2 的三流（table/point/claim stream），新增：
**W1 的 row 块流**（注意力 online softmax 的控制边带：row_max/row_sum 向量）。
PCIe 带宽核算：13TB 数据全部片内/HBM 就地消化后，主机↔卡只传 claim/挑战/
commitment（<100MB/段）——**PCIe 不是瓶颈的前提是零物化做到底**。

## 6 维度 4：协议-硬件协同设计

1. **chunk 大小 = 片上容量的函数**：2^22 窗口（128MB Fr × 双缓冲）已是默认
   chunk 阈值——把 `ZKML_CHUNK_THRESHOLD_LOG` 的选择从"软件调参"变成"规格参数"。
2. **多卡近线性**：段间无协议依赖（方案 A 种子链只约束吸收顺序），N 卡按段
   划分加速比 ≈ N；13b@32k 的 48 段天然映射 2-4 卡。
3. **流水形态**：前向(MAC) → 证明(折叠/MSM) 在同一卡上时间复用还是空间分区，
   由两者的带宽画像差决定（MAC 是计算型、折叠是带宽型——**空间分区 + HBM 时分**）。
4. **安全边界不动**：方案 A transcript、BN254/HyperKZG 实例、verify 逐段重放
   ——硬件任何改动不得触碰 K 文档的审计面（transcript 等价性 L4 验收）。

## 7 维度 5：验证方法学与性能模型

1. **功能**：沿用 FPGA 文档 L1-L4（算子→实例→chunk→端到端），L4 = CPU
   `verify_streaming` 通过为最终验收；新增 formal：Montgomery 流水线、折叠
   边界（奇偶长度）、桶溢出。
2. **性能**：先建 **cycle-accurate 模拟器**（输入 = 实测段画像 CSV），锚定
   三个实测点（g270m s=512 算子占比、llama7b s=512/1024 段时间、13b s=512
   分解）后再 tape-out 决策。**禁止无模拟器的流片**。
3. **风险对冲**：W1 若走 R1（exp 多项化），先在 CPU 协议层实现并过 verify
   （纯软件可验证），再定 ASIC 的 exp 单元形态。

## 9 风险与对冲

| 风险 | 对冲 |
| --- | --- |
| W1-R1 的 exp 多项化精度不过 | R2 SWA 保底；或 exp 查表保留但只对 row-max 归一化后的有界域查（表长受限） |
| 带宽实测低于模型 | 折叠窗口降到 2^20（段数↑但每段带宽 ↓）——段间并行补吞吐 |
| 多卡 transcript 排序 | 段级吸收已顺序化（方案 A），卡间只并行证明、串行吸收——协议不变 |
| host RAM（32k 的 2.6TB T_pad） | W2 零物化 + 段级 pin/dry（现架构已支持） |

## 附 · 达标算术汇总（W1 后，单/双卡系统）

```
前向:    0.86P int8 MAC ÷ 300 TOPS        ≈ 3s
证明:    域乘 0.61T ÷ 30G/s               ≈ 20s
         搬运 13TB ÷ 1TB/s(单卡HBM有效)   ≈ 13s（与域乘重叠）
         MSM/LogUp/固定开销               ≈ 5-10s
verify:  CPU 秒级（27MB 级 proof）
─────────────────────────────────────────
合计                                      ≈ 45-55s ✓ （含推理）
```

对照：CPU 现状 13b@512 证明 2.9h；协议改约 ×22（W1）×硬件 ×50-100（域乘阵列）
——两个杠杆各贡献一个数量级，缺一不可。
