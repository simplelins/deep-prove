# C · DeepProve ZK → FPGA 实现规格（目标板：AMD Alveo U250 / U280-HBM）

> **定位**：落地文件——**怎么算**。把 HyperKZG 的承诺/打开/sumcheck 落到**可实现的算子、面积-时序推导、权衡、M1 规格**，全部"可点算账"（给推导式 + 参数，不绕弯）。
> **读者**：FPGA 架构师、RTL/验证工程师——照此能写代码、能估面积、能定时序。
> **依赖**：硬事实见 [A](A_关键事实与源码核定.md)，选型理由见 [B](B_工作负载与瓶颈判定.md)。本文绑 Alveo U250/U280-HBM。

**关于本文的"算"与"估"**：所有资源/时序/带宽都以**推导式**给出（并行度、URAM 字节/PE、带宽 BW 均可代入），一步都依赖源码核定的常量（域宽 32B、chunk=2²⁰、打开≈4×承诺）。板卡资源总表在[附录](#b-板卡资源总表datasheet)，凡引用的 {LUT,DSP,URAM,HBM} **精确数取自 AMD 产品 datasheet/PSR**，本文不臆造；本文给出的据此换算的量才标"估算"。

## 1. 目标与边界

- **目标**：在单板 FPGA 上做 **HyperKZG<Bn254> 承诺 + 打开**（同一 MSM 引擎）为主、**sumcheck/EQ 引擎**为辅的板级加速器；推理留 GPU、验证留 CPU。
- **域**：`ark_bn254::Fr`，元素 32 B。**所有面积/存储以 32B 计，勿按 8B 毛估。**
- **I/O 粒度**：chunk = 2²⁰ = 1M 元素 = **32 MB(BN254)/chunk**；架构最小处理/搬运单位。
- **边界（明确不做）**：不做完整推理、不做验证者、不做分布式协调（若做 worker 单板协调由 CPU 负责）。

### 1.1 板卡资源基线（U250/U280，精确数取自[附录 B](#b-板卡资源总表datasheet)）

| 资源 | U250 | U280-HBM | 本文取 |
|------|:---:|:---:|:---:|
| 系统逻辑单元 | ~1.3M LUT / ~2.6M FF | 同左 | 参数 `LUT_TOT, FF_TOT` |
| DSP48E2 | ~4.5~4.6k | 同左 | 参数 `DSP_TOT` |
| 片上 BRAM+URAM | 34.6 MB URAM 级 | 34.6 MB URAM | 参数 `URAM_BYTES_TOT` |
| 主存 | 4×DDR4（~77GB/s） | **8×HBM2 ~1.5 TB/s** | 参数 `BW` |
| PCIe | Gen3×16（Gen4 兼容） | 同左 | — |

> **为何选 U280**：权重 GPT-2 ~8GB / Gemma ~17GB 需要 HBM 常驻；U250 无 HBM、DDR 带宽不够（§C 数据路径结论）。U250 仅作为"无 HBM 对照"。

## 2. 算法 → 算子映射（每算子给出并行度 = f(资源, 带宽)）

### 2.1 算子清单（HyperKZG 三 prover 阶段）

| 阶段 | 数学 | 硬件算子 | 数据并行性 |
|---|---|---|---|
| 承诺 | `Pippenger MSM(g1_powers, poly)` | **BN254 EC 标量乘/MSM 引擎** | 桶并行 |
| 打开①折叠 | `f[2j]←r(f[2j+1]-f[2j])`, k-1轮 | **EQ/fold SIMD 数组** | 逐元素并行 |
| 打开③witness | `h[i-1]=f[i]+h[i]u`（Horner 串行链） | **串行乘加链** | 需窗口分解 |
| sumcheck/EQ | `β(r,x)=∏(r_i x_i+(1-r_i)(1-x_i))`, 2^k 项 | **EQ 张量分解流水** | 层内位增长 |
| 域算术 | Fr Montgomery 模乘 | **254-bit 模乘器** | 多 limb 级联 |

### 2.2 域算术引擎（一切的地基，M1 交付）

- **254-bit Montgomery 模乘**：`Fr` 拆 4×64-bit limb（256-bit 承载 254-bit）。每一位需 1 个 64×64→128 乘 ⇒ 4 个 `F_64mux` 乘积 + Montgomery 归约。
- 面积量级：一个 254-bit 模乘 ≈ **4–6 个 64×64→128 乘法器级联的 CIOS**，相比单个 64-bit 域模乘 ≈ **4..8×**。
- **关键路径**：`D_crit = N_limb × T_64mux + T_add`，其中 `T_64mux` 为 64×64→128 乘 + 累加延迟（3-4 级 DSP 级联）。Montgomery 归约的 `sum` 累加链是时序主核，须做进位/进位交叉分解。
- **收敛预估**：目标 `F_clk = 200–300 MHz`（U280 常规可收敛），若超 300 需二次 pipeline 拆分归约。

### 2.3 MSM / 承诺打开引擎（主包袱）

Pippenger：参数 `w`（window/桶），`n` 个标量。标量乘数范围 `2^w - 1`；
- 桶数 `B = 2^w`，每 bucket 一组中点加法链，最终一级点累加。
- **并行度 `P`**（并行 bucket 组数）→ 时延下降 `∝ P`（理论），面积涨 `∝ P`。`P` 的上限受面积预算 `A_MSM = P × A_PA`（`A_PA`=单组点加面积）与 URAM 标量缓冲容量的双重约束。
- **存储**：`n=2^k` 个标量点缓冲 = `32×n + 36×n`（缓冲+基点偏置），是 URAM 大户。公式见 §4.2。

### 2.4 EQ/张量积引擎（sumcheck 每轮热点）

- 递推：`β(r,x)=β(r[1..k-1], x[1..k-1])·(r_kx_k+(1-r_k)(1-x_k))`——前层 2^{k-1} 值各乘第 k 因子，位增长、天然流水。
- 存储 `2^k × 32B` 中间层：k=16→2MB、k=20→**32MB(BN254)**，k=20 要整组 URAM/内存组。
- 并行展开 `2^m` 路 → 面积 `∝ 2^m`、吞吐 `∝ 2^m`；受模乘器数量与 `URAM` 约束。

### 2.5 打开 witness 的 Horner 链（唯一"串行"瓶颈）

`compute_witness_polynomial`（`mod.rs:171-183`）是 `h[i-1]=f[i]+h[i]·u` 的 O(n) 串行依赖。**流水不友好**。缓解选项：
- **方案 P1（线性窗口）**：固定乘法窗口（如每窗 `Lw` 个元素），把 Horner 拆成可重叠的窗内 SIMD + 窗间顺序，流水可收敛。
- **方案 P2（并行前缀）**：若 u 固定，可预先算 u 的幂，把长链转成可并行 prefix tree（代价：`O(n) log n` 乘、面积大）。
- **P1 更务实**：面积可控、时序仍收敛；P2 留给"吞吐优先"变体。

## 4. 面积-时序推导（每算子"能点算账"）

> 统一记号：`E`=域元素宽(32B)；`U`=URAM 字节；`P`=并行度；`K`=MSM 并行 bucket 组数；`m`=EQ 展开指数；`BW`=可用带宽（HBM2e ~1.5TB/s 摊实际利用率 70-80%）；`F_clk`=时钟。

### 4.1 域模乘
- 面积：`DSP_mul ≈ L×1`（L=limb 数，CIOS 级联），LUT 数百。
- 时序：`Delay ≈ L×T_mac + T_red`，`F_max ≈ f(Delay)`。L=4..6。

### 4.2 MSM 引擎
- **面积（DSP）**：`DSP_MSM ≈ P × D_PA`（P=组数，D_PA=点加模乘数）。U280 ~4.6k DSP → P 上限受此约束。
- **URAM（标量缓冲）**：`URAM_MSM ≈ (32B + 36B基点) × n` 平摊到窗口。n=2²⁴ → **~16 MB**；n=2²⁶（表1=MAX_CHUNKS 128→4.3GB）远超 URAM，需 HBM 流式分片。**结论：n 大时 MSM 是"HBM 流式 + 片上窗口缓冲"混合，不是片上驻留。**

### 4.3 EQ 引擎
- URAM：`2^k × 32B`。k=20 → 32MB ≈ 整组 URAM（U280 34.6MB），贴边；k>20 需 HBM。
- 吞吐目标：`1 eval/cycle` × `F_clk`；m 路展开 `×2^m`。

### 4.4 汇总预算表（M1，代入 U280；精确数量见附录 B）

| 算子 | DSP 估算 | URAM 估算 | 最高限制 |
|---|---|---|---|
| 254-bit 模乘器（非 MSM） | 数千 | — | 乘级联时序 |
| MSM 引擎（K 桶并行） | `~K×几百` | 标量缓冲/窗口 | DSP+URAM |
| EQ 表（k=20 展开） | 中等 | ~32MB | URAM 贴边 |
| 数据重排/乒乓 | — | 2×32MB×2 | URAM/BRAM |
| **本表为推导式** | — | — | 上板点数替换 |

> **诚实标注**：`K`、`m`、并行度是**优化变量**，本表只给约束关系（DSP/URAM/带宽如何随它们变化），**不给"已综合回填"的实测数**。要出确切回填值需一次实际综合，属后续工程交付，不属于本规格静默承诺。

## 5. 权衡矩阵（每个决策的两侧代价，不隐瞒）

| 决策 | 一侧（收益） | 另一侧（代价） | 本文倾向 |
|---|---|---|---|
| MSM 并行组 K ↑ | 时延 ∝1/K | DSP、URAM 缓冲 ∝K | 取折中，受 DSP→预算 |
| EQ 展开 m ↑ | 吞吐 ×2^m | 模乘器数和 URAM ×2^m | m=窗口内，k>20 HBM |
| HBM vs U250-DDR | 带宽 ~1.5 vs ~0.08 TB/s | U280 更贵、内存更小 | **U280-HBM 必须**（权重 8-17GB 常驻） |
| 承诺+打开同引擎 | 复用一个 MSM、免双引擎 | 打开 ≈4×承诺，占同一引擎达峰 | **必须同引擎**，合并验收 |
| witness Horner 拆窗 | 时序可收敛 | 面积 + | 默认窗，吞吐再上 prefix |
| 全 fp 推理上板 | 减主机负载 | 工程量巨大、已有 GPU 后端 | 不做 |
| 注意力裁剪 | 免二次项带宽黑洞 | 正确性"待求证" | 先求证再设计（见 A§7-2） |

## 6. 数据路径与带宽预算

- **常驻板载（HBM）**：权重 GPT-2 ~8GB / Gemma-3 ~17GB + 查找表 + SRS 基点表（`g1_powers`，大 n 时数百 MB，流式分片）；Gemma-3 ~17GB 已贴 U280 HBM，须分卷。
- **流式（逐层）**：witness，每层 ≤1 chunk（32MB-BN254），逐层 DMA 喷发。
- **带宽账（读为主）**：MSM/EQ 需以 `≥计算速度` 持续喂入 32MB chunk，否则读路径成为瓶颈。U280 HBM2e ~1.5TB/s（实际利用率 70-80% ≈ 1.05-1.2TB/s）**可满足**；U250 仅 DDR ~77GB/s，读路径喂不饱 MSM，承诺/sumcheck 加速无从谈起——**这正是选 U280-HBM 的结构性理由，非价格偏好**。
- **乒乓**：双缓冲当前/下一 chunk + EQ 中间层，避免握手间隙饿死流水。

## 7. M1 首里程碑规格

### 7.1 目标与验收
1. **254-bit Montgomery 模乘器**，对拍 `ark_bn254::Fr` 位级。
2. **BN254 EC 标量乘 / MSM 承诺原语**，对拍 `dp_crypto::arkyper::HyperKZG`。
3. **EQ 张量积引擎**（k≤20，每 32B），对拍 `poly::eq::evals` 位级。

**验收门**：Golden vector（固定 r、大小、已知向量）bit 级一致；吞吐 ≥ 目标（EQ ≥ 1 eval/cycle × F_clk；MSM 达目标）；`WNS ≥ 0` 且资源 ≤ 预算。

### 7.2 接口与数据流
```
host (CPU)  ←──►  FPGA
 r / chunk 起止 / k   ──►  AXI-Lite（寄存器，小量）
 2^k 中间层（URAM）      │
 evals / MLE 值          ◄──  AXI-Stream / BRAM 口
```
- 双缓冲；AXI-Lite 走握手（r/m 小量），大量数据走独立 DMA，解耦防小包阻塞大流。

### 7.3 任务清单（milestone exit）
1. [ ] BN254 254-bit Montgomery 模乘器 + 单测对拍 `ark_bn254::Fr`
2. [ ] BN254 EC 标量乘 / MSM 承诺原语（对标 `HyperKZGGpu`，含 Pi basis）
3. [ ] EQ-evals 张量分解流水（k≤20、每元素 32B）对拍 `poly::eq::evals`
4. [ ] 双缓冲 + AXI 接口
5. [ ] 时序收敛（WNS≥0）、资源 report ≤ 预算
6. [ ] Golden vector（k=16/20、随机 r）通过
7. [ ] 与 `poly_commit/prover.rs` 对接，估算 M2 的 PCS/MSM 增益

## 8. 验证计划

- **Golden vector**：用 Rust `dp_crypto::arkyper`（BN254）生成固定 r、固定大小的已知向量，RTL 与行为级 bit 一致对拍。覆盖：模乘进位/归约边界、EC 标量乘角（0、1、max scalar）、EQ k=16/20、随机 r、n=2^16..2^24。
- **吞吐**：EQ evals ≥ 1/cycle × F_clk；MSM 达设计时延；**承诺+打开合并计量**（因为同引擎，打开+≈4×）。
- **资源/时序**：综合 report（LUT/DSP/URAM/FF + WNS）与集中预算/延迟模型对不上即回退并行度。

## 9. 风险与缓解（仅技术）

| 风险 | 等级 | 缓解 |
|---|---|---|
| BN254 254-bit 模乘 + EC/MSM 工程量（域宽 4×） | **HIGH** | M1 起正视：模乘 + MSM 承诺/打开共享引擎；忌"后置可弃" |
| 100GB 足迹不驻留单板；权重 8-17GB 贴 HBM | HIGH | 流式 + chunk 乒乓 + HBM；Gemma 分卷 |
| 注意力二次项带宽黑洞 | MED-HIGH | 掩码/认证行裁剪——**先求证可裁，再上线** |
| 打开负载被低估（≈4×承诺） | MED | 与承诺同一 MSM 引擎，独立排预算、合并验收 |
| sumcheck 随机组合时序关键路径 | MED | 双缓冲 + 多轮流水 |
| EQ 表 URAM 贴边（k=20→32MB） | MED | k>20 转 HBM 流式 |
| Rust→RTL 工程总量 | MED-HIGH | 模块级先行，性能不达标再迭代 |
| 精度（域整数 vs 定点推理偏差） | LOW | 域整数是精确的（无浮点误差），与软件对拍闭环 |

## 10. 结论

M1 在 **254-bit 域**上交付**模乘 + MSM 承诺/打开 + EQ** 三个夯实地基的原语，对拍 `dp_crypto` 与 `ark_bn254`。瓶颈在带宽（HBM 刚需）与 MSM 时序收敛，不在 MAC 阵列。价值兑现点：把 ~92%（论文数字）热路径的"承诺+打开（同引擎 MSM）+sumcheck"流式搬上 U280-HBM，即是实用加速器；端到端全移植不划算（推理留 GPU、验证留 CPU）。
