## 五、架构关键知识（新会话必须理解）

### 5.1 流式分段证明流程
```
trace 按预算分段生成 → 段完成投递 → 专用 64MB 栈证明线程
（FIFO prove → seed 链吸收 → 通知释放 pin）→ 按完成顺序合并 → verify_streaming
```
- 方案 A 全局串行 transcript：seed₀ = H(setup‖input‖chunk数)，逐段吸收派生
- 磁盘读 = 0 不变量
- S1 修复后：XOF 流推进语义（吸收后首采样从位置 0、连续采样推进、再吸收重置）

### 5.2 证明成本分布（N 文档实测，gemma-270m s=512）
| 算子族 | 占比 |
| ---| ---: |
| **查表族（requant/rms-norm/softmax/logits 的 logUp+linking+witness）** | **~82%** |
| einsum（矩阵乘 sumcheck） | 8% |
| MSM（承诺+opening） | ~6% |

**结论**：查表族是绝对主力；FPGA 优先级 = sumcheck/LogUp 引擎 > MSM。

### 5.3 成本模型
- 每段证明 ~110s **与模型无关**（段体积主导）；13b 偏高 2.2×（更多节点/claim）
- 证明墙 = 段数 × 单位体积成本；前向墙 = O(N·s)；内存墙 = max(参数 Fr 化, 窗口×段工作集, logits MLE)
- 13b/512 = 48 段 × ~3.6min/段 = 2.9h dispatch

## 六、D1.1 带状注意力（SWA）——当前工作重心

### 设计
score 张量从 `[Hq,s,s]` 缩到 `[Hq,s,w]`，使 s=32k trace 从 67.4TB → 3.5TB。

**Stage A（工程化路径，核心已实现+验证）**：
- `GatherRows` 算子：`K'[t,d] = K[f(t),d]`（f = 窗口映射闭式）
- 证明 = logUp 重排论证：Table 侧 (K 值列+索引列+闭式重数) ↔ Lookup 侧 (K'值列+f 索引列)，多列 tuple 绑定 → 位置精确
- B = einsum(Q, K′) 走标准 einsum prove（fix_axes，零新协议）
- banded mask 角掩码：q+off < w-1 的无效位置

**Stage B（研究轨，待做）**：零物化 K′ 的 banded-matmul 论证（截断乘积+商见证）

### 已验证组件（全部 PASS，已推送）
| 组件 | 测试 | 位置 |
| --- | --- | --- |
| GatherRows 数学（映射/重数/clamp） | 3/3 | `gather_rows/mod.rs` |
| GatherRows 推理算子（burn 移位交错） | 5/5 | `gather_rows/evaluate.rs` |
| logUp 重排 round-trip + 负对照 | 7/7 | `gather_rows/prove.rs` |
| 层集成（18 分发点 + ProvableOp/VerifiableCtx） | 编译零错误 | `gather_rows/prove.rs` + 各分发文件 |
| BandedQK 数学+推理+可分权重恒等式 | 7+1/7+1 | `banded_qk/` |
| banded mask 角掩码 evaluate | mask 5/5 | `attention_mask/evaluate.rs` |

### ⚠️ Parser 集成——当前阻塞点（§13 三方案待决策）

带状路径的图拓扑变更遇到障碍（首版接线发现，已回退至标准路径）：
1. QK einsum 方程需从 `A(ghqs)` 改为 `A(ghqo)`（新增窗口轴 o）
2. K/V 输入需经 gather 重排——但 **gather 插入位置在 RoPE 之后**（gemma3/llama2 的 `insert_custom_logic` 创建 RoPE 并连接到 QK einsum），**改变 QK 的输入连接 = 三模型 custom_logic 也要重构**
3. graph 的 `automatic_output_labelling` 在中间节点未被消费时报多输出错误

**三方案**：
- **α 渐进**：mask→softmax 间插 gather（softmax 窗口化收益），QK 仍全量——最小改动
- **β 完整**：重构 attention graph 为 QKV→RoPE→gather→banded-QK→mask→softmax→gather(V)→AV——需同步修改三模型 custom_logic
- **γ Stage B 研究轨**：不物化 [q,s] 的 banded-matmul 论证

## 七、P1 偶发 verify 失败——距根因一步

### 现象
gemma-270m s=1024 的 `verify_streaming` 偶发失败（~7.7%，13 轮 1 败），固定模式：sumcheck 第 0 轮 "prover message not consistent with the claim"。

### 判别结论（已实锤）
| 发现 | 意义 |
| --- | --- |
| 失败节点确定性锁定 **Chunk(7)/N173**（RequantiseTable_10bits） | 非随机位置，随机的是数据是否被污染 |
| 两侧 `[p1-linking]` dump 逐位一致 | **transcript 清白**——排除容器顺序/挑战链分叉 |
| 自检钩子触发：`Total output prover ≠ last claim` | **witness 数据污染实锤** |

### 头号嫌疑
requant 的 witness 由输入张量派生 → 若 trace 张量在前向与 witness-gen 之间被改写（pipeline 并发窗口），witness 重算值不同 → 不一致。

### 已部署工具（p1-debug feature）
- **mutation-detector**（`requant/lookup.rs`）：witness 重算值 vs 前向张量逐元素对照 → `[p1-mut]` 打印不一致位置
- **debug_linking_sumcheck**（`inputs/proving.rs`）：暴力自检 → 打印 output/norm/input/sum 四项分项差值
- 猎捕脚本：`model_cache/hunt_p1_v2.sh`（**可能仍在运行**，检查 `pgrep -f target-p1`）
